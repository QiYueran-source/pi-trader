# Cronjob 设计

## 任务分类

| 类型 | 仓库目录 | 名称格式 | 典型职责 |
|---|---|---|---|
| 全局型 | `cronjob/global/` | `global-{HHMM}-{task}` | 汇总、提醒、摘要、跨体系扫描 |
| 体系型 | `cronjob/system/{system-id}/` | `{system-id}-{HHMM}-{task}` | 执行、复盘、计划、参数检查 |

全局型任务不归属具体交易体系，可以读取多个体系的结果。体系型任务必须能通过 `system.yml` 找到所属体系，并引用该体系的文档作为业务依据。

## 设计清单

创建任务前回答以下问题：

```text
任务类型：全局型 / 体系型
任务名称：
所属体系：全局型留空
执行时间：
任务目的：
输入文件或上游结果：
执行动作：
输出文件：
通知方式：
非交易日或输入缺失时如何处理：
失败时汇报什么原因：
```

## 设计原则

- 任务名称中的 `HHMM` 使用任务实际调度时区，并与 `schedule` 对应。
- `schedule` 负责触发；是否为交易日由任务内部判断。
- 全局型任务面对单个体系缺失时，应尽量继续处理其他体系，并在结果中说明缺失。
- 体系型任务应明确读取哪些流程文档、规则文档和过程产物。
- 任务应明确输出是当天结果、下一交易日计划，还是其他日期的产物。
- 任务 prompt 只保留执行动作、输入输出和必要的异常处理，不复制大段业务规则。
- 新任务先保存仓库文件，再注册到 Pi；运行时注册不能替代版本化文件。

## 任务命名

名称由三部分组成：

```text
{scope-or-system-id}-{HHMM}-{short-task}
```

要求：

- 只使用英文小写、数字和连字符。
- 时间使用 24 小时制四位数字。
- 任务描述简短、稳定，避免使用临时日期或中文。
- 任务目录名、`cronjob.yml` 的 `name` 和 Pi 注册名称一致。

## 轻量异常约定

不要求单独建立复杂状态或执行日志。每个 prompt 只需明确：

- 脚本失败时报告哪一步和错误原因。
- 上游结果不存在时是跳过、继续并说明，还是使用其他输入。
- 已有输出时是否允许覆盖。
- 补做时使用哪个目标日期。
