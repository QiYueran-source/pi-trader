# 待办管理

## 定位

待办的事实来源是 `knowledge/` 和 `archive/` 下的动态知识文档；`todo-management` MCP 维护文件级 SQLite 索引，只用于查询、统计和审计，不能替代原文档。

索引数据库默认位于 `database/todo_index.db`，数据库可以删除并从文件重新建立。索引查询不到某条待办时，不得据此推断该待办不存在或已经完成。

## 索引路径硬规则

SQLite 的 `todo_files.path_rel` 是**动态知识的逻辑路径**，不是物理文件路径：

- 路径必须是相对于内容根的路径，使用 `/` 分隔；
- 不得包含 `knowledge/` 或 `archive/` 前缀；
- 不得使用绝对路径、工作区绝对路径或系统路径；
- `knowledge/` 与 `archive/` 只表示同一逻辑路径当前所在的物理根目录；
- 文件从 `knowledge/` 归档到 `archive/` 时，`path_rel` 不得改变，只更新物理状态；
- `knowledge/` 和 `archive/` 同一 `path_rel` 同时存在时，必须报告 `both_exist`，不得创建两条索引或静默合并；
- 两边都不存在时保留原索引并报告 `gone`，不得把文件消失解释为待办已完成。

`todo_list` 返回的 `path_rel`、`prefix` 参数和审计结果中的路径均遵守这套逻辑路径规则。数据库文件本身仍是物理基础设施路径 `database/todo_index.db`，不属于动态知识引用。

## 标准条目格式

新的待办必须使用以下格式：

```text
- [ ] T-YYYY-MM-DD-N ｜ owner ｜ 触发 ｜ 来源
```

已完成的待办使用：

```text
- [x] T-YYYY-MM-DD-N ｜ owner ｜ 触发 ｜ 来源
```

约定如下：

- `T-YYYY-MM-DD-N` 是待办标识；日期是创建日期，`N` 是当天从 1 开始的序号。
- `owner`、`触发`、`来源` 必须非空；分隔符使用全角 `｜`。
- `[ ]` 表示未完成，`[x]` 表示已完成。
- 其他 Checkbox 写法会被审计报告为未识别，不得默默当作已完成或忽略。
- 历史每日计划快照不因本技能自动批量迁移或回修。

## 工作纪律

1. 在本次会话提出的待办必须当轮写入对应的正式知识文档；尚未确定正式归属时先写入 `.scratch-space/`，不能只留在对话中。
2. 创建体系计划、复盘或过程资料中的待办时，使用对应体系和 `knowledge-management` 的落盘规则。
3. 确认上一份文档中的事项已经处理时，应回填原条目的 `[ ]` 为 `[x]`，不要只在新文档中写“已完成”。
4. 完成待办不删除原条目，保留来源和完成状态。
5. 新动态知识写入 `knowledge/`；`archive/` 由归档流程作为历史物理目录使用。
6. 动态文档中的来源路径遵守 `knowledge-management` 的逻辑路径规则，不把 `knowledge/` 或 `archive/` 写入新引用。

## MCP 使用

需要查询或核查时调用 `todo-management` MCP：

- `todo_scan`：扫描最近活跃文档和数据库中仍有未结项的文件。默认 `since_days=7`；`dry_run=true` 只预览，不写数据库。
- `todo_list`：列出文件级未结项、物理存在状态、累计数量和当前积压天数。
- `todo_stats`：查看未结文件数、未结条目数、最老待办和分组分布。
- `todo_audit`：按与扫描相同的范围核对文件和索引，只报告不修改。

文件级索引不提供条目级 CRUD，也不能指出同一文件中具体哪一条发生变化。需要逐条确认时必须读取原文档。

`todo_scan` 的纳入范围为最近活跃文档，或数据库中仍有开放条目的文档。旧历史文档不因不在扫描范围而被视为已完成。`knowledge/` 和 `archive/` 同一逻辑路径同时存在时，报告 `both_exist`，不得静默合并；文件消失时报告 `gone`，不得自动写成已完成。

## 降级与汇报

MCP 未加载、工具不存在、扫描失败或审计存在差异时：

- 说明具体失败阶段或差异类型；
- 不把查询失败说成“没有待办”；
- 不自行创建数据库记录来掩盖文件与索引差异；
- 需要精确判断时直接读取文件，并说明未完成索引审计。

## 定时审计

每日 23:30 的全局任务负责执行 `todo_scan` → `todo_audit`，并向既有飞书投递目标发送一行状态。审计任务只负责索引和报告，不删除、移动或修改知识文档。
