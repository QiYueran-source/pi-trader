# 动态知识路径协议

## 1. 适用范围

`knowledge/` 与 `archive/` 是动态知识的两个物理根目录。归档是物理位置变化，不是动态知识身份变化。

## 2. 逻辑路径

动态知识的逻辑路径是从**物理相对路径**中去掉 `knowledge/` 或 `archive/` 前缀后的仓库相对路径。

例如：

```text
knowledge/事实/2026-10-14/市场收评.md --逻辑路径--> 事实/2026-10-14/市场收评.md
archive/事实/2026-09-14/市场收评.md --逻辑路径--> 事实/2026-09-14/市场收评.md
```

**重要要求**：新写入的动态知识引用和数据库来源字段**不得以 `knowledge/` 或 `archive/` 开头，不得使用机器绝对路径或旧工作区绝对路径。**；逻辑路径必须是仓库内相对文件路径，不得包含空路径段、`.`、`..` 或路径穿越。  

## 3. 引用和归档

在新创建 `knowledge/` 下的动态文档时，可能会引用其他动态文档，引用**请使用逻辑路径**  

文件归档后，会被移动到 `archive/` 目录下，其逻辑路径不变。具体请参见 `archive`技能。  

## 4. 双头解析、唯一性与 MCP 用法

对逻辑路径 `P`，解析器必须同时检查：

```text
knowledge/P
archive/P
```

项目通过 `logic-path` MCP 执行这项检查。需要发现或校验动态知识路径时，调用对应工具：

- `logic_path_resolve`：解析单个逻辑路径，返回 `unique`、`not_found` 或 `duplicate`，并在 `unique` 时返回实际物理位置；
- `logic_path_validate`：校验单个逻辑路径的格式；新建引用或数据库来源写入前，默认要求目标存在且唯一；
- `logic_path_audit`：批量审计逻辑路径，汇总格式错误、缺失目标和重复目标。

解析结果：

- 两边都不存在：`not_found`；
- 只有一边存在：`unique`，返回实际物理位置；
- 两边都存在：`duplicate`，不得静默优先选择任一位置。

新写入数据库或新建动态知识引用时，必须先使用 `logic_path_validate` 或 `logic_path_resolve` 确认结果为 `unique`。如果 MCP 不可用、工具未加载或返回错误，不能把路径当作已验证；应停止依赖该校验的写入，并如实报告校验未完成。

历史数据可以在兼容模式下读取，但不得以兼容历史格式作为新写入格式。MCP 只负责逻辑路径的格式检查和双头解析，不负责移动文件、改写引用或迁移数据库。

## 5. 静态资产中的动态文档

静态长期资产，如skills，extensions，cronjobs，mcp等，其内部**不允许**引用具体逻辑路径。长期资产应该是全局层面的指引，而不是具体到某个文件。

其内部可以用类似通配符的形式，引用通用的动态知识路径，如 "任务执行后，落盘到 `交易/交易计划/<日期:yyyy-mm-dd>/<体系名称>_交易计划.md`" ，具体请参考`skills/agent-dev`下各类技能的说明。  

## 6. 历史兼容

历史文档和数据库可能包含 `knowledge/...`、`archive/...`、裸路径或绝对路径。这些内容不在本协议落地阶段批量改写。读取端可以提供兼容识别和审计；新建或主动修改的内容必须使用逻辑路径。
