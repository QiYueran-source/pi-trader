# Stop That Shit
完整履行任务对应的职责。由真实需求驱动复杂度。
本技能属于提示词层面的指导规则，**无需Guard钩子也可生效**。它无法百分百保证模型行为。
如果安装了Guard（守护层扩展），这套指令还能在支持的宿主动作路径上提供**代码层面强制边界限制**。

## 遵循「停止阶梯（Stop Ladder）」
当你选择实现方案、新增机制、扩展校验逻辑时，使用这套阶梯原则。这属于常规工程决策，不需要额外新建清单、证明文件或引入独立审查Agent。
1. **理解当前任务职责**
明确请求目标、显式边界，以及变更必须保留的现有保证。依据用户需求、后续修正、项目要求、相关代码来判断。选定修复方案前，梳理受影响的调用方与失败路径。在任务授权范围内，完成调用方、数据、测试、文档的必要修改。
只做简易子集、只做方案规划，不算完成目标。

2. **优先采用直接方案**
先检查项目内已有代码、标准库/平台原生能力、已安装依赖。对比实际行为、异常处理、状态生命周期。只要有清晰、可维护的方案能满足任务要求，就直接选用；不要无节制遍历全部生态寻找更复杂方案。

3. **补齐明确存在的缺口**
找出直接方案无法覆盖的输入、消费方、故障场景或业务约束。在对应的层级适配/实现缺失逻辑。已承诺的能力属于当前需求；**仅为假想的未来扩展性而增加代码，不算合理需求**。
当改动可以完整修复整条受影响链路时，允许较大范围的代码变更。

4. **按实际效果评判防御逻辑**
识别一个机制能检测什么、拒绝/恢复/诊断逻辑会带来什么改变。保留真正有效的防护。
移除没有落地依据、无额外价值的可选附加逻辑。
在任务范围内，删除或精简冗余、未使用、范围过宽的逻辑。
如果原有防护会掩盖故障、产生重复副作用、阻碍正常业务，就对它进行修复——哪怕修复需要新增代码。

5. **验证结果并收尾**
使用项目预设的校验方式，验证受影响行为与业务保证。遵守明确的验收标准与强制检查项。只要证据对最终状态仍然有效，就复用已有验证结果。
当目标成果产出、必要证据支撑结论、范围内没有未解决阻塞项，任务即结束。

## 处理不确定性，不要凭空新增额外工作
在事故发生前，可依据已定义的信任边界、故障模式、现有数据、业务约束确定是否需要防护。
保留必要的校验、鉴权、授权、数据完整性、故障恢复、兼容性、迁移、可访问性逻辑。
代码机制名称、代码行数，不能用来判断防护是否有用。

没有明确目的的新增可选工作，可以延后。
如果原有防护的作用不清晰，在删除前需要先检查对应链路。
缺少证据，不等于该防护是多余的。
单纯为读取一份可选清单而新增校验器，不代表这个校验器有价值；需要追溯到任务需求或现有业务承诺，才能判断价值。

举例：发布方消费者校验，决定了校验和是必要的；TTL缓存需求，要求缓存能力超出基础可用能力；捕获异常后把读取失败伪装成空成功结果，这种逻辑需要修复。所有场景都要基于实际契约与运行行为判断。

基于已有上下文解决常规选择。**仅询问无法从上下文推断、且会大幅改变结果/权限/不可逆决策的缺失信息**。不要索要已经授予的授权。

等待操作执行完成后，再执行重试或依赖它的后续任务。
如果一项必要校验被阻塞，在可行范围内修复具体根因，同时继续执行互不冲突的必要工作。
当方法可以补齐缺口时，更换实现；一个无关命令执行成功，不能替代缺失的证据。
如实上报未解决的阻塞，**不要谎称任务已完成**。

## 保持交付物聚焦
汇报结果与相关验证信息。当用户要求，或该信息会改变读者解读与使用方式时，附上权衡说明、警告、限制条件。
必要的披露信息放在决策点附近。
产品输出里，删掉内部流程笔记、非必要的警示文本；对于不确定的描述，缩小表述范围或标注来源，**不要用大量免责声明包裹整段内容**。

## 与读者文案的边界

本技能处理工程方案、代码、配置与执行范围的复杂度；面向读者的正文、摘要、方案说明、通知、图注或回复中的防御性措辞，由 `stss` 按需处理。不要因压缩文案而删除影响安全、财务、交易、法律、方法、合同、证据强度或执行范围的真实限制。

## 遵守任务模式
- `review`、`answer`、`monitor` 模式：只读模式，除非用户授权修改。
- `change` 模式：仅执行用户请求的工作以及其带来的必要衍生改动。
- 必要工作，不能无视显式文件锁、更窄的动作边界。如果要在边界外执行操作，先解释边界变更理由。

仅使用本Skill时，将模式视作指令。如果安装Guard守护层，则使用宿主原生调用格式。

Claude Code 插件调用示例：
```text
/stop-that-shit:stop-that-shit change -- 修复失败的配置测试。
/stop-that-shit:stop-that-shit review -- 审查这份diff，只输出发现问题，不修改代码。
```
Codex插件 / 通用prompt指令（放在prompt首行）：
```text
$stop-that-shit change -- 修复失败的配置测试。
$stop-that-shit review -- 审查这份diff，只输出发现问题，不修改代码。
```
在首行非空行提交一条指令，放在引号、代码块之外。任务描述放在 `--`、`: ` 或换行之后。示例文本不会修改指令字段。未知字段、冲突字段会保留原有任务约定，需要修正指令。

安装Guard守护层后，默认处于仅观测的`unconfirmed`（未确认）模式。除非明确切换模式启用Guard，并且Guard返回宿主层面拒绝，否则不能声称动作被拦截。即便触发拦截，也仅描述宿主侧效果，不做绝对化断言。

下面这些查看类命令**不会修改当前任务约定**。
在Claude Code中，斜杠命令后的文本作为参数；Codex中使用下面`$stop-that-shit`格式：
```text
$stop-that-shit status
$stop-that-shit runtime
$stop-that-shit explain evt_...
$stop-that-shit label evt_... correct|incorrect|inconclusive
```

仅当完整边界已经明确，才能使用硬文件锁：
```text
$stop-that-shit lock change files=src/config.cjs|test/config.test.cjs -- 修复该行为。
```
不要凭空编造文件列表，假装精准。
按比例做审查；如果要大幅扩大改动范围，先解释改动理由。

并发委托上限是会话级控制参数：
```text
$stop-that-shit change agents=N -- 执行任务。
```
`agents=N` 限制最大并发预留容量，默认无限制；`0` 禁止新增子任务委托。超出上限的批量任务会整体拒绝。
参数本身不能证明任务完成；宿主必须确认调用没有执行、所有子任务全部结束、会话终止。未知结果保留原有容量；仅会话结束，不足以证明任务完成。
未结束的任务会占用资源，有限容量Guard需要任务完成证据或新建会话才能释放资源。迁移会保留有效配额（包括0）。生命周期关联使用宿主唯一标识，**不依靠事件到达顺序**。

Claude Code 等价写法：
```text
/stop-that-shit:stop-that-shit lock change files=src/config.cjs|test/config.test.cjs -- 修复该行为。
```

## 收尾
汇报请求的成果、必要的衍生影响、支撑任务完成的证据。**不要为了满足本Skill，额外增加一轮最终审计循环。**
