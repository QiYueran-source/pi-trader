# 自选股管理

自选股管理用于维护当前关注的证券列表，记录证券所处的全局状态、被哪些交易体系关注，以及进入自选池的原因，为后续分析、决策和交易管理提供统一入口。

## 作用

自选股管理的核心作用包括：

1. **统一管理关注标的**：集中维护当前正在关注的股票或 ETF
2. **区分全局状态**：用统一状态标记证券当前处于观察、候选还是交易阶段
3. **记录交易体系关注关系**：支持同一证券被多个交易体系同时关注
4. **沉淀入选原因**：记录证券进入自选池的总体原因和体系级理由
5. **支撑后续分析与交易**：为候选标的分析、交易决策和复盘提供基础数据

## 表结构

- 表名：`watchlist`
- 字段定义：
    - `code`：证券代码，唯一标识一个证券，如 `600519.SH`
    - `name`：证券名称，如 `贵州茅台`
    - `status`：证券当前的全局状态，取值为 `watching`、`candidate`、`trading`
    - `systems`：交易体系列表，JSON 格式，记录哪些交易体系在关注该证券
    - `reason`：该证券进入自选池的总体原因或补充说明
    - `created_at`：加入自选池的时间
    - `updated_at`：最后更新时间

## 状态说明

`status` 字段表示该证券在整个 `hermes-trader` 视角下的全局状态，而不是单个交易体系的局部判断。

状态固定为以下三种：

- `watching`：观察。默认状态，表示该证券处于一般关注状态，不进入重点分析流程。
- `candidate`：候选。表示该证券进入重点分析和决策队列，应优先分析。
- `trading`：交易。表示 `hermes-trader` 已经综合多个交易体系的判断，将该证券纳入交易管理流程。

### 状态流转建议

- `watching -> candidate`：从普通观察转入重点分析
- `candidate -> trading`：分析完成后决定进入交易管理
- `candidate -> watching`：分析后暂不交易，退回普通观察
- `trading -> watching`：交易阶段结束后，继续保持关注

## 交易体系字段格式

`systems` 字段为 JSON 数组，用于记录该证券被哪些交易体系关注，以及各体系各自的关注原因。

```json
[
  {
    "id": "breakout",
    "name": "突破体系",
    "reason": "放量突破平台，趋势有望延续"
  },
  {
    "id": "dip-buy",
    "name": "回调低吸体系",
    "reason": "回踩关键均线后企稳，存在低吸机会"
  }
]
```

### 字段说明

- `id`：交易体系唯一标识，如 `breakout`
- `name`：交易体系名称，如 `突破体系`
- `reason`：该体系关注该证券的具体原因

### 设计说明

- `systems` 允许同一证券被多个交易体系同时关注
- `status` 是全局状态，由 `hermes-trader` 综合多个交易体系后统一给出
- `reason` 是全局原因或补充说明，用于描述该证券整体上为何值得纳入自选池
- 如果后续需要记录更多体系级字段，例如 `score`、`priority`、`signal_date`，可以在 `systems` 中继续扩展

## CLI 使用说明

### 命令目标

当前已经提供 `watchlist_cli.py`，用于维护自选股信息，支持以下动作：

- 添加证券到自选池
- 查看所有自选股
- 按状态筛选自选股
- 查看某个证券详情
- 更新证券名称、状态、交易体系或总体原因
- 删除证券

### 参数约束

- `status` 只允许以下三种取值：`watching`、`candidate`、`trading`
- `systems` 必须是 JSON 数组
- `systems` 数组中的每一项都必须是对象，并且至少包含以下字段：
  - `id`
  - `name`
  - `reason`

### 命令列表示例

```bash
# 查看帮助
./watchlist_cli.py --help

# 添加证券
./watchlist_cli.py create --code <证券代码> --name <证券名称> --status <状态> --systems <交易体系JSON> --reason <原因>

# 列出所有自选股
./watchlist_cli.py list

# 按状态筛选
./watchlist_cli.py list --status candidate

# 查看详情
./watchlist_cli.py show <证券代码>

# 更新名称
./watchlist_cli.py update <证券代码> --name <新名称>

# 更新状态
./watchlist_cli.py update <证券代码> --status trading

# 更新交易体系
./watchlist_cli.py update <证券代码> --systems '<交易体系JSON>'

# 更新原因
./watchlist_cli.py update <证券代码> --reason "新的说明"

# 删除证券
./watchlist_cli.py delete <证券代码>
```

## 使用示例

### 添加证券

```bash
./watchlist_cli.py create \
  --code 600519.SH \
  --name "贵州茅台" \
  --status candidate \
  --systems '[{"id":"breakout","name":"突破体系","reason":"放量突破平台"},{"id":"dip-buy","name":"回调低吸体系","reason":"回踩均线后企稳"}]' \
  --reason "多个交易体系同时关注，进入重点分析"
```

### 查看自选股列表

```bash
./watchlist_cli.py list
```

输出示例：

```
600519.SH: 贵州茅台 - candidate - 多个交易体系同时关注，进入重点分析
510300.SH: 沪深300ETF - watching - 跟踪指数趋势
300750.SZ: 宁德时代 - trading - 已进入交易管理流程
```

### 按状态筛选

```bash
./watchlist_cli.py list --status candidate
```

### 查看单个证券详情

```bash
./watchlist_cli.py show 600519.SH
```

输出示例：

```text
代码: 600519.SH
名称: 贵州茅台
状态: candidate
交易体系: [{"id": "breakout", "name": "突破体系", "reason": "放量突破平台"}]
原因: 多个交易体系同时关注，进入重点分析
创建时间: 2026-06-02 10:30:00
更新时间: 2026-06-02 11:00:00
```

### 更新状态

```bash
./watchlist_cli.py update 600519.SH --status trading
```

### 更新名称

```bash
./watchlist_cli.py update 600519.SH --name "贵州茅台(重点跟踪)"
```

### 更新交易体系

```bash
./watchlist_cli.py update 600519.SH --systems '[{"id":"breakout","name":"突破体系","reason":"趋势加强"}]'
```

### 更新原因

```bash
./watchlist_cli.py update 600519.SH --reason "突破确认后，进入交易管理"
```

### 删除证券

```bash
./watchlist_cli.py delete 600519.SH
```

删除前会有确认提示：

```text
确定要删除该自选股吗？ [y/N]:
```

## 注意事项

1. **表名建议使用 `watchlist`**：不要使用 `watch-list`，避免 SQL 语法中额外转义的问题
2. **`code` 应唯一**：同一证券在自选池中只保留一条全局记录
3. **`status` 是全局状态**：表示 `hermes-trader` 的最终统一判断，不等同于真实成交结果
4. **交易事实应由交易表记录**：是否实际下单、是否成交、持仓多少，应以后续 `trade` 表为准，不应只依赖 `watchlist.status`
5. **`systems` 建议存对象数组**：不要只存字符串列表，否则后续难以表达各体系的独立理由
6. **候选标的是重点分析对象**：建议只对 `candidate` 状态的证券执行重点分析流程，其他默认视为普通观察
