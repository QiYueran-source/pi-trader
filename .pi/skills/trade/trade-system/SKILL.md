# 交易体系管理

交易体系由三类资产组成：**运行定义与 MCP 服务**（可执行）、**知识库文档**（规则与说明）、**体系定时任务**（触发）。本技能负责三者的边界与衔接。

## 资产分工

| 资产 | 位置 | 内容 |
|:--|:--|:--|
| 运行定义与 MCP 服务 | `.pi/mcp-servers/trade-system/<system-id>/` | 实现、`system.yml`、`params/`、`templates/`；一个体系一个服务，见 `reference/mcp.md` |
| 知识库体系文档 | `knowledge/交易/交易体系/<体系名称>/` | 体系介绍、MCP 介绍、运作流程、规则说明与更新日志；不放参数、模板与脚本，也不放跨日期证据（证据、案例与设计记录写入 `knowledge/笔记/<题材>/`，引用用逻辑路径） |
| 体系定时任务 | `cronjob/system/<system-id 连字符形式>/` | 见 `reference/cronjob.md` |

## 使用流程

1. 确认目标体系与 `system-id`（取自运行定义 `system.yml`）。
2. 通过该体系 MCP 读运行契约：`list_systems`、`get_manifest` 取体系身份、成熟度、支持的操作、参数与模板位置、产物落盘位置。
3. 读体系文档：`体系介绍.md` 与 `体系运作流程.md`；规则细节读对应专题文档，执行细节以 SOP 章节为准。
4. 确认运行日期、交易日状态、成熟度、账户范围，以及上游过程资料与前置任务是否齐备。
5. 用 MCP 校验参数后执行体系规定的事实计算、信号计算或计划辅助计算；核对参数版本与哈希、数据来源与错误信息。
6. 过程资料写入 `knowledge/交易/过程资料/<YYYY-MM-DD>/<体系名称>/`。
7. 按体系规则生成或更新 `knowledge/交易/交易计划/<YYYY-MM-DD>/<体系名称>_交易计划.md`。
8. 计划执行、成交、持仓、现金与盈亏交给 `trade-management` 技能；复盘写入 `knowledge/交易/交易复盘/<YYYY-MM-DD>/<体系名称>_复盘.md`。
9. 完成完整工作后按 `summary` 技能写简报。

## 边界

- 不直接执行体系脚本，不从知识库读取运行参数或模板；体系计算、参数校验与渲染一律通过 MCP。尚未提供 MCP 的体系按 `reference/mcp.md` 的「存量体系迁入」收口。
- 不把计算结果、日期化状态或人工审批记录写回运行定义目录。
- 过程资料不能替代交易计划，交易计划不能替代交易复盘。
- 不用未来日期、其它体系或旧输出目录的结果冒充当前运行结果。
- 上游产物缺失、参数校验失败、数据不足或证据冲突时，如实记录并停止相关下游步骤。
- 不直接执行实际交易；实际下单与成交登记遵循交易管理流程。
- 是否允许生成正式计划，以体系成熟度和体系自身规则为准。
- 计划、复盘、摘要和通知中的数据日期、来源、证据强度、失败阶段、风险条件、账户性质与模拟/真实范围必须保留。

## 重要约束

- 遵循 `knowledge-management` 技能的路径、Frontmatter 和写作规范。
- 体系运行口径以该体系 `体系运作流程.md` 为唯一事实源；任务 `prompt.txt` 只写运行契约并指向 SOP 的具体章节。
- 使用运行定义 `system.yml` 中的 `system-id`，不自行创建或改写体系标识。
