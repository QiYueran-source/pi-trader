# 交易体系管理规则

## 体系资产

| 资产 | 位置 | 内容 |
|:--|:--|:--|
| 运行定义与 MCP 服务 | `.pi/mcp-servers/trade-system/<system-id>/` | `mcp_server.py`（入口，及 `functions/` 实现模块）、`params/`、`templates/` |
| 知识库体系文档 | `knowledge/交易/交易体系/<体系名称>/` | 体系介绍、MCP 介绍、运作流程、规则与专题、`更新日志/` |
| 体系定时任务 | `cronjob/system/<system-id 连字符形式>/` | 任务声明与 prompt |

知识库体系目录**只放文档**：不放可独立生效的参数、模板或计算脚本（这些在运行定义目录，且是唯一来源）；也不放跨日期证据、案例与设计记录（写入 `knowledge/笔记/<题材>/`）。目录命名、注册与接口见 [mcp.md](mcp.md) 与 [cronjob.md](cronjob.md)。

## 知识库体系文档

每个体系至少包含：

- `体系介绍.md`：体系目标、模块关系、运行入口、文件索引与过程产物清单。
- `体系运作流程.md`：该体系的运行 SOP；有运行流程时必须优先读取，执行口径以它的具体章节为唯一事实源。

按需包含：专题规则文档（如风控、参数说明、选股）、MCP 介绍（服务名、工具与入参、产物口径）、`更新日志/`（规则、参数、实现与结构变更记录）。跨日期有效的方法、证据、案例与设计记录写入 `knowledge/笔记/<题材>/`，体系文档引用它们时用逻辑路径。

## 静态内容与运行产物

- 静态规则与说明留在知识库体系目录；参数、模板与实现留在运行定义目录。
- 每日运行结果写入 `交易/过程资料/<YYYY-MM-DD>/<体系名称>/`（新内容写入 `knowledge/`，引用用逻辑路径）。
- 过程资料包括计算结果、风险事实、调节器事实、候选结果和中间分析。
- 过程资料不是最终交易指令；交易计划只保留可执行结论。
- 重跑或修正应保留历史事实，不能无痕覆盖导致无法追溯。

## 体系标识与成熟度

- `system-id` 即运行定义目录名，并在文档、任务与产物中保持一致；不自行创建或改写。
- 体系成熟度通常包括 `观察体系`、`候选体系` 和 `执行体系`。
- 观察体系以验证为主；是否允许实际交易以体系自身规则和用户明确要求为准。
- 体系规则、参数、实现或稳定产物发生变化时，更新对应体系文档和更新日志。

## 运行定义变更

改动参数、模板或实现后按顺序执行：

1. 改运行定义目录内的文件。
2. 用 MCP `validate_parameters` 校验参数；改实现或模板时用同一输入复算一次并比对事实值。
3. 写 `更新日志/<YYYY-MM-DD>_<主题>.md`，记动因、变更、验证与遗留。
4. 同步受影响文档与任务：规则、SOP、任务 prompt 与运行时注册。
5. 重载 MCP 客户端并自检（见 [mcp.md](mcp.md)）。

## 交易计划与复盘

- 交易计划写入 `交易/交易计划/<YYYY-MM-DD>/<体系名称>_交易计划.md`，记录未来动作、触发条件、参数、风险和失效条件。
- 交易复盘写入 `交易/交易复盘/<YYYY-MM-DD>/<体系名称>_复盘.md`，记录计划、执行、结果、偏差和体系改进建议。
- 计划、执行和复盘使用同一个 `system-id`，保持链路可追溯。
- 实际成交、持仓、现金和账户数据由 `trade-management` 技能登记，本技能不自行编造。

## 体系专属定时任务

目录与命名、prompt 与 SOP 的分工、注册与重启检查见 [cronjob.md](cronjob.md)。
