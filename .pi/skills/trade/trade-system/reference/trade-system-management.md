# 交易体系管理规则

## 体系目录

交易体系位于：

```text
knowledge/交易/交易体系/<体系名称>/
```

每个体系至少应有：

- `system.yml`：体系标识、账户、成熟度、静态目录和过程产物契约。
- `体系介绍.md`：体系目标、模块关系、运行入口和文件说明。
- `体系运作流程.md`：该体系的运行 SOP；有运行流程时必须优先读取。

体系目录还可以包含：

- `params/`：可审阅的业务参数。
- `scripts/`：计算、状态和渲染脚本。
- `templates/`：结构化过程资料的渲染模板。
- `references/`：跨日期仍有效的方法、证据和案例。
- `更新日志/`：体系规则、参数、脚本和结构变更记录。

## 静态内容与运行产物

- 静态规则、参数、脚本和模板保留在体系目录。
- 每日运行结果写入：

```text
knowledge/交易/过程资料/<YYYY-MM-DD>/<体系名称>/
```

- 过程资料包括计算结果、状态快照、风险事实、候选结果和中间分析。
- 过程资料不是最终交易指令；交易计划只保留可执行结论。
- 重跑或修正应保留历史事实，不能无痕覆盖导致无法追溯。

## 体系标识与成熟度

- 使用 `system.yml` 中已有的 `system-id`，并在相关文档中保持一致。
- 体系成熟度通常包括 `观察体系`、`候选体系` 和 `执行体系`。
- 观察体系以验证为主；是否允许实际交易必须遵循体系自身规则和用户明确要求。
- 体系规则、参数或稳定产物发生变化时，更新对应体系文档和更新日志。

## 交易计划与复盘

- 交易计划写入 `knowledge/交易/交易计划/<日期>/`，记录未来动作、触发条件、参数、风险和失效条件。
- 交易复盘写入 `knowledge/交易/交易复盘/<日期>/`，记录计划、执行、结果、偏差和体系改进建议。
- 计划、执行和复盘应使用同一个 `system-id`，保持体系运行链路可追溯。
- 实际成交、持仓、现金和账户数据由 `trade-management` 技能登记，不在本技能中自行编造。

## 体系专属定时任务

- 体系任务定义位于 `cronjob/system/<system-id>/`。
- 任务的业务顺序、输入、输出和依赖由对应体系的 SOP 说明；执行明细以 SOP 的具体章节为唯一事实源。
- `prompt.txt` 只写运行契约（触发语义、可用工具与数据来源、简报路径、投递与输出格式、硬边界）以及对 SOP 具体章节的引用；不重写 SOP 的步骤、产物清单和判定阈值。
- 每个任务的 `prompt.txt` 必须自包含，不能依赖当前对话上下文；「自包含」指不依赖对话上下文，引用体系内的规则与流程文档是允许且推荐的。
- 引用 SOP 时写「章节编号 + 标题」；SOP 调整结构或编号后，必须同步检查引用它的 prompt。
- 修改 prompt 或 SOP 章节结构后，按 cronjob 管理技能同步运行时注册。
- 注册、查询、启停和删除任务由 cronjob 管理技能负责。
- 本节口径适用于新建任务与体系改造；存量任务在下一次体系升级时改造。
