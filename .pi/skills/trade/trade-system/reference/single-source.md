# 单一事实源

## 原则

每类事实只有一个存放位置，其它位置只写**指针**或**带说明的索引**，不写副本。

判断一条信息该放哪，看**谁消费它、谁改它**：

- 机器计算要用 → 运行定义目录（参数、模板、契约）
- 人要读「为什么、怎么读」 → 知识库体系文档
- 调度要靠它触发 → 任务目录
- 账户、行情等运行时数据 → 对应的 MCP 与数据库

## 位置映射

| 事实类别 | 唯一位置 | 其它位置怎么写 |
|:--|:--|:--|
| 参数数值、阈值、倍数、档位 | 运行定义 `params/*.json` | 规则文档只写语义与含义，不写数值 |
| 模板正文与文案 | 运行定义 `templates/` | 文档不复制段落 |
| 运行契约（体系身份、账户、操作、产物、边界） | 运行定义 `system.yml` | 文档写「以 `system.yml` 为准」 |
| 运行步骤与判定顺序 | 体系 `体系运作流程.md` | 任务 `prompt.txt` 只写运行契约 + 章节引用 |
| 调度时间与投递 | 任务 `cronjob.yml` 与 `prompt.txt` | 技能与文档只写规范，不复制具体时间 |
| 命名映射（`system-id`、注册键、目录名、任务名） | [mcp.md](mcp.md) 的命名规则表 | 其它文件引它 |
| 落盘路径模板与命名 | `knowledge-management` 技能的 `reference/routes.md` | 本技能只写指针 |
| 账户、成交、持仓、现金 | `database/trade_management.db`（`trade-management` MCP） | 计划与复盘只引用，不手写数值 |
| 每日运行事实 | `交易/过程资料/<YYYY-MM-DD>/<体系名称>/` | 计划、复盘与简报引用它，不复制全文 |
| 审批留痕 | 过程资料 `human_review.json` | 不写回运行定义目录 |
| 待办 | 各文档的 todo 段落（`todo-management` 索引） | 简报只汇报，不作事实源 |
| 验证与实证证据 | `knowledge/笔记/<题材>/`、体系 `更新日志/` | 体系文档用逻辑路径引用 |

## 允许与不允许

允许：

- 带说明的索引，例如 `体系介绍.md` 列出过程产物名称并注明「产物契约以 `system.yml` 为准」。
- 章节引用，例如 `prompt.txt` 写「按 `体系运作流程.md` 第 2 节『盘后任务执行明细』执行」。
- 逻辑路径引用，不带 `knowledge/` 或 `archive/` 前缀。

不允许：

- 可独立生效的副本：参数数值、阈值、模板正文、契约条款、判定口径。
- 双入口表述：「按脚本执行或按同口径用 MCP 复算」这类两处都像事实源的说法。
- 同一份结果写进两处（例如同一份信号既落过程资料又抄进计划正文）。

## 以运行时为准

仓库文件存在不等于已生效：

- 运行定义改动后需重载 MCP 客户端，工具行为才更新。
- 定时任务以实时注册为准，仓库 `prompt.txt` 是副本；改完必须同步注册并回填 `job_id`。
- 副本与运行时不一致时，改副本并向运行时同步，不反过来以副本为准。

## 历史不回改

- 旧日期的过程资料、计划、复盘与更新日志保持原状，修正写新的 `更新日志/` 条目并产出新事实。
- 复现旧口径时按当时的模板与实现（见 git 历史），不用当前模板回改历史产物。
- 历史文档中的旧路径、旧 Frontmatter 不作追溯修改，除非用户明确要求。

## 冲突收口

发现同一事实存在两份时：

1. 先确认哪一份是事实源（通常是有校验、被机器读取的那份）。
2. 把另一份改成指针或索引。
3. 在体系 `更新日志/` 记一次收口（动因、范围、验证）。
4. 收口完成前，不再叠加新的副本。

## 已出现过的反例

- 双网格的参数与模板曾各存两份（运行定义与知识库），2026-10-17 收口到运行定义。
- 同一日的涨停口径曾在 `regulator_facts.json` 与 `sector_facts.json` 等处不一致；按「不回改历史」处理，修正只在后续日期生效。
- 任务 `prompt.txt` 曾落后于实时注册的同名 prompt；改为按注册内容逐字回写，并加自检。
