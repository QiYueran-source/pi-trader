# 体系定时任务

## 目录与命名

体系型任务放在：

```text
cronjob/system/<system-id 连字符形式>/<system-id 连字符形式>-<HHMM>-<动作>/
```

每个任务目录含 `cronjob.yml` 与 `prompt.txt`；`name` 与目录名一致，`schedule` 与名称中的 `HHMM` 一致。目录、任务名与 `system-id` 的对应关系见 [mcp.md](mcp.md) 的命名规则。

性质共通的调度规范（两类任务的差异、注册与查询、重启检查、投递机制）由 `agent-dev/cronjob-management` 技能负责，本文件只写体系侧的衔接口径。

## prompt 与 SOP 的分工

- `prompt.txt` 只写**运行契约**：触发语义与时间、交易日判断方式、可用的 MCP 与数据来源、简报路径、投递与输出格式、硬边界，以及指向体系 `体系运作流程.md` 的章节引用（写「章节编号 + 标题」）。
- 步骤、产物清单、判定阈值、计划结构写在 `体系运作流程.md`；prompt 不重写。
- SOP 调整章节结构或编号后，必须同步检查引用它的 prompt。

## 依赖写法

- 体系计算来源写**实际的服务名**（如 `div-etf-grid-trade`），不写脚本命令、不写「或按同口径用 MCP 复算」这类双入口表述。
- 数据与账户来源写 `tushare-data`、`trade-management` 的具体工具；待办索引写 `todo-management`。
- 不在 prompt 或配置中写密钥；密钥由 MCP 服务自行读取。

## 注册与检查

- 新建、修改或删除任务前，按 `agent-dev/cronjob-management` 技能确认变更内容与影响，再操作注册。
- 修改 `prompt.txt` 后同步更新运行时注册，并回填运行时的 `job_id` 到 `cronjob.yml`。
- 自检三项：`list` 中该任务有 `Next`、运行时记录不带 `session`、运行时 `prompt` 与仓库 `prompt.txt` 逐字一致。
- Pi 或调度器重启后重新核对这三项；仓库文件存在不代表任务已注册。

## 边界

- 定时任务只产出事实、参数与计划：不代替人工审批、不切换状态或防守档、不修改规则与参数、不代写复盘结论；各体系的具体边界以该体系 `体系运作流程.md` 为准。
- 任务失败、上游缺失或需要补做时，只汇报任务名称、失败阶段、原因和是否产生部分输出，由人工决定后续处理。
