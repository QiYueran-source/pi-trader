# 交易体系通用运行 SOP

具体体系的运行步骤以该体系目录中的 `体系运作流程.md` 为准。本文件只提供通用顺序。

## SOP 文档的必备内容

每个体系的 `体系运作流程.md` 是该体系运行口径的**唯一事实源**；体系任务的 `prompt.txt` 只写运行契约并指向它的具体章节。SOP 至少覆盖：

1. **运行入口**：该体系的任务清单（名称、时间、触发语义）、数据与账户来源、规则/参数/接口的唯一来源指针。
2. **执行明细**（任务指引的核心）：输入与前置条件；步骤与产物表（步骤 ｜ 数据来源（MCP 工具及入参）｜ 产物落盘的逻辑路径模板）；判定口径；输出结构（计划、复盘的字段与写法）；汇报要点；异常分支。
3. **审批与复盘衔接**：谁提出、谁审批、在什么时点、留痕写在哪、何时生效、超时如何顺延。
4. **按需链**：触发式事件（需要人工重设的参数、信号引发的审批、硬闸触发与恢复）各自的触发条件、动作、恢复条件与留痕。
5. **变更链**：参数、规则、实现（MCP）与流程变更的流程（校验 → 更新日志 → 文档同步 → 外部系统同步）。
6. **接口**：与全局任务及其他体系的输入输出关系。
7. **边界**：本体系不做的事（如不切换、不清仓、不代下单）。

写作约束：

- 判定阈值与可配参数分别留在规则文档与运行定义的 `params/`；接口与依赖口径留在体系目录的接口速查文档（如 `MCP介绍.md`）；SOP 只写职责、顺序与指针，不复制数值。
- 执行明细必须可执行：写明调用哪个 MCP 工具与入参、产出什么、写到哪个逻辑路径模板。
- SOP 调整结构或章节编号时，必须同步检查引用它的任务 prompt；prompt 引用写「章节编号 + 标题」。

## 运行前

- 确认当前工作目录和目标体系。
- 通过体系 MCP 读取运行契约（`get_manifest`），并读 `体系介绍.md`、`体系运作流程.md`。
- 确认 `system-id`、账户、成熟度和运行日期。
- 确认是否为交易日，以及本次任务对应的交易日或下一交易日。
- 按体系流程检查所需的前置过程资料、参数或其他事实来源是否存在且日期正确。

## 运行中

- 按体系运作流程指定的事实来源生成过程事实：体系计算通过 MCP，明确指定用户输入时使用已确认的用户输入；混合流程按体系规定的顺序执行。未明确指定事实来源时，不自行猜测执行方式，并停止依赖该事实的下游步骤。
- 再由 Agent 按体系规则解释事实并形成判断。
- 将计算结果和必要的分析材料保存到对应日期的过程资料目录。
- 按体系专属 cronjob 的顺序处理，不跳过缺失的上游产物。
- 发现输入缺失、日期不一致、参数错误或证据冲突时，记录问题并停止相关下游步骤。

## 运行后

- 需要未来动作时，生成交易计划，明确标的、动作、触发条件、参数、风险和失效条件。
- 已发生执行时，记录实际执行和偏差，并在适当时间生成交易复盘。
- 实际成交、持仓和资金变化交给 `trade-management` 技能登记。
- 完成一个完整工作后，调用 `summary` 技能在 `knowledge/摘要/.abstract/` 写入简报。

## 落盘路径与命名

本节中的路径模板表示落盘目的地，因此使用 `knowledge/...` 物理路径；文档正文中的链接、Frontmatter 路径字段和 MCP `logical_path` 则使用不含 `knowledge/` 或 `archive/` 前缀的逻辑路径。

路径模板以 `knowledge-management` 技能的 `reference/routes.md` 为准；写入前先检查目标目录、相邻日期和同体系文件，优先沿用已有结构和命名。

- 过程资料：`knowledge/交易/过程资料/<YYYY-MM-DD>/<体系名称>/<产物名称>.<扩展名>`
  - 产物名称应准确反映内容，例如 `strategy_state.json`、`signal_facts.json`、`signal_report.md`。
- 交易计划：`knowledge/交易/交易计划/<YYYY-MM-DD>/<体系名称>_交易计划.md`
- 交易复盘：`knowledge/交易/交易复盘/<YYYY-MM-DD>/<体系名称>_复盘.md`
- 体系简报：`knowledge/摘要/.abstract/YYYY-MM-DD_<简短主题>.txt`

命名要求：

- 日期统一使用 `YYYY-MM-DD`。
- 体系名称和 `system-id` 以运行定义目录名为准（知识库侧见 `体系介绍.md` 的 Frontmatter），不自行改写。
- 过程产物文件名使用稳定、简短、能表达内容的英文 `snake_case`。
- 交易计划和复盘文件名应包含体系名称及 `_交易计划` 或 `_复盘` 后缀。
- 新建文件前先检查是否已有同日、同体系、同类型文件，避免重复创建。
- 具体体系已有稳定命名时，兼容历史结构，不为统一格式强行批量改名。

## 禁止事项

- 不用旧日期、未来日期或其他体系的结果替代当前缺失结果。
- 不把过程资料直接当作交易计划。
- 不把交易计划当作已经发生的成交。
- 不在没有证据时补写价格、持仓、成交或收益。
- 不直接执行实际交易。
