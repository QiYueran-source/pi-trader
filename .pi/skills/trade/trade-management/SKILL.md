# 交易管理

## 触发

以下任务必须使用本技能：

- 查询账户、成交、持仓、现金、自选股或盈亏；
- 记录用户确认已经发生的成交；
- 核对交易计划与实际成交；
- 进行账户、体系或组合层面的持仓与交易复盘；
- 管理交易体系与账户之间的归属关系。

## 作用

本技能是 `trade-management` MCP 的业务入口，负责说明什么时候调用交易管理工具以及如何解释结果。MCP 服务负责数据库访问、参数校验、事务处理和具体业务实现。

本技能不直接访问数据库，不执行 SQL，不调用旧 CLI，也不提交券商订单。

## 使用原则

1. 查询数据时使用 MCP 返回的事实，不根据计划、文档或金额自行推算当前账户状态。
2. 记录成交前必须确认这是已经发生的成交，而不是计划、委托意图或建议；记录非成交现金流水（分红、利息、注资、取现、费用、调整）前，必须确认金额、日期、标记（`kind`）与来源，且不使用 `trade_record` 代替。
3. 记录成交前核对账户、交易体系、证券代码、方向、数量、价格和成交时间。
4. 发现疑似重复记录、账户归属不明或成交事实不完整时，停止写入并请求确认。
5. 现金、持仓和盈亏按账户与 `system_id` 保留归属；不能把不同体系的名义本金直接相加为实际总资产。
6. 复盘需要组合快照时，按账户和交易体系分别查询，再进行组合层整理。
7. `watchlist` 状态表示关注管理状态，不等同于实际成交、持仓或券商订单状态。
8. MCP 返回错误时如实报告错误阶段和原因，不能把错误当作空结果。

## 安全边界

- `trade_record` 只登记已确认成交，不执行真实下单。
- 真实交易必须经过独立的券商接口和人工确认。
- 交易、现金和自选股写入属于有副作用的操作；只读查询可以自动执行，写入必须符合对应确认要求。
- 数据库路径、表结构、工具参数和业务校验以 MCP 服务实现为准，不在技能中重复定义。
