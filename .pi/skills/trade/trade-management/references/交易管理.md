# 交易管理

交易管理用于记录每一笔实际发生的交易事件，为后续的持仓统计、收益计算、交易复盘提供统一的数据真相源。

## 作用

交易管理的核心作用包括：

1. **记录单笔交易事件**：每一次买入或卖出都作为独立交易记录保存
2. **作为持仓和收益的真相源**：当前持仓、成本、已实现收益等由交易流水推导得到
3. **支撑交易复盘**：可以回看每一笔交易的时间、方向、价格、数量、体系归属和备注
4. **支撑多体系并行管理**：支持同一账户下按交易体系区分交易、持仓和盈亏
5. **支撑后续导入与对账**：未来可接券商交割单或外部数据导入

## 设计原则

交易管理当前采用“单笔交易事件”模型，而不是直接维护“证券持仓表”作为真相源。

也就是说：

- 买入时新增一条交易记录
- 卖出时新增一条交易记录
- 当前持仓由交易记录汇总得出
- 收益由交易记录和账户费率规则计算得出
- 每条交易记录可通过 `system_id` 标记其归属的交易体系

这样设计的优点是：

- 真相源清晰，不会把结果状态误当成事实
- 后续可以重算持仓、成本和收益
- 更利于复盘和追踪每一笔交易动作
- 可以在同一账户下按体系切分交易流水和盈亏表现

## 表结构

- 表名：`trade`
- 字段定义：
    - `id`：交易记录主键，自增整数
    - `account_id`：账户 ID，对应 `account.id`
    - `system_id`：交易体系 ID，用于标记该笔交易归属的体系，如 `dividend_etf_grid`
    - `code`：证券代码，如 `600519.SH`
    - `name`：证券名称，如 `贵州茅台`
    - `side`：交易方向，取值为 `buy` 或 `sell`
    - `quantity`：成交数量
    - `price`：成交价格
    - `occurred_at`：交易发生时间
    - `note`：交易备注，如“突破买入”“止盈卖出”
    - `updated_at`：最后更新时间

## 字段说明

### 主键

建议使用：

```sql
id INTEGER PRIMARY KEY
```

说明：

- `id` 作为自增主键，便于引用、更新和删除
- `system_id` 属于业务归类字段，不参与主键设计
- 不建议直接将 `证券代码 + 时间戳` 作为主键
- `证券代码 + 时间戳` 可以作为业务识别方式，但不适合作为数据库主键

### 体系归类字段

建议使用：

```sql
system_id TEXT NOT NULL
```

说明：

- `system_id` 用于标记这笔交易归属于哪个交易体系
- 同一账户下，同一证券可以因为不同体系而产生不同交易记录
- `system_id` 不作为主键，但应保持命名稳定、一致、可读
- 如果是旧数据或未归类数据，可临时使用如 `legacy` 之类的默认值

## 最小建表 SQL

```sql
CREATE TABLE IF NOT EXISTS trade (
    id INTEGER PRIMARY KEY,
    account_id TEXT NOT NULL,
    system_id TEXT NOT NULL,
    code TEXT NOT NULL,
    name TEXT NOT NULL,
    side TEXT NOT NULL,
    quantity REAL NOT NULL,
    price REAL NOT NULL,
    occurred_at TEXT NOT NULL,
    note TEXT,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (account_id) REFERENCES account(id)
);
```

## 索引建议

### 主键索引

- `id` 作为主键，会自动具备主键索引

### 推荐普通索引

建议补以下索引：

```sql
CREATE INDEX IF NOT EXISTS idx_trade_account_id
ON trade(account_id);

CREATE INDEX IF NOT EXISTS idx_trade_system_id
ON trade(system_id);

CREATE INDEX IF NOT EXISTS idx_trade_code
ON trade(code);

CREATE INDEX IF NOT EXISTS idx_trade_occurred_at
ON trade(occurred_at);
```

如果后续经常按“账户 + 体系 + 证券 + 时间”查询交易历史，可以进一步补联合索引：

```sql
CREATE INDEX IF NOT EXISTS idx_trade_account_code_time
ON trade(account_id, code, occurred_at);

CREATE INDEX IF NOT EXISTS idx_trade_account_system_time
ON trade(account_id, system_id, occurred_at);

CREATE INDEX IF NOT EXISTS idx_trade_account_system_code_time
ON trade(account_id, system_id, code, occurred_at);
```

## 当前字段取舍

当前第一版有意保持较小字段集，以下字段暂不写入表：

- `fee`：暂不直接保存费用，后续由账户费率规则计算
- `amount`：暂不单独保存成交金额，可由 `price * quantity` 计算得到
- `created_at`：当前不区分“录入时间”和“最后更新时间”，先只保留 `updated_at`

### 注意事项

- 由于当前不保存 `fee`，后续收益统计时需要明确费用计算逻辑
- 如果账户费率规则未来发生变化，历史交易收益的回算口径也会受到影响
- `side` 应限制为 `buy` 或 `sell`，避免自由文本导致后续统计混乱
- `quantity` 和 `price` 建议统一使用数值类型，便于后续统计和收益计算
- `system_id` 建议采用稳定命名，例如 `dividend_etf_grid`、`agent_etf_rotation`

## CLI 使用说明

`trade_cli.py` 提供交易记录管理和盈亏追踪两类功能。

### 创建交易记录

```bash
./trade_cli.py create \
  --account-id <账户ID> \
  --system-id <体系ID> \
  --code <证券代码> \
  --name <证券名称> \
  --side <buy|sell> \
  --quantity <成交数量> \
  --price <成交价格> \
  --occurred-at <交易时间> \
  --note <备注>
```

- `--account-id`：必填，账户 ID，需在 `account` 表中已存在
- `--system-id`：必填，交易体系 ID
- `--code`：必填，证券代码，如 `600519.SH`
- `--name`：必填，证券名称，如 `贵州茅台`
- `--side`：必填，交易方向，仅支持 `buy` 或 `sell`
- `--quantity`：必填，成交数量（浮点数）
- `--price`：必填，成交价格（浮点数）
- `--occurred-at`：必填，交易时间，格式 `YYYY-MM-DD HH:MM:SS`
- `--note`：可选，交易备注

### 列出交易记录

```bash
# 列出所有交易记录
./trade_cli.py list

# 按账户筛选
./trade_cli.py list --account-id <账户ID>

# 按体系筛选
./trade_cli.py list --system-id <体系ID>

# 按证券筛选
./trade_cli.py list --code <证券代码>

# 组合筛选
./trade_cli.py list --account-id <账户ID> --system-id <体系ID> --code <证券代码>
```

输出格式：`#ID [时间] 账户/体系 方向 代码 名称 数量@价格`

### 查看交易详情

```bash
./trade_cli.py show <交易ID>
```

输出包含：ID、账户、体系、代码、名称、方向、数量、价格、金额、时间、备注、更新时间。

### 更新交易记录

```bash
./trade_cli.py update <交易ID> [--system-id] [--quantity] [--price] [--occurred-at] [--note]
```

- 只需传入需要更新的字段，未传入的字段保持不变
- 更新后自动刷新 `updated_at`
- `--system-id` 可用于手工重归类该笔交易

### 删除交易记录

```bash
./trade_cli.py delete <交易ID>
```

删除前会要求确认。

### 盈亏追踪

```bash
# 基本盈亏追踪（仅已闭合盈亏）
./trade_cli.py pnl --account-id <账户ID> --code <证券代码>

# 按体系筛选盈亏
./trade_cli.py pnl --account-id <账户ID> --code <证券代码> --system-id <体系ID>

# 传入当前价格，计算未闭合盈亏和总盈亏
./trade_cli.py pnl --account-id <账户ID> --code <证券代码> --system-id <体系ID> --price <当前价>

# 显示详细配对信息
./trade_cli.py pnl --account-id <账户ID> --code <证券代码> --system-id <体系ID> --price <当前价> --detail
```

输出字段说明：

- **总买入**：该范围下的总买入数量
- **总卖出**：该范围下的总卖出数量
- **剩余数量**：未平仓数量
- **已闭合盈亏**：已完成开仓-平仓配对的盈亏（扣除费用）
- **未闭合盈亏**：剩余仓位按当前价计算的浮动盈亏（需 `--price`）
- **总盈亏**：已闭合 + 未闭合盈亏（需 `--price`）

使用 `--detail` 时额外输出：

- 每段开仓-平仓配对的买入价、卖出价、数量和盈亏
- 未闭合仓位的剩余数量和平均成本

### 证券类型自动识别

`pnl` 命令根据证券代码自动识别类型以选择对应费率规则：

- 代码以 `51`、`15`、`16` 开头 → ETF
- 其他 → 股票（stock）

### 费用计算

费用根据账户的 `fee` JSON 规则动态计算，包含：

- **佣金**：`成交金额 × 佣金率`，不低于最低佣金
- **印花税**：仅卖出时收取，`成交金额 × 印花税率`
- **过户费**：`成交金额 × 过户费率`

买入和卖出费用均从盈亏中扣除。

## 盈亏追踪说明

### 设计目标

`pnl` 命令不再强调“实际盈亏 / 浮动盈亏”这两个对外概念，而是按交易流水输出更适合复盘的结果：

- 已闭合交易段盈亏
- 未闭合剩余仓位盈亏
- 总盈亏

### 计算口径

建议按以下口径处理：

1. 在同一个 `account_id + code` 范围内汇总交易记录
2. 如果传入 `--system-id`，则进一步限制在同一个 `account_id + system_id + code` 范围内
3. 采用 `FIFO` 方式做买卖配对
4. 每一次完整的开仓-平仓形成一个闭合交易段
5. 最后未卖完的剩余仓位作为未闭合仓位保留
6. 如果传入当前价格 `--price`，则进一步计算未闭合仓位盈亏和总盈亏

### 输出结构建议

默认输出摘要信息：

- 账户 ID
- 体系 ID（如果传入）
- 证券代码
- 总买入数量
- 总卖出数量
- 剩余数量
- 已闭合盈亏
- 未闭合盈亏（仅在传入 `--price` 时计算）
- 总盈亏

如果带上 `--detail`，则额外输出每一段交易配对明细：

- 第 1 段开仓-平仓盈亏
- 第 2 段开仓-平仓盈亏
- 最后一段未闭合仓位的剩余数量、剩余成本和当前盈亏

### 注意事项

- 盈亏追踪应限制在同一个账户内进行，不能跨账户混算
- 当前表中不直接保存 `fee`，后续收益统计时需要按账户费率规则动态计算
- 如果未传 `--price`，则无法得到完整的未闭合盈亏，只能输出已闭合盈亏和剩余仓位信息
- `side` 应严格限制为 `buy` 或 `sell`
- 如果不传 `--system-id`，`pnl` 默认按整个账户下该证券的交易记录聚合

## 现金自动联动

创建交易记录时，系统会自动往 `cash_flow` 表插入一条对应的现金变动记录：

- **买入**：现金流出 = `quantity * price + 手续费`，reason 为 `买入 <代码> <数量>股@<价格> (trade#<ID>)`
- **卖出**：现金流入 = `quantity * price - 手续费`，reason 为 `卖出 <代码> <数量>股@<价格> (trade#<ID>)`

手续费根据账户的 `fee_rules` 动态计算，与 `pnl` 命令保持一致。如果账户没有配置费率规则，手续费按 0 计算。

详细的现金管理说明请参考 `references/现金管理.md`。

## 后续扩展方向

后续如有需要，可以再扩展以下字段或能力：

- `fee`：记录单笔交易总费用
- `amount`：记录成交金额
- `commission` / `stamp_duty` / `transfer_fee`：拆分费用结构
- `broker_trade_id`：接入券商导入时保留外部成交编号
- 独立的 `system` 表：对 `system_id` 做更强约束和元数据管理
- `position_snapshot`：保存阶段性持仓快照，但不作为唯一真相源
