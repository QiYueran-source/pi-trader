# 复盘行情数据拉取模式（2026-08-10 实测）

复盘/信号复核 cron 需要拉当日指数与 ETF 行情做信号链判断。标准做法是写一个临时 .py 文件一次拉取（不要用 `python -c` 内联长代码，避免转义/安全扫描问题），脚本 shebang 用 `/opt/hermes/.venv/bin/python3`。

## 核心接口

- **指数**（如科创50 000688）：`pro.index_daily(ts_code='000688.SH', start_date=..., end_date=...)`
- **ETF/基金**（如 511990 华宝添益）：`pro.fund_daily(ts_code='511990.SH', ...)` — ETF 用 fund_daily 不是 daily（静默空）
- 两者都必须带 `.SH/.SZ` 后缀，裸代码静默返回空；每次调用后检查 `len(df) > 0`
- 拉完 `sort_values('trade_date')` 再看，输出关键列 `trade_date/open/high/low/close/pct_chg/vol/amount`
- **vol/amount 单位陷阱**：`fund_daily` 与 `index_daily` 的 `vol` 单位是「手」、`amount` 单位是「千元」，都不是「万手/亿元」。转万手需 `/10000`（如科创50 8/14 vol=8685139 手 = 868.51 万手）。写临时脚本打印列时别把 `vol` 直接标成「万手」，否则量能环比会错一个数量级

## 代码后缀陷阱：000688

科创50 指数是 `000688.SH`（上交所指数），**不套用股票代码段规则**（000xxx 段股票是 `.SZ`，且存在股票 000688.SZ 国城矿业）。指数按交易所定后缀：上交所指数 `.SH`，深交所指数 `.SZ`。不确定时 `.SH`/`.SZ` 各试一次并检查返回行数。

## token fallback

cron/子进程环境下 `TUSHARE_TOKEN` 可能不在 os.environ。脚本开头依次尝试：

```python
token = os.environ.get("TUSHARE_TOKEN", "")
if not token:
    for p in ["/opt/data/.tushare_token", "/hermes-trader/.tushare_token", os.path.expanduser("~/.tushare_token")]:
        if os.path.exists(p):
            token = open(p).read().strip()
            break
if not token:
    print("NO_TOKEN"); raise SystemExit(1)
```

带 fallback 的取数脚本在 cron 场景实测可直接跑通。

## 复盘判断要点（ETF轮动体系信号链）

- 「缩量止跌日」候选形态：量能较前日萎缩（8/10 科创50 1082万手 vs 8/7 1214万手，约 -11%）、涨幅收窄/微跌、低点不破前日低点
- ⚠️ **「缩量止跌」两个条件缺一不可**：①量较前日萎缩达标（15%+）②低点不破前日低点。若量萎缩达标但**低点跌破前低**，是「缩量阴跌」而非「缩量止跌」，候选不成立（8/14 实例：科创50 量 -17.89% 达标，但低点 1690.68 破 8/13 低点 1715.34 → 第三例候选证伪，窗口继续关闭）
- 4000 万手绝对值阈值近一月无区分度（实际量能常驻 1000-1500 万手），观察以「相对萎缩」为主
- 双日确认条件：次日放量反弹 >3%（确认线收盘价 = 前收 × 1.03）
- **低波防御资产（国债 511260）单日放量创新高 ≠ 趋势确认**：8/10 国债「创新高 135.569 + 放量 47.68万手」后 8/11 即缩量回调，单日放量常是脉冲。判定是否构成「明确替代」需连续两日放量创新高确认，不能因单日量能放大即从现金切换

## 涨停统计：limit_list_d 无权限的替代法（8/10 实测）

热门板块回调低吸复盘要判断「元器件板块涨停几只/排名」。`pro.limit_list_d` 本账户无权限（报「没有接口访问权限」）。替代：一次脚本内拉 `pro.daily(trade_date=...)`（全市场当日行情）+ `pro.stock_basic(fields="ts_code,name,industry")`（行业映射），按代码段涨停阈值过滤（主板 ≥9.8%、30/68 开头 ≥19.5%、.BJ ≥29.5%），再 `Counter(industry)` 聚合出行业涨停 TOP。8/10 实测：全市场涨停 103 只，元器件 6 只（电气设备 7 只第 1）。**口径注意**：8/7 计划里的「元器件 15 涨停」是 22 天窗口累计口径，与单日涨停数不可直接对比，复盘对比时要标注口径。

## 开盘半小时审慎标签检查（热门板块回调低吸复盘 cron 职责）

复盘 cron（1830）常需补做 1825 执行 cron 未做的第一层风控：拉 `pro.stk_mins(ts_code=code, freq='5min', start_date='YYYY-MM-DD 09:30:00', end_date='YYYY-MM-DD 10:00:00')`（一次性拿全 7 根 bar），用 risk_signal.py 的 classify 逻辑判信号：`low <= open*(1-0.03)` → rapid_drop；先涨后跌不过开盘 → weak_distribution；先跌后涨不过开盘 → weak_rebound；先涨后跌不破开盘 → strong_continuation；先跌后涨站稳开盘 → strong_recovery。rapid_drop/weak_distribution/weak_rebound 打审慎标签（3 交易日有效，写 prudent_tags.json）；标签有效期内 MA5 跌破 → 当日直接减半（加速模式，无观察期）。stk_mins 拉取必须一次性完成全部计算（限频陷阱见 SKILL.md #19）。
