# 整体持仓复盘

## 定位

本技能从组合视角复盘全部相关账户和交易体系，不属于任何单一 `system-id`，也不替代体系级复盘。体系级规则、信号和计划仍由各体系负责。

## 输入与边界

1. 确认复盘日期及是否为交易日。
2. 从 `trade-management` MCP 获取当日成交、相关持仓、现金和盈亏；按账户与 `system_id` 保留归属。
3. 读取当日各体系交易计划、体系复盘、市场事实和用户回复；缺失时如实标注，不用其他日期补充。
4. 对照计划与成交，逐笔标记计划内、计划外、遗漏执行或无法判断。
5. 不把不同体系的名义本金相加为实际总资产；没有可靠的真实资产与仓位数据时，明确说明口径限制。
6. 不猜测用户动机，只记录用户明确提供的主观判断；不执行真实交易，不擅自生成或修改任一体系的交易计划。

## 复盘内容

按以下顺序形成结论：

1. **看市场**：指数、量能、市场宽度、主线与风险，以及对持仓的事实性影响。
2. **看持仓与执行**：按账户和体系列出成交、持仓、成本、盈亏及计划偏差；识别同标的、同方向或同风险因子的集中暴露、体系间叠加或冲突。
3. **看自己**：整理用户对操作依据、纪律执行和情绪因素的回复；区分决策质量与盈亏结果。
4. **待办**：列出需要用户或对应体系处理的风险、数据缺口与待验证事项。需要交易动作时，只说明应回到哪个体系的计划处理。

单日结果只能作为经验或待验证假设，不能自动升级为交易规则。

## 落盘

完成复盘后写入：

- 正式复盘：`knowledge/交易/交易复盘/{日期}/整体复盘.md`
- 简报：`knowledge/摘要/.abstract/{日期}_portfolio-review.txt`

正式复盘使用 `knowledge-management` 技能规定的 Frontmatter 最小格式：`title`、`summary`、`date`、`tags`。可按需要补充 `account_id`、`trade_type` 和 `links`；该文档不使用单一 `system-id`，正文说明实际覆盖的账户和体系。

已有同日整体复盘时先读取；除非用户明确要求修订，不重复创建或无痕覆盖。

## 输出

向用户简要说明：整体市场结论、计划执行偏差、组合层面的风险或集中暴露、用户已确认的主观复盘结论，以及需要由哪个体系继续处理的待办。
