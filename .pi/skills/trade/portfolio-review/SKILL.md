# 整体持仓复盘

## 定位

本技能从组合视角复盘全部相关账户和交易体系，不属于任何单一 `system-id`，也不替代体系级复盘。体系级规则、信号和计划仍由各体系负责。

本技能只整理事实、执行偏差和用户明确提供的主观判断，不代替任何体系生成交易计划，不执行真实交易。

## 每日复盘追问

交易日 22:30 由 `global-2230-manual-review` 任务推送固定清单。推送前只核验事实和提问，不写复盘结论、不评价操作、不提供买卖建议、不生成跨体系交易计划；非交易日不推送，只写简报。

```text
【今日整体复盘清单 · {今天日期}（周X）】

一、看市场（水温）
   指数：{上证/深成指/创业板指涨跌幅；缺失则标明}
   量能：{全天成交额、较上一交易日增减；涨跌家数；缺失则标明}
   板块：{涨停最集中方向} ｜ 领跌：{方向；缺失则标明}

二、看自己（整体持仓与交割单）
   今日成交：
   - {逐笔：账户 / 体系 / 方向 / 标的 / 数量 @价格（时间）/ 计划判定}
   持仓：{相关账户和体系的剩余数量与成本}
   → 请回两句：
     ① 这些操作是「模式内试错」，还是「偏离规则」？
     ② 当时是因为看到信号下单，还是不甘心 / 怕踏空？

三、定明天（只记录意图）
   → 请回一句：如果明天继续跌，你的整体防守底线是什么？

（回复后调用 `portfolio-review` 技能，落盘《整体复盘》，并列出需要由对应体系分别处理的行动与待办。）
```

## 输入与事实核验

1. 确认复盘日期及是否为交易日。
2. 加载 `trade-management` 技能，使用其 MCP 工具获取交易事实；不得直接访问数据库、执行 SQL 或调用旧 CLI。
3. 确定复盘范围：从当日交易计划、相关体系配置和交易记录识别涉及的账户与 `system_id`。无法确定范围时列出缺失，不自行补齐。
4. 对每个账户和交易体系组合分别调用 `portfolio_snapshot`，获取现金、非零持仓和 `trade_as_of`。
5. 使用 `trade_list` 查询复盘日期内的成交；需要单笔详情时使用 `trade_get`。
6. 对需要当前估值的持仓，按账户、体系和证券调用 `trade_pnl` 并提供当前价格；不得用成本或交易金额代替市值和未实现盈亏。
7. 读取当日各体系交易计划、体系复盘、市场事实和用户回复；缺失时如实标注，不用其他日期补充。行情数据拉取的接口选择、代码后缀和单位口径遵循 [`trade-management` 的复盘行情数据参考](../trade-management/references/复盘行情数据拉取.md)。
8. 对照计划与成交，逐笔标记计划内、计划外、遗漏执行或无法判断。

## 账户、体系与组合口径

- 账户级、体系级和组合级结果分开呈现，不把不同体系的名义本金直接相加为实际总资产。
- `portfolio_snapshot` 返回的现金是账户—体系账本现金，不自动等同于券商真实现金或组合总资产。
- 组合总资产只有在取得可靠的账户现金、持仓当前估值和估值时间后才能计算；数据不完整时只报告已知部分并说明限制。
- 同一证券被多个体系持有时，先按体系分别列出，再在组合层按实际账户和证券合并展示，避免重复计算；必须保留体系归属和共仓关系。
- 不能把 `watchlist` 状态当作成交或持仓事实；实际成交和持仓以交易管理 MCP 返回为准。
- 不同账户中的同一证券不能直接合并为单一账户持仓，必须保留账户边界。
- `trade_as_of` 只能说明交易账本截止时间，不代表行情估值时间；两者不同必须明确标注。
- MCP 查询失败、账户或体系范围不明、行情缺失或时间口径不一致时，标记为缺失或无法判断，不推断为空仓或零成交。

## 看自己

整理用户对操作依据、纪律执行和情绪因素的回复；不猜测用户动机，只记录用户明确提供的主观判断。区分决策质量与盈亏结果，不因盈利或亏损反推操作是否正确。

## 复盘内容

按以下顺序形成结论：

1. **看市场**：指数、量能、市场宽度、主线与风险，以及对持仓的事实性影响。
2. **看持仓与执行**：按账户和体系列出成交、持仓、成本、已实现盈亏、未实现盈亏及计划偏差；识别同标的、同方向或同风险因子的集中暴露、体系间叠加或冲突。
3. **看自己**：整理用户对操作依据、纪律执行和情绪因素的明确回复。
4. **待办**：列出需要用户或对应体系处理的风险、数据缺口与待验证事项。需要交易动作时，只说明应回到哪个体系的计划处理。

单日结果只能作为经验或待验证假设，不能自动升级为交易规则。

## 落盘

完成复盘后写入：

- 正式复盘：`knowledge/交易/交易复盘/{日期}/整体复盘.md`
- 简报：`knowledge/摘要/.abstract/{日期}_portfolio-review.txt`

22:30 追问任务的事实核验简报写入 `knowledge/摘要/.abstract/{日期}_global-2230-manual-review.txt`，与整体复盘简报分别保留，不相互覆盖。

正式复盘使用 `knowledge-management` 技能规定的 Frontmatter 最小格式：`title`、`summary`、`date`、`tags`。可按需要补充 `account_id`、`trade_type`。

已有同日整体复盘时先读取；除非用户明确要求修订，不重复创建或无痕覆盖。

## 输出

向用户简要说明：整体市场结论、计划执行偏差、账户和体系层持仓事实、组合层风险或集中暴露、用户已确认的主观复盘结论，以及需要由哪个体系继续处理的待办。
