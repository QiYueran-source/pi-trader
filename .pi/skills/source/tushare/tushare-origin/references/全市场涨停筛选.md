# 全市场涨停筛选与候选股生成模式

## 场景

需要从全市场 A 股中，筛选满足特定技术条件的股票池（如涨停板数量、均线位置、成交量等），而非单只个股分析。

## 推荐数据流

```
daily(trade_date=X)               → 某日全市场行情（含 pct_chg）
  → 按 pct_chg >= 9.5 过滤涨停     → 涨停股票列表（按天聚合）
  → 统计窗口内涨停次数             → 各股票涨停板计数
  → 按板数过滤（如1-2板）          → 初选池
stock_basic                        → 补名称、行业（申万分类）
daily(ts_code=XXX, ...)            → 逐只拉日线计算均线/成交量
  → time.sleep(0.15)               → 控制频率
  → 回调不破 N 日线                 → 最终候选池
```

## 关键接口技巧

### 替代 limit_list_d（1次/分钟限制）

```python
df = pro.daily(trade_date="20260615")
up = df[df["pct_chg"] >= 9.5]
```

`daily(trade_date)` 不加 `ts_code` 返回全市场数据，频率限制宽松得多。

注意：`pct_chg >= 9.5` 能覆盖主板10%涨停和科创/创业板20%涨停，但无法区分"封板"和"盘中触及"。如需要精确的封板/炸板区分，应使用 `limit_list_d` 但做好分钟级节流。

### 补充名称和行业

```python
df = pro.stock_basic(ts_code=",".join(codes), fields="ts_code,name,industry")
info = {str(r["ts_code"]): {"name": r["name"], "industry": r["industry"]} for _, r in df.iterrows()}
```

`stock_basic` 频率限制宽松，一次性可查数千条。

## 候选池输出规范

建议使用以下结构输出候选股 JSON：

```json
{
  "date": "20260615",
  "params": {
    "window_days": 10,
    "ma_period": 10,
    "min_boards": 1,
    "max_boards": 2
  },
  "stats": {
    "total_limit_up_stocks": 998,
    "candidates_filtered": 516
  },
  "candidates": [
    {
      "code": "300408.SZ",
      "name": "三环集团",
      "industry": "电子",
      "board_count": 1,
      "board_dates": ["20260612"],
      "current_close": 150.25,
      "ma10": 134.753,
      "pullback_pct": -1.01,
      "bounceback_days": 1
    }
  ]
}
```

- `bounceback_days`: `null`=从未跌破MA10，数字=跌破后几天站回
- 文件建议用 `latest.json` 覆盖写入，不留历史
- 配合 `render_candidates.py` 输出 Markdown 表格供 AI 分析
