# 2026-08-04 体系升级：窗口22天 + 三层仓位分级 — 回测依据

286 交易日（2025-06-03 ~ 2026-08-03）长样本回测驱动的一次升级。核心结论：**体系瓶颈不是"条件太严"，是市场环境**；但有两处放松被数据证明有效，且都避开"放宽信号质量"的坑——只动参与时机（窗口）和参与仓位（试仓）。

## 回测结论速查（全部来自长样本，n 均 ≥ 30 才有统计意义）

### 1. 板块热度单维度预测力弱

| 信号 | n | 胜率 | 均值 |
|:-----|:----:|:----:|:----:|
| 涨停≥5 单日（板块） | 58/280 | 40% | -0.83% |
| 涨停≥5 持续2天 | 107 | 40% | -0.70% |
| 涨停≥5 持续3天 | 64 | 36% | **-1.35%** |
| 多头排列 持续2天 | 2105 | 36% | -1.35% |

- **"持续"不 work，反而越久越差**：持续满足条件 = 板块已涨很久 = 情绪高潮接盘，不是"资金确认"。
- 短样本（20天，7月下旬普涨）曾显示多头持续2天 79% 胜率——**普涨行情的假象**，拉长到 286 天变 36%。
- 唯一转正组合：板块当日双确认（涨停≥5 **且** 多头）+ 大盘企稳 → +1.94%（n=49，短样本）/ +0.25%（n=672，长样本放宽版）。

### 2. 窗口 10→22 天：白捡的改进（个股认证）

| 窗口 | n | 胜率 | 均值 |
|:-----|:----:|:----:|:----:|
| 10天（旧） | 3016 | 37% | -1.22% |
| 22天（新） | 9128 | 39% | -0.97% |
| 22天新增部分 | 6112 | 40% | **-0.84%** |

- 样本扩大 3 倍，新增部分质量更高：10 天窗口常抓"涨停后立刻回调"的接飞刀；22 天能等到"涨停→充分回调→站回MA10"的**潜伏末期**形态。
- **⚠️ 板块热度窗口保持 10 不动**：22日累计涨停过滤（-1.06%）显著差于当日涨停≥5（-0.55%）。窗口拉长只作用于个股认证（pick.json 涨停窗口），板块确认必须看当日。

### 3. 三层仓位分级（试仓逻辑）

| 层级 | 条件 | 仓位 | 期望 |
|:-----|:-----|:-----|:-----|
| 🟢 正式仓 | 开仓信号 + 板块当日双确认 + 大盘企稳(cyb>0) | 正常单票仓位 | +0.25% |
| 🟡 试仓 | 开仓信号 + 板块当日双确认 + 大盘非极端弱(cyb>-2%) | 单票 1/4 | -0.09% |
| ⚪ 观察 | 其他 | 只记录 watchlist | — |

- 试仓条件比正式仓只少"大盘企稳"一层，换 902 个样本的参与机会，代价是期望接近零。**1/4 仓位承担零期望试错，换取不空仓、不错过主升启动。**
- **试仓无风控豁免**：三层风控（审慎标签/MA5减半/MA10清仓）一视同仁——这是试仓安全的核心。
- 试仓升级：持仓期间板块双确认 + 大盘企稳同时满足 → 加仓至正式仓。
- **试仓条件不能再低**：只要求"板块多头"就试仓 → -0.52%（n=2999），稳定亏钱。

### 4. 投顾方向（财经分析）作为板块判断源 — 只能做排除项

| 投顾 sentiment | n | 胜率 | 均值 |
|:-----|:----:|:----:|:----:|
| 板块 积极 | 87 | 23% | -0.95% |
| 板块 谨慎 | 10 | 30% | -0.29% |
| 板块 消极 | 11 | 36% | -0.61% |
| 个股 积极 | 88 | 33% | **-3.72%** |

- 投顾"看好"方向 5 日内平均跑输基准（+0.44%）——荐股往往在板块涨起来之后，追的是情绪不是起涨点。
- **但"谨慎/消极"有规避价值**：可用作 generate-plan 的排除清单（板块数据热但投顾明确看空 → 不追/降级）。
- 与红利网格状态机"投顾判断优先"不冲突：那是大级别方向（normal/bull/bear），不是短线买点确认。

## 验证方法论备忘（下次调参照做）

1. 先跑短样本（20天）快速看方向，**必须再拉长样本（200+天）确认**——短样本结论经常是行情区间的假象。
2. 数据一次性拉全市场 daily 存 parquet（286天约 156 万行、21MB，比反复 API 调用快），用 `pd.read_parquet` 复用。
3. 每个结论带 n；n<30 只算观察不算结论。
4. 测"持续 N 天"时用 `persist(sector, end_idx, k, mode)` 逐日回看窗口，不要只测单日。
5. 注意 Tushare `daily` 的 trade_date 是 `YYYYMMDD`，mentions DB 的 mention_date 是 `YYYY-MM-DD`——跨库比对前统一格式（2026-08-04 实测踩坑）。
