# 新增交易日判断工具 is_trading_day | 2026-10-18

## 一、动因

用户 2026-10-18 裁定：每个体系自带一个交易日判断工具，各服务各写一份实现，不共用 `tushare-data` MCP 的 `get_trade_calendar`。

## 二、变更

| 对象 | 变更 |
|:--|:--|
| `.pi/mcp-servers/trade-system/zslof_timing_trade/` | 新增工具 `is_trading_day`（`system_id` 必填、`date` 可选，默认今天；返回 `ok`／`is_open`／`pretrade_date`／`source`），实现放在本服务内（`tushare.trade_cal`，SSE） |
| 同目录 `system.yml` | 增加 `utilities: [is_trading_day]` 声明（工具属声明，不含参数取值） |
| `交易/交易体系/招商双债LOF择时体系/MCP介绍.md` | 工具表补该工具一行；依赖段说明「交易日判断由本服务自带」 |
| `交易/交易体系/招商双债LOF择时体系/体系运作流程.md` | 「交易日判断」由 `tushare-data.get_trade_calendar` 改为本体系 MCP `is_trading_day` |

## 三、验证

- 真实 stdio 握手：工具数 5→6，`is_trading_day` 实测 `2026-10-16 → is_open=true`、`2026-10-18 → is_open=false`、省略 `date` 取今天（2026-10-18，`false`），`pretrade_date` 正确；体系不符、非法日期格式按 `{"ok": false, "error": ...}` 拦截。
- `validate_parameters` 与既有工具（`get_manifest`／`calculate`／`render`）行为不变。

## 四、遗留

- 体系任务 `prompt.txt` 与运行时注册中的「交易日判断用 `tushare-data.get_trade_calendar`」将同步改为本服务工具，**待用户确认后一并更新并重注册**（按 `agent-dev/cronjob-management` 的确认要求）。
- 运行中的 MCP 子进程仍为改动前进程，重启或新会话后加载新工具。
