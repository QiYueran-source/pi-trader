# 2026-08-10 招商双债LOF择时体系建立与升级

## 一、体系建立（12:00）

基于 2026-08-09 实证分析《招商双债LOF N日不创新高/新低择时策略回测》落地为正式交易体系。回测结论：N=2 最优（择时总收益 168.3%、夏普 6.06、回撤 -0.68%），四规则闭环（买/卖/止损/追回）全面提升绩效。

### 体系设计

| 项 | 值 |
|:---|:---|
| system-id | `zslof_timing_trade` |

### 四规则

| # | 规则 | 触发 |
|:---|:---|:---|
| 1 | 买 | 空仓中连续 N 天收盘不创新低 → 次日买 |
| 2 | 卖 | 持有中连续 N 天收盘不创新高 → 次日卖 |
| 3 | 止损 | 买入后收盘破「买入前谷值」→ 次日卖 |
| 4 | 追回 | 卖出后收盘破「卖出时峰值」→ 次日买 |

### 边界确认

- 计数语义：连续"不创新高"（c ≤ peak），`c = peak` 不中断计数；仅卖出信号要求 c < peak
- 成交口径：实盘次日开盘成交；回测用信号日收盘近似
- 流动性：161716 日成交约 100-350 万，单笔资金几万以内无碍

## 四、信号协议与责任边界收敛

- 统一约定：`params/*.json`、脚本和过程资料使用英文机器字段与枚举；Jinja 信号报告和交易计划使用中文业务展示。
- 明确 `signal` 记录收盘触发原因：`buy`、`sell`、`stop_loss_sell`、`chase_buy` 或 `null`；`next_trading_action` 记录次日执行动作：`buy`、`sell_all`、`hold` 或 `no_action`。
- 普通卖出与止损卖出的触发原因保持区分，但次日均执行 `sell_all`；`hold` 表示理论持仓继续持有，`no_action` 表示理论空仓且不操作。
- `strategy_state.json` 定义为收盘信号确认后、假设下一交易日计划已执行的理论状态，不代表 YHZQ 的实际持仓或成交。
- 实际成交、成本、手续费和盈亏统一由 `hermes-trade` 的交易管理流程记录和核算，不回写择时体系的理论状态。
- 未修改择时规则和参数，也未调整 `timing_signal.py` 的状态计算；本次只收敛报告展示、协议说明和体系边界。
