# 招商双债LOF择时体系

## 阅读顺序

1. 先读本文，了解体系定位、运行链路和文件索引。
2. 执行体系时读取 `体系运作流程.md`。
3. 需要理解参数、计数和调参边界时读取 `择时参数.md`。
4. 运行时通过 MCP 获取数据和账户事实；`params/`、`scripts/` 和 `templates/` 仅供规则与历史实现查阅。

## 基本信息

- 标的：`161716.SZ` 招商双债增强债券（LOF）
- 类型：机械择时
- 成熟度：执行体系
- 关联账户：`YHZQ`
- 运行方式：收盘确认信号，下一交易日开盘人工执行

本体系维护理论策略状态，不查询实际账户，不自动下单。实际成交、持仓、手续费和盈亏由用户另行管理。

## 核心逻辑

- 空仓时，连续确认不创新低并反弹，生成买入信号。
- 持仓时，连续确认不创新高并回落，生成卖出信号。
- 收盘跌破买入前谷值，生成止损卖出信号。
- 卖出后收盘突破卖出时峰值，生成追回买入信号。

信号优先级和计数语义见 `择时参数.md`，实际参数以 `params/timing.json` 为准。

## 运行链路

```text
收盘行情（tushare-data MCP）
→ 按 择时参数.md 推进理论状态与信号
→ strategy_state.json + signal_facts.json
→ signal_report.md（报告）
→ 下一交易日交易计划
```

JSON 是机器事实和状态来源，Markdown 是可读展示产物。`scripts/` 下脚本为历史实现归档（当前运行不使用），执行细节见 `体系运作流程.md` 第 2 节。

## 过程产物

```text
交易/过程资料/<日期>/招商双债LOF择时体系/
```

- `strategy_state.json`：理论策略状态，供下一次信号计算读取。
- `signal_facts.json`：当日收盘信号和下一交易日动作。
- `signal_report.md`：面向 Agent 和用户的可读报告。

理论策略状态不等于实际账户持仓。交易计划属于下一交易日的执行安排，不代表已经成交。
