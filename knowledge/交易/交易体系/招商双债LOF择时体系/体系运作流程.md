# 招商双债LOF择时体系 · 运作流程

本流程只描述当前运行步骤。体系定位和文件索引见 `体系介绍.md`，参数语义见 `择时参数.md`。

## 运行前

1. 确认目标日期和交易日状态。
2. 读取 `system.yml`、`params/` 和最近一期有效的理论策略状态。
3. 只读取目标日期以前的状态，不使用未来日期或其他体系的产物。
4. 非交易日不计算信号，不生成当日过程产物和交易计划。

## 运行步骤

### 1. 计算收盘信号

运行：

```bash
python knowledge/交易/交易体系/招商双债LOF择时体系/scripts/timing_signal.py \
  --date YYYY-MM-DD
```

脚本负责：

- 读取标的、择时和运行参数；
- 获取目标日期的收盘行情；
- 读取并推进理论策略状态；
- 计算当日信号和下一交易日动作；
- 写入 `strategy_state.json` 和 `signal_facts.json`。

输出目录：

```text
knowledge/交易/过程资料/YYYY-MM-DD/招商双债LOF择时体系/
```

无新信号时，也必须根据理论仓位明确输出 `hold` 或 `no_action`，不能沿用上一交易日动作。

### 2. 渲染信号报告

运行：

```bash
python knowledge/交易/交易体系/招商双债LOF择时体系/scripts/render.py \
  --date YYYY-MM-DD
```

脚本只读取当日 JSON，生成 `signal_report.md`。报告用于阅读和后续计划生成，不是新的事实来源。

### 3. 生成下一交易日计划

读取：

- `signal_facts.json`；
- `strategy_state.json`；
- `signal_report.md`；
- `择时参数.md`。

在 `knowledge/交易/交易计划/<下一交易日>/` 生成唯一计划，至少说明：

- 信号日期和目标交易日期；
- 标的；
- 理论仓位；
- 下一交易日动作；
- 计划金额或全部卖出；
- 信号原因；
- 理论状态不等于实际账户状态；
- 实际执行由用户人工完成。

计划路径示例：

```text
knowledge/交易/交易计划/YYYY-MM-DD/招商双债LOF择时体系.md
```

## 失败处理

- 行情缺失或目标日期不是有效行情日：停止运行并记录错误。
- 理论状态缺失：首次运行使用脚本定义的初始状态；已有运行链路中状态损坏时停止并修复。
- 参数校验失败：停止运行，不生成替代信号。
- JSON 生成成功但报告渲染失败：保留 JSON，记录渲染错误，不伪造报告。
- 不能用旧日期、未来日期或估算价格替代当前缺失数据。

## 边界

- 本流程不查询实际账户，不判断用户是否完成成交。
- 本流程不自动下单，不登记实际成交，不计算实际盈亏。
- 实际执行和账户记录由用户按照交易管理流程完成。
- 完成一次完整运行后，调用 `summary` 技能写入摘要简报。
