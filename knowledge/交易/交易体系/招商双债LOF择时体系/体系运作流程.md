# 招商双债LOF择时体系 · 运作流程

## 定位

本体系当前只运行 `gen_plan`：收盘后计算机械信号，渲染报告，由 Agent 生成下一交易日唯一交易计划。

用户自行完成：

- 阅读交易计划；
- 次日开盘下单；
- 交易记录和账户管理；
- 未按计划执行时的人工状态修正。

体系不查询 `hermes-trade`，不自动执行，也不做独立执行复盘。

## gen_plan 流程

### Step 1：确认交易日

运行入口必须先确认 `{date}` 为有效交易日。非交易日不调用信号计算脚本，不生成过程资料或交易计划。

### Step 2：计算收盘信号

```bash
cd /hermes-trader && /opt/hermes/.venv/bin/python3 \
  knowledge/交易/交易体系/招商双债LOF择时体系/scripts/timing_signal.py \
  --date {date}
```

脚本执行：

1. 读取 `instrument.json`、`timing.json`、`runtime.json`；
2. 从过程资料中读取最近的理论策略状态；
3. 拉取 `161716.SZ` 的 `fund_daily` 行情；
4. 按四条机械规则推进理论状态；
5. 生成当日 `signal_facts.json`；
6. 生成当日 `strategy_state.json`。

输出目录：

```text
交易/过程资料/{date}/招商双债LOF择时体系/
```

当日无新信号时，`signal` 写入 `null`，报告显示“无新信号”；`next_trading_action` 按理论仓位明确为 `hold` 或 `no_action`，不能继承上一交易日动作。

### Step 3：渲染信号报告

```bash
cd /hermes-trader && /opt/hermes/.venv/bin/python3 \
  knowledge/交易/交易体系/招商双债LOF择时体系/scripts/render.py \
  --date {date}
```

使用 `templates/signal_report.md.j2` 生成：

```text
交易/过程资料/{date}/招商双债LOF择时体系/signal_report.md
```

渲染器只读取本地 JSON，不访问 Tushare 或交易数据库。

### Step 4：Agent 生成下一交易日计划

Agent 读取：

- `signal_report.md`；
- `signal_facts.json`；
- `strategy_state.json`；
- `择时参数.md`；
- 当前交易计划规则。

然后根据结构化事实生成计划。`signal` 表示收盘触发原因，`next_trading_action` 表示下一交易日实际动作：

```text
signal:
  buy              # 买入
  sell             # 普通卖出
  stop_loss_sell   # 止损卖出
  chase_buy        # 追回买入
  null             # 无新信号

next_trading_action:
  buy              # 买入
  sell_all         # 全部卖出；普通卖出和止损卖出共用此动作
  hold             # 理论持仓继续持有
  no_action        # 理论空仓且不操作
```

交易计划以中文展示信号原因和执行动作，但不改变上述机器枚举。

计划写入：

```text
交易/交易计划/{next_trade_date}/招商双债LOF择时体系.md
```

计划必须说明：

- 收盘信号日期；
- 理论策略状态；
- 下一交易日动作；
- 计划金额或全仓卖出；
- 收盘信号与次日开盘执行的时间差；
- “实际执行由用户手动完成”。

## 用户手动执行

用户根据交易计划在 YHZQ 执行。实际成交、持仓、成本、手续费和盈亏由 `hermes-trade` 的交易管理流程记录和核算，不影响本体系下一次 `gen_plan` 的信号计算。

若用户未按计划执行，应在下一次生成计划前主动说明，并人工修正理论策略状态；系统不会自动查询账户来判断偏差。

## 调参

调参不是日常 gen_plan 的一部分。以下情况才需要重新验证：

- 季度复核 `confirmation_days`；
- 实际费率变化；
- 跨品种扩展；
- 发现稳定、可复用的策略偏差。

调参顺序：

```text
回测验证 → 修改 params → 更新择时参数文档 → 更新日志
```

## 脚本与模板

```text
scripts/runtime_support.py       # 参数校验与过程路径
scripts/timing_signal.py         # 收盘信号与理论状态
scripts/render.py                # Jinja 严格渲染
templates/signal_report.md.j2    # 信号报告模板
```

本体系暂不配置执行复盘、成交对账、数据库查询适配层或自动下单流程。
