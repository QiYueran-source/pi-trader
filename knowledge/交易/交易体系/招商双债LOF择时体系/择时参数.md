# 招商双债LOF择时体系 · 择时参数

## 参数原则

`params/` 只保存静态参数。JSON 字段名、枚举值和过程资料中的机器值统一使用英文；Jinja 报告和交易计划使用中文展示。行情、当日信号和理论状态统一写入日期化过程资料。

```text
params/
├── instrument.json   # 标的、账户与费率
├── timing.json       # 择时规则与计划金额
└── runtime.json      # 过程路径与状态文件名
```

## `instrument.json`

| 参数 | 当前值 | 说明 |
|---|---|---|
| `instrument.instrument_id` | `zslof` | 体系内部标的 ID |
| `instrument.ts_code` | `161716.SZ` | 招商双债增强债券(LOF) |
| `account.account_id` | `YHZQ` | 计划关联账户，不用于自动查询 |
| `commission.commission_ratio` | `0.00005` | 万 0.5 |
| `commission.minimum_commission_exempt` | `true` | 免最低佣金 |

## `timing.json`

| 参数 | 当前值 | 说明 |
|---|---:|---|
| `confirmation_days` | `2` | 连续不创新高/新低的确认天数 |
| `stop_loss_enabled` | `true` | 跌破买入前谷值时触发卖出信号 |
| `chase_enabled` | `true` | 突破卖出时峰值时触发追回买入信号 |
| `order_amount` | `25000` | 计划中的单次买入金额，单位元（2026-09-12 由 10000 调整，对齐资金池全仓口径） |
| `signal_timing` | `close_confirmed` | 收盘后确认信号 |
| `execution_timing` | `next_open` | 下一交易日开盘人工执行 |

## 信号与动作协议

以下值属于 `signal_facts.json` 的过程资料协议，不是可调参数。机器值使用英文，Jinja 报告和交易计划使用中文展示。

| 字段 | 机器值 | 中文含义 |
|---|---|---|
| `signal` | `buy` | 买入 |
| `signal` | `sell` | 普通卖出 |
| `signal` | `stop_loss_sell` | 止损卖出 |
| `signal` | `chase_buy` | 追回买入 |
| `signal` | `null` | 无新信号 |
| `next_trading_action` | `buy` | 买入 |
| `next_trading_action` | `sell_all` | 全部卖出 |
| `next_trading_action` | `hold` | 理论持仓继续持有 |
| `next_trading_action` | `no_action` | 理论空仓且不操作 |

`signal` 记录触发原因，`next_trading_action` 记录执行动作。普通卖出和止损卖出的执行动作均为 `sell_all`。

## 计数语义

### 持有状态

```text
close > peak  → peak = close，no_high_days = 0
close <= peak → no_high_days += 1
卖出条件      → no_high_days >= confirmation_days 且 close < peak
```

`close == peak` 会增加“不创新高”计数，但不能单独触发卖出。

### 空仓状态

```text
close < trough → trough = close，no_low_days = 0
close >= trough → no_low_days += 1
买入条件       → no_low_days >= confirmation_days 且 close > trough
```

### 优先级

止损信号优先于普通卖出信号；追回买入只在空仓状态下检查。

## 运行参数

`runtime.json` 规定：

- 过程资料根目录为 `交易/过程资料`；
- 日期目录使用 `YYYY-MM-DD`；
- 理论状态文件为 `strategy_state.json`；
- 当日信号文件为 `signal_facts.json`；
- 报告文件为 `signal_report.md`；
- 只读取当前日期之前的理论状态，不读取未来日期。

## 交易计划金额写法

「计划金额」是交易计划文件中唯一的金额展示位，写法统一如下：

- 术语固定为「计划金额」，不使用「买入金额」「每笔金额」「预算」等变体；
- 金额格式为千分位 + 「元」，如 `25,000 元`；份数为千分位 + 「份」，如 `15,000 份`；
- 金额只在计划文档的「动作」节出现一次，取值必须当日从 `params/timing.json` 的 `order_amount` 读取，不得沿用上一日文本；
- 「参数」行只列 N / 止损 / 追回 / 费率，不挂金额；监控条件与风控备注中需要提及时写「按计划金额执行」，不重复数字。

固定写法示例：

```markdown
## 2026-09-14 动作

**无动作** — 理论空仓，继续观察
- 标的：161716.SZ 招商双债增强债券(LOF)
- 计划金额：25,000 元（无动作，本次不适用）
```

触发买入时，「计划金额」行写为 `25,000 元（按次日开盘价折 100 份整数倍）`。

## 调参边界

- `confirmation_days`：季度回测复核；
- 止损与追回：需要新的回测证据后再调整；
- `order_amount`：根据用户资金和流动性人工调整；
- 参数修改必须同步更新更新日志和本文件。

实际交易是否成交、成交价格和账户持仓不属于这些参数，也不写回 `params/`。
