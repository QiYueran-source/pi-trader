# 招商双债LOF择时体系 · 择时参数

实际运行参数以运行定义目录 `.pi/mcp-servers/trade-system/zslof_timing_trade/params/` 下的 JSON 文件为准（下文 `params/` 均指该目录）。本文只解释参数含义和机器协议，不重复运行流程。

## 参数文件

```text
params/instrument.json   # 标的、账户与费率
params/timing.json       # 择时规则与计划金额
params/runtime.json      # 日期、过程目录和文件名
```

参数文件使用英文字段和机器枚举；报告和交易计划将其转换为中文展示。

## 主要参数

| 参数 | 作用 |
|---|---|
| `confirmation_days` | 连续不创新高或不创新低的确认天数 |
| `stop_loss_enabled` | 是否启用跌破买入前谷值的止损 |
| `chase_enabled` | 是否启用卖出后突破卖出时峰值的追回 |
| `order_amount` | 买入计划金额，单位为元 |
| `signal_timing` | 信号确认时点，当前为收盘确认 |
| `execution_timing` | 计划执行时点，当前为下一交易日开盘 |

当前核心值见 `params/timing.json`，不要在文档中复制一份可独立生效的参数。

## 信号与动作协议

`signal_facts.json` 中：

- `signal`：当日收盘触发原因。
  - `buy`：买入
  - `sell`：普通卖出
  - `stop_loss_sell`：止损卖出
  - `chase_buy`：追回买入
  - `null`：无新信号
- `next_trading_action`：下一交易日执行动作。
  - `buy`：买入
  - `sell_all`：全部卖出
  - `hold`：理论持仓继续持有
  - `no_action`：理论空仓且不操作

`signal` 说明为什么触发，`next_trading_action` 说明下一交易日做什么。普通卖出和止损卖出的执行动作都为 `sell_all`。

## 状态计数

### 持仓状态

```text
收盘价 > peak  → 更新 peak，no_high_days = 0
收盘价 <= peak → no_high_days += 1
卖出条件       → no_high_days >= confirmation_days 且收盘价 < peak
```

### 空仓状态

```text
收盘价 < trough → 更新 trough，no_low_days = 0
收盘价 >= trough → no_low_days += 1
买入条件        → no_low_days >= confirmation_days 且收盘价 > trough
```

### 优先级

- 止损卖出优先于普通卖出。
- 追回买入只在理论空仓状态下检查。
- 理论状态由体系 MCP 按本文协议推进（`calculate(operation="signal")`）；需要复核时用 `replay_check` 从 `params/runtime.json#state_anchor_date` 重放比对（只读）。
- 理论状态不等于实际账户持仓：`strategy_state.json` 是理论仓位，实际成交、持仓与盈亏以 `trade-management` 为准。

## 金额与计划

- 计划金额从 `params/timing.json` 的 `order_amount` 读取。
- 交易计划中使用“计划金额”这一术语，不从上一日文档复制金额。
- 买入金额按计划执行，实际成交金额和成交份数以用户实际执行为准。
- 卖出动作使用 `sell_all`，不把理论状态写成实际成交。

## 调参边界

- `confirmation_days`：需要定期回测复核后调整。
- 止损和追回：需要新的回测或运行证据后调整。
- `order_amount`：根据用户资金和流动性人工调整。
- 修改参数后，应同步更新相关说明和 `更新日志/`。
- 实际成交、持仓、手续费和盈亏不写入 `params/`。
