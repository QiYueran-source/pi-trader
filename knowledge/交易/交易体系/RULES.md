# 交易体系规则

## 定位

交易体系是静态、可版本化的决策能力包：定义规则、参数、计算脚本和展示模板。每日运行结果不存放在体系目录，而是写入 `交易/过程资料/`。

## 必备文件

每个体系目录必须包含：

```text
<体系名称>/
├── system.yml
└── 体系介绍.md
```

- `system.yml`：体系标识、账户、成熟度、静态目录说明和稳定过程产物契约。
- `体系介绍.md`：体系目标、模块关系、运行入口和文件说明。

体系目录下的 Markdown 文档应在 frontmatter 中包含所属 `system-id`。

## 标准体系示例

以下是推荐骨架，不是强制目录清单。体系只保留实际需要的模块：

```text
<体系名称>/
├── system.yml
├── 体系介绍.md
├── 体系运作流程.md          # 可选：有定时或多阶段运行时使用
├── params/                  # 可选：可审阅的业务参数
├── scripts/                 # 可选：计算、状态或渲染入口
├── templates/               # 可选：Jinja 等展示层模板
├── references/              # 可选：跨日期仍有效的模板、方法和证据
└── 更新日志/                 # 可选：按日期记录体系演进
```

不同体系不必包含选股、建仓、风控、板块热度等全部模块；目录与文件应由实际策略职责决定。

## 目录职责

| 项目 | 职责 |
|---|---|
| `params/` | 业务规则的可配置值；文件名使用英文，字段使用 `snake_case` |
| `scripts/` | 读取参数、计算事实、写入过程资料；不在脚本中硬编码同类业务参数 |
| `templates/` | 结构化数据的展示层，例如 Jinja 模板；不承载交易规则 |
| `references/` | 跨日期仍有效的方法、模板和体系演化证据；不放每日案例或运行结果 |
| `更新日志/` | 记录体系规则、参数、脚本和目录结构的变更，按日期命名 |

体系目录禁止存放按日期生成的 JSON、状态快照、每日分析 Markdown、执行记录和 `output/` 目录；这些内容属于过程资料、计划或复盘。

## system.yml 规范

`system.yml` 至少包含以下字段：

```yaml
uuid: <唯一标识>
system-id: <英文 snake_case，且全库唯一>
system-name: <中文名称>
system-overview: <中文概述>
account-id:
  - MNZH
updated_at: <ISO 8601 时间>
maturity: 观察体系 | 候选体系 | 执行体系
directory: <静态目录说明>
process-output: <稳定过程产物契约，可选>
```

修改体系的静态结构、规则、参数或稳定产物名称后，必须同步更新 `system.yml` 与体系介绍。

## 内容要求

- 规则应说明触发条件、动作、适用边界和依据。
- 核心规则必须链接到对应笔记、事实、回测证据或复盘结论，不得凭空设定。
- 成熟度由复盘结果调整：观察体系可用于模拟验证；候选体系和执行体系才可直接生成正式交易计划。
