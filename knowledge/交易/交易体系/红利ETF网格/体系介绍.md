# 红利+双创网格交易体系

## 定位

本体系以红利 ETF（`515180.SH`）和双创 50 ETF（`159781.SZ`）为固定标的，在震荡环境运行双网格，在趋势环境切换为单标的人工波段持有。

- `normal`：双网格运行；红利网格不对称储蓄，双创网格对称交易。
- `bull`：停止双网格，清空红利，双创进入人工趋势持有模式。
- `bear`：停止双网格，清空双创，红利进入人工趋势持有模式。

本体系为候选体系，绑定 YHZQ 账户。条件单设置和实际成交仍由人工在券商端完成。

## 架构

```mermaid
flowchart LR
    A[静态参数] --> B[脚本采集与计算]
    B --> C[日期化过程资料]
    C --> D[Agent 综合文本与事实]
    D --> E[状态迁移提案]
    E --> F[状态校验与审计]
    F --> G[人工执行指令与交易计划]
```

### 职责边界

| 层级 | 职责 | 不负责 |
|---|---|---|
| `params/` | 标的、公式、阈值、状态迁移约束 | 当日行情、仓位、状态结果 |
| 脚本 | 计算网格、采集风险和板块事实、校验迁移 | 判断科技牛熊、直接下单 |
| Agent | 综合投顾、收评、板块和风险事实，形成唯一状态结论 | 绕过状态迁移约束 |
| 状态迁移脚本 | 校验提案、保存状态和仓位快照 | 重新判断市场 |
| 人工执行 | 在券商端设置条件单和完成交易 | 修改过程事实 |

## 运行产物

体系目录只保存静态能力。所有按日期生成的结果统一写入：

```text
交易/过程资料/{date}/红利ETF网格/
├── calibration_check.json
├── grid_parameters.json
├── risk_facts.json
├── sector_facts.json
├── transition_proposal.json
├── state_before.json
├── state_after.json
└── switch_instruction.json
```

`output/` 中的旧文件仅作为迁移前历史证据保留；新脚本不再读取或写入该目录。

## 状态迁移原则

市场状态由 Agent 判断，而非固定阈值脚本判断。Agent 必须基于当日过程事实和文本研究，写入包含状态、证据摘要、冲突处理与置信度的 `transition_proposal.json`。

`apply_state_transition.py` 只接受合法迁移：

```text
normal → bull / bear
bull → normal
bear → normal
```

若证据关键冲突，默认保持当前状态。状态切换后的订单动作由 `build_switch_instruction.py` 根据已固化迁移和真实仓位快照生成，不使用默认仓位或硬编码价格。

## 核心模块

| 模块 | 输入 | 输出 |
|---|---|---|
| 网格校准 | 静态网格参数、基金日线 | `grid_parameters.json` |
| 风险事实 | 风控参数、行情、实际持仓 | `risk_facts.json` |
| 板块事实 | 行业分类、全市场日线 | `sector_facts.json` |
| 状态迁移 | Agent 提案、前序状态、实际持仓 | `state_before.json`、`state_after.json` |
| 切换指令 | 已固化状态迁移、仓位快照 | `switch_instruction.json` |

## 数据源

- ETF 行情：Tushare `fund_daily`
- 股票行情与行业：Tushare `daily`、`stock_basic`
- 交易日历：Tushare `trade_cal`
- 持仓：YHZQ 实际账户查询结果
