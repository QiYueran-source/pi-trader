# 红利+双创网格体系运作流程

## 定位

本 SOP 定义体系的调参、盘后事实采集、Agent 状态判断和人工执行衔接。脚本只生成可复现事实；状态迁移由 Agent 决定并由脚本校验固化。

所有运行产物写入 `交易/过程资料/{date}/红利ETF网格/`。非交易日不生成行情事实、状态迁移或交易计划。

## 一、周频或按需调参

### 触发检查

每个交易日收盘后可运行调参检查。满足首次运行、本周最后一个交易日或人工强制触发时，才执行参数计算。

```bash
cd /hermes-trader && /opt/hermes/.venv/bin/python3 \
  knowledge/交易/交易体系/红利ETF网格/scripts/should_calibrate.py \
  --date {date}
```

读取当日 `calibration_check.json`：仅当 `should_calibrate = true` 时进入下一步。

### 计算参数

```bash
cd /hermes-trader && /opt/hermes/.venv/bin/python3 \
  knowledge/交易/交易体系/红利ETF网格/scripts/calculate_grid.py \
  --date {date}
```

脚本读取静态参数和最近基金日线，生成 `grid_parameters.json`。它不更新状态机、不修改资金余额、不写交易计划。

### 人工更新条件单

Agent 根据 `grid_parameters.json` 和当前有效状态生成交易计划。人工在 YHZQ 更新条件单：

- `normal`：按双网格参数设置条件单；
- `bull` / `bear`：按状态机对应模式暂停或保留条件单；
- 参数结果仅是计算事实，不自动形成成交。

## 二、每日收盘后：事实采集与状态判断

### Step 1：准备真实持仓事实

从 YHZQ 查询双标的实际持仓，保存为过程输入。最小结构：

```json
{
  "positions": {
    "dividend": {"shares": 0, "market_value_amount": 0},
    "growth": {"shares": 0, "market_value_amount": 0}
  }
}
```

持仓事实必须来自账户查询，不得用估算值或旧状态文件替代。

### Step 2：采集风险与板块事实

```bash
collect_risk_facts.py --date {date} --positions {positions.json}
collect_sector_facts.py --date {date}
```

输出：

```text
risk_facts.json
sector_facts.json
```

风险事实只标记阈值是否命中；板块事实只统计涨停行业和科技占比。两者都不决定状态切换。

### Step 3：Agent 形成状态提案

Agent 依次读取：

1. 最近有效 `state_after.json`；
2. 当日 `risk_facts.json` 与 `sector_facts.json`；
3. 投顾盘前分析、午评、收评等文本资料；
4. [[状态机管理.md|状态机管理]] 的迁移约束。

Agent 输出唯一结论到 `transition_proposal.json`：保持当前状态或迁移至唯一目标状态。提案必须包含证据摘要、冲突处理和置信度，不保存原始思维链。

### Step 4：校验并固化状态

```bash
apply_state_transition.py \
  --date {date} \
  --proposal 交易/过程资料/{date}/红利ETF网格/transition_proposal.json \
  --positions {positions.json}
```

输出 `state_before.json` 与 `state_after.json`。若提案的前置状态不符、迁移非法或字段不完整，脚本必须失败，不得擅自修正。

### Step 5：生成切换执行指令

```bash
build_switch_instruction.py --date {date}
```

仅在状态迁移发生时生成对应清仓或恢复仓位指令。指令不直接下单，价格、时点和成交结果应由交易计划与实际执行记录确认。

### Step 6：渲染过程资料

按需要渲染指定事实：

```bash
render.py --template risk_facts --date {date}
render.py --template sector_facts --date {date}
render.py --template state_transition --date {date}
render.py --template switch_instruction --date {date}
```

## 三、交易计划与执行

每天都应生成交易计划：

- `normal`：说明有效网格参数、条件单模式和下一交易日关注点；
- `bull` / `bear`：说明趋势持有或状态切换指令；
- 无状态迁移、无条件单变更时，也应明确“不操作”的依据。

实际下单由人工在 YHZQ 执行。执行结果进入交易记录与交易复盘，不回写参数或过程事实。

## 四、异常处理

| 情况 | 处理 |
|---|---|
| 非交易日 | 不运行行情与状态脚本 |
| 缺少基金行情 | 如实记录失败，不生成替代价格 |
| 缺少实际持仓 | 不固化状态迁移，不生成切换订单 |
| 证据矛盾 | Agent 提案为 `keep`，保留当前状态 |
| 参数校验失败 | 停止运行，先修复静态参数 |
| 过程资料缺失 | 不用未来日期或旧 `output/` 文件替代 |

## 五、当前迁移边界

旧 `output/` 目录仅保留历史证据。新运行链路只读取静态参数与日期化过程资料；本 SOP 暂不涉及 cronjob 更新。
