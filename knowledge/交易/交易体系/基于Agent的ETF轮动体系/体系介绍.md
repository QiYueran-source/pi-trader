# 基于Agent的ETF轮动体系

## 体系定位

本体系在固定六只 ETF 和货币 ETF 之间进行日频轮动，由 Agent 完成环境评估、候选比较、调仓判断和风控审查，当前使用 MNZH 模拟账户，处于**观察体系**阶段。

核心不是追逐单日最强，而是在证据充分时形成唯一动作，并让计划、执行和复盘保持一致。

## 固定候选池

- `510300.SH`：沪深300ETF
- `588000.SH`：科创50ETF
- `511260.SH`：10年国债ETF
- `518880.SH`：黄金ETF
- `513500.SH`：标普500ETF
- `511990.SH`：货币ETF，作为现金替代

候选池不因短期热点临时扩展，代码与费率口径见 `规则库/ETF池.md`。增减标的需要经过复盘论证并写入更新日志。

## 决策链路

```text
交易日与账户状态
  → 环境评估
  → 候选比较
  → 当前持仓复核
  → 调仓判断
  → 风控审查
  → 交易计划
  → 计划推送
  → 模拟执行
  → 交易复盘
```

详细业务顺序见 [`体系运作流程.md`](体系运作流程.md)，具体执行时间由体系 cronjob 配置决定。

本体系**没有机械计算**：环境与候选事实由 Agent 经 `tushare-data` 获取，账户事实经 `trade-management` 获取，判定按 `规则库/` 执行；体系 MCP 只提供运行契约、参数校验与复盘渲染。

## 相关技能和 MCP

- `trade-system`：体系运行、规则读取和流程衔接；
- `tushare`：市场数据工具路由；`trade-management`：MNZH 模拟账户、成交、持仓、现金与盈亏；
- 体系 MCP `agent-etf-rotation-system`：运行契约、参数校验与复盘渲染（不取数、不判定）；
- `knowledge-management`：路径、Frontmatter 和正文整理；`summary`：完整工作结束后的简报落盘；`cronjob-management`：体系定时任务管理。

## 交易边界

- 体系只生成模拟交易计划与模拟成交，不执行真实交易。
- 过程资料记录事实和判断依据，交易计划记录唯一可执行动作，复盘记录计划与执行偏差。
- 当前持仓默认优先保留，只有显著且有持续证据的替代优势才切换。
- 证据不足、数据缺失或风险失真时，降低动作强度或转入现金。
