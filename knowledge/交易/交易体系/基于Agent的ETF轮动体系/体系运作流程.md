# 基于Agent的ETF轮动体系 · 体系运作流程

## 定位

本文档定义业务顺序。具体时间由 cronjob 配置决定，当前为：18:25 回放执行、18:35 复盘、18:50 生成下一交易日计划，次日 09:15 推送计划简报。

本体系为观察体系，使用 MNZH 模拟账户，不执行真实交易。计划、执行和复盘必须分离。

## 核心原则

1. 先完成上一计划的执行和复盘，再生成下一计划。
2. 正式计划全文是唯一执行依据；推送不能改写动作，执行不能重新判断。
3. 单日只能有一个主动作：继续持有、切换到另一只 ETF 或切换到 `511990.SH`。
4. 当前持仓拥有延续优先权，只有显著且有持续证据的替代优势才允许切换。
5. 数据不足、证据冲突或事件风险高时，降低动作强度或转入现金。
6. 不补造价格、持仓、成交、收益或宏观数据。

## 阶段一：确认交易日与当前状态

### 输入

- `get_trade_calendar` 返回的交易日历；
- MNZH 当前持仓、现金、成交和盈亏；
- 上一交易日计划和复盘。

### 执行

确认当前日期是否为交易日，确认上一计划是否完成执行和复盘，核对当前持仓属于 `agent_etf_rotation_system`。数据由 `trade-management` MCP 和 `tushare-data` MCP 提供。

### 输出

- 当前交易日状态；
- 当前持仓和现金事实；
- 上一轮闭环是否完整。

### 异常处理

非交易日不生成正式计划。上一轮执行或复盘未核清时，停止新计划生成并记录原因。

## 阶段二：环境评估与候选比较

### 输入

- `规则库/ETF池.md`；
- `规则库/评估框架.md`；
- 各 ETF 档案；
- Tushare MCP 的 ETF 日线、A股指数、海外指数和可用宏观数据。

### 执行

先判断增长预期、风险偏好、流动性与利率、通胀与避险、外部扰动五个维度，再在固定六只 ETF 中统一比较：

```text
510300.SH  沪深300ETF
588000.SH  科创50ETF
511260.SH  10年国债ETF
518880.SH  黄金ETF
513500.SH  标普500ETF
511990.SH  货币ETF
```

ETF 日线使用 `get_fund_daily`，ETF 基础资料使用 `get_fund_basic`，A股指数使用 `get_index_daily`，海外指数使用 `get_index_global`，宏观证据使用 `get_cpi`、`get_pmi`、`get_shibor` 和 `get_us_treasury_curve`。

### 输出

将环境判断、候选排序、当前持仓复核和数据来源写入：

```text
knowledge/交易/过程资料/<YYYY-MM-DD>/基于Agent的ETF轮动体系/ETF轮动-选股分析.md
```

### 异常处理

可选宏观数据缺失时记录缺失，不用旧日期数据替代。核心 ETF 日线或交易日数据缺失时，不形成高置信度切换结论。

## 阶段三：调仓判断与风控审查

### 输入

- 阶段二候选排序；
- `规则库/调仓逻辑.md`；
- `规则库/风控逻辑.md`；
- 当前持仓和风险事实。

### 执行

先复核当前持仓是否失效，再判断第一候选是否显著更优，最后由风控决定维持、降级、强制复核或转现金。风控状态只分：正常、审慎、防御。

### 输出

过程资料补充：

- 当前持仓是否仍成立；
- 第一候选与当前持仓的优势级别；
- 风控状态和干预原因；
- 唯一动作候选。

复杂比较和最终理由写入同一日期的过程资料，不把长篇分析复制进交易计划。

## 阶段四：生成下一交易日计划

### 输入

- 正式复盘；
- 阶段二和阶段三过程资料；
- MNZH 当前持仓和现金；
- 规则库结论。

### 执行

生成唯一动作：

1. 继续持有当前 ETF；
2. 切换至另一只固定池 ETF；
3. 切换至 `511990.SH` 货币 ETF。

计划必须包含：当前持仓、市场环境、候选排序、风控状态、动作、目标标的、执行时点、执行价格规则、核心理由、风险和失效条件。

计划写入：

```text
knowledge/交易/交易计划/<下一交易日>/基于Agent的ETF轮动体系_交易计划.md
```

### 异常处理

结论不清时默认继续持有或转现金，不输出二选一。计划缺少动作、目标标的或执行时点时，不进入自动回放。

## 阶段五：计划推送

由全局 09:15 计划通报任务执行。任务只读取当天正式计划，提炼动作、标的、触发条件和执行时间后推送，不重新生成或修改计划。没有计划时明确提示无计划。

## 阶段六：按计划回放执行

由 18:25 replay-execute cronjob 执行。

### 输入

- 当日正式计划；
- MNZH 持仓和现金；
- `get_fund_minutes` 返回的计划时点价格。

### 执行

读取计划执行区块，按指定时点定位 ETF 分钟线收盘价。官方分钟数据失败时可使用 MCP 返回的代理数据，但必须记录 `source` 和 `warnings`。通过交易管理 MCP 登记模拟卖出和买入，不能执行真实交易。

### 输出

记录计划动作与实际动作、成交价格和数量、成交时点、成交前后持仓、现金变化和异常。完成后写入：

```text
knowledge/摘要/.abstract/<日期>_agent-etf-rotation-replay-execute.txt
```

## 阶段七：执行复盘

由 18:35 review cronjob 执行。

### 输入

- 正式计划；
- 回放执行结果；
- 交易管理 MCP 的成交、持仓、现金和盈亏；
- 当日过程资料与市场事实。

### 执行

分别完成：

1. 执行复盘：计划、价格、数量、记账是否一致；
2. 体系复盘：环境判断、候选比较、调仓逻辑和风控是否有效；
3. 进化记录：稳定、可复用的改进建议只记录，不在复盘任务中直接改规则。

复盘写入：

```text
knowledge/交易/交易复盘/<日期>/基于Agent的ETF轮动体系_复盘.md
```

无成交时仍生成复盘，并说明无成交是否符合计划。完成后写入摘要文件。

## 阶段依赖

```text
交易日与账户状态
  -> 环境评估
  -> 候选比较
  -> 调仓判断
  -> 风控审查
  -> 交易计划
  -> 计划推送
  -> 回放执行
  -> 执行复盘
  -> 下一轮计划
```

任何阶段不得使用其他日期或其他体系的产物替代当前缺失输入。历史计划和复盘仅用于回顾，不替代当前正式文件。
