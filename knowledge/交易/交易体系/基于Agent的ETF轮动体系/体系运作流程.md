# 基于Agent的ETF轮动体系 · 体系运作流程

> 本文件是体系流程的唯一事实源。盘后三个任务的执行指引见**第 2 节**；任务 prompt 只写运行契约并指向本节。
> **路径写法**：落盘目的地与文档引用一律用逻辑路径（如 `交易/交易复盘/<YYYY-MM-DD>/基于Agent的ETF轮动体系_复盘.md`），不带 `knowledge/`、`archive/` 前缀；新产物写入物理根 `knowledge/`。只有需要指明物理位置时（归档、历史形态）才写出 `knowledge/` 与 `archive/`。

## 一、运行入口

本体系为观察体系，使用 **MNZH 模拟账户**，只生成模拟计划，不执行真实交易。三个定时任务构成一条链：**18:25 回放执行 → 18:35 复盘 → 18:50 生成下一交易日计划**；次日 09:15 由全局任务只读推送计划。

- 运行定义（唯一）：`.pi/mcp-servers/trade-system/agent_etf_rotation_system/`，含 `mcp_server.py`（入口，只做工具注册与路由）、`functions/`（实现模块）、`params/`（契约参数唯一来源）、`templates/`（模板唯一来源）。下文 `params/`、`templates/` 均指该目录下。
- 体系 MCP：注册名 `agent-etf-rotation-system`；工具、入参与产物口径见 `交易/交易体系/基于Agent的ETF轮动体系/MCP介绍.md`。**本体系没有机械计算**——事实由 Agent 经 `tushare-data`、`trade-management` 获取，判定按规则库执行；服务只提供运行契约、参数校验、交易日判断与复盘渲染。
- 判定口径唯一来源：`规则库/决策协议.md`（判定入口）与 `规则库/评估框架.md`、`规则库/调仓逻辑.md`、`规则库/风控逻辑.md`；候选池与资产定位见 `规则库/ETF池.md` 与 `规则库/ETF档案/`。
- 数据与账户工具入口：`交易/交易体系/基于Agent的ETF轮动体系/MCP介绍.md`。

### 1.1 每日时间轴（交易日）

| 时点 | 事项 | 谁做 |
|:--|:--|:--|
| 18:25 | 回放执行：按当日正式计划登记模拟成交 | 体系任务 |
| 18:35 | 执行复盘 + 体系复盘，渲染正式复盘 | 体系任务 |
| 18:50 | 生成下一交易日唯一模拟计划 | 体系任务 |
| 22:30 | 全局复盘追问：核验成交与持仓、汇总未结 todo | 全局任务 |
| 次日 09:15 | 全局通报：读当日计划并推送 | 全局任务 |

非交易日：三个任务各只回执一行，不生成产物。

### 1.2 核心原则

1. 先完成上一计划的执行与复盘，再生成下一计划。
2. 正式计划全文是唯一执行依据；推送不改写动作，执行不重新判断。
3. 单日只能有一个主动作：继续持有、切换到另一只固定池 ETF、或转 `511990.SH` 货币 ETF。
4. 当前持仓拥有延续优先权；只有显著且有持续证据的替代优势才允许切换。
5. 数据不足、证据冲突或事件风险高时，降低动作强度或转入现金。
6. 不补造价格、持仓、成交、收益或宏观数据。

## 二、盘后任务执行明细（交易日 18:25／18:35／18:50）

### 2.1 共同输入与前置

- 交易日判断：本体系 MCP `agent-etf-rotation-system` 的 `is_trading_day`（本服务自带，数据源 tushare.trade_cal/SSE，不依赖其它 MCP）；非交易日发送一行状态后结束，不生成产物。
- 账户事实：`trade-management.portfolio_snapshot`（账户 MNZH、体系 `agent_etf_rotation_system`）；不得用估算值替代。
- 市场数据：`tushare-data` 的 `get_fund_daily`（ETF 日线）、`get_fund_minutes`（分钟线）、`get_index_daily`（A 股指数）、`get_index_global`（海外指数）、`get_cpi`、`get_pmi`、`get_shibor`、`get_us_treasury_curve`。
- 上一轮闭环：确认上一计划已完成执行与复盘；未核清时停止新计划生成并记录原因。
- 契约参数校验：调用体系 MCP `validate_parameters`；失败时记录错误并停止。

### 2.2 回放执行（18:25）

| # | 步骤 | 数据来源 | 产物 |
|:--|:--|:--|:--|
| 1 | 读取当日正式计划，确认动作、标的、数量、执行时点与价格规则 | 计划 `交易/交易计划/<当天>/基于Agent的ETF轮动体系_交易计划.md`（读 `knowledge/`→`archive/`） | — |
| 2 | 按计划时点取分钟价格 | `tushare-data.get_fund_minutes` | — |
| 3 | 登记模拟成交 | `trade-management.trade_record` | 成交记录（模拟） |
| 4 | 核验执行后现金与持仓 | `trade-management.portfolio_snapshot` | — |
| 5 | 写简报 | — | 简报 `摘要/.abstract/<日期>_agent-etf-rotation-replay-execute.txt`（落 `knowledge/`） |

价格规则：成交价取计划指定时点的分钟线收盘价；官方分钟数据失败时可用 MCP 返回的代理数据，但必须记录 `source` 与 `warnings`，且代理数据仅用于取数。非交易日无动作；计划或必要数据无效时写明链路异常且不执行成交。

### 2.3 复盘（18:35）

| # | 步骤 | 数据来源 | 产物 |
|:--|:--|:--|:--|
| 1 | 读取当日计划、执行事实与账户快照 | 计划 + `trade-management`（成交、持仓、现金、盈亏） | — |
| 2 | 执行复盘：计划／价格／数量／记账是否一致 | 同上 | — |
| 3 | 体系复盘：环境判断、候选比较、调仓逻辑与风控是否有效 | `规则库/` + 当日过程资料与市场事实 | — |
| 4 | 渲染正式复盘 | 体系 MCP `render(artifact="review", date, document=...)` | `交易/交易复盘/<日期>/基于Agent的ETF轮动体系_复盘.md`（落 `knowledge/`） |
| 5 | 写简报 | — | 简报 `摘要/.abstract/<日期>_agent-etf-rotation-review.txt`（落 `knowledge/`） |

- 复盘结构由 `templates/review.md.j2` 固定。`document` 必填字段：`date`、`summary`、`trade_summary`、`exec_review`（计划动作／实际执行／偏差／执行评价）、`holdings`、`market`、`improvements`、`decision_refs`；可选 `signal_check`、`risk_state`。
- 无成交时仍生成复盘，并说明无成交是否符合计划（有市场变化时对照计划中的危险/积极信号逐项核对）。
- **进化记录**：稳定、可复用的改进建议只写进复盘的「体系改进建议」；不在复盘任务中直接改规则库。

### 2.4 生成下一交易日计划（18:50）

| # | 步骤 | 数据来源 | 产物 |
|:--|:--|:--|:--|
| 1 | 取环境与候选事实（ETF 日线、指数、宏观、基础资料） | `tushare-data` | — |
| 2 | 按规则库形成唯一动作（继续持有／切换／转货币 ETF） | `规则库/` | — |
| 3 | 写过程资料（环境判断、候选排序、持仓复核、数据来源） | 上列事实 | `交易/过程资料/<YYYY-MM-DD>/基于Agent的ETF轮动体系/ETF轮动-选股分析.md`（落 `knowledge/`） |
| 4 | 写计划（结构见 2.6） | 上列产物 + 账户快照 | `交易/交易计划/<下一交易日>/基于Agent的ETF轮动体系_交易计划.md`（落 `knowledge/`） |
| 5 | 写简报 | — | 简报 `摘要/.abstract/<日期>_agent-etf-rotation-generate-plan.txt`（落 `knowledge/`） |

**过程资料历史形态**：2026-10-16 及以前的选股分析写在日期目录根层（`交易/过程资料/<日期>/ETF轮动-选股分析.md`），已归档的保持原路径不改；自 2026-10-19 起新产物写入体系子目录 `交易/过程资料/<日期>/基于Agent的ETF轮动体系/`。

### 2.5 判定口径

| 判定 | 依据 |
|:--|:--|
| 环境五维度（增长、风险偏好、流动性与利率、通胀与避险、外部扰动） | `规则库/评估框架.md` |
| 候选比较（趋势、相对强弱、波动与回撤、流动性、环境匹配度、事件风险） | `规则库/评估框架.md` |
| 置信度分档与动作矩阵 | `规则库/决策协议.md` |
| 持仓延续、切换与转现金边界 | `规则库/调仓逻辑.md` |
| 持仓阶段（建仓窗口期／持有观察期）与持有期核验项 | `规则库/调仓逻辑.md` |
| 风险状态（正常／关注／异常）与降级、阻断 | `规则库/风控逻辑.md` |

本节不复制规则内容与任何阈值；规则库是判定口径的唯一事实源。

### 2.6 计划结构

当前持仓、市场环境、候选排序、风控状态、动作、目标标的、执行时点、执行价格规则、核心理由、风险与失效条件。计划缺少动作、目标标的或执行时点时，不得进入自动回放。

### 2.7 汇报要点

首行一行式状态；正文列动作、标的与关键数字，风险一行、异常与待办各一行；不超过 5 行。

### 2.8 异常分支

| 情形 | 处理 |
|:--|:--|
| 非交易日 | 各任务一行状态回执后结束，不生成产物 |
| 数据不足、日期不一致或来源告警未消除 | 状态记为「待复核」，不形成高置信度切换结论、不执行切换 |
| 可选宏观数据缺失 | 记录缺失，不用旧日期数据替代 |
| 上游产物缺失（计划／执行／复盘） | 停止下游步骤并说明缺失阶段；不用其它日期或其它体系的产物替代 |
| MCP 调用失败（含体系 MCP） | 记录失败阶段与错误信息并停止依赖该事实的步骤；不估算、不编造 |

## 三、执行与复盘衔接

- 本体系**无人工审批环节**：Agent 依规则库形成唯一动作，回放任务严格按计划执行，不重新判断或改写计划。
- 成交与持仓由 `trade-management` 登记；计划、执行与复盘使用同一 `system-id`，保持链路可追溯。
- 过程资料记录事实与判断依据，计划记录唯一动作，复盘记录计划与执行的偏差；三者不得互相替代。

## 四、边界

- 只生成模拟计划与模拟成交，不执行真实交易，不查询券商实盘账户。
- 不改 `规则库/`、不改运行定义 `params/` 与 `templates/`、不改历史产物。
- 不在无证据时补写价格、持仓、成交或收益；不用估算仓位替代真实持仓。
- 候选池不因短期热点临时扩展；增减标的须经复盘论证并写更新日志。

## 五、规则与接口入口

- 规则：`规则库/决策协议.md`（入口）、`规则库/评估框架.md`、`规则库/调仓逻辑.md`、`规则库/风控逻辑.md`、`规则库/ETF池.md`、`规则库/ETF档案/`
- 契约与参数：运行定义 `params/runtime.json`、`params/universe.json`（候选池与费率的唯一参数来源）；身份与成熟度见 `交易/交易体系/基于Agent的ETF轮动体系/体系介绍.md`
- 工具与入参：`交易/交易体系/基于Agent的ETF轮动体系/MCP介绍.md`
- 运行定义（唯一）：`.pi/mcp-servers/trade-system/agent_etf_rotation_system/`

## 六、按需链

### 6.1 规则与候选池调整

1. 由复盘论证提出（进化记录），写 `更新日志/`；
2. 更新运行定义 `params/universe.json`（增减标的与费率）与 `规则库/` 对应文档、`交易/交易体系/基于Agent的ETF轮动体系/规则库/ETF池.md`（增减标的须同步 `ETF档案/`），并调 `validate_parameters` 复核；
3. 若接口或工具口径变化，同步 `交易/交易体系/基于Agent的ETF轮动体系/MCP介绍.md`；
4. 检查本文件章节编号与引用它的任务 prompt 是否仍正确。

### 6.2 契约与模板调整

改 `params/runtime.json` 或 `templates/` 后，调 `validate_parameters` 复核；渲染变更用 `render(dry_run=true)` 预览后再落盘。本体系**不设判定阈值参数**（判定口径在规则库）。

## 七、变更链

1. 改规则库、运行定义 `params/`、`templates/` 或 `mcp_server.py`；
2. 校验：`validate_parameters`；模板或契约变更用 `render(dry_run=true)` 预览比对；
3. 写 `更新日志/<YYYY-MM-DD>_<主题>.md`，记动因、变更、验证与遗留；
4. 同步文档：`交易/交易体系/基于Agent的ETF轮动体系/体系介绍.md`、本 SOP、`交易/交易体系/基于Agent的ETF轮动体系/MCP介绍.md`；
5. 若改动本章节结构或编号，检查引用它的任务 prompt；
6. 变更后首个交易日复核实际产物。
