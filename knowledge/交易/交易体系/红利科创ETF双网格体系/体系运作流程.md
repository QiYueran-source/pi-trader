# 红利科创ETF双网格体系运作流程

> 本文件是体系流程的唯一事实源。盘后任务的执行指引见**第 2 节**；任务 prompt 只写运行契约（交易日判断、投递、简报、输出格式、边界）并指向本节。

## 一、运行入口

体系只有**一个定时任务**：`div-etf-grid-trade-1800-daily-check`（交易日 18:00；非交易日只回执一行）。任务通过 MCP 访问数据与账户：`tushare-data`（交易日、行情、情绪）、`trade-management.portfolio_snapshot`（YHZQ 仓位与现金）、体系自身的 `div-etf-grid-trade`（事实计算与渲染）。

- 运行定义（唯一）：`.pi/mcp-servers/trade-system/div_etf_grid_trade/`，含 `mcp_server.py`（实现）、`system.yml`（契约）、`params/`（参数唯一来源）、`templates/`（模板唯一来源）。下文出现的 `params/`、`templates/` 均指该目录下。
- 体系 MCP：注册名 `div-etf-grid-trade`，工具清单、入参与返回口径见 `trade-system` 技能的 `reference/mcp.md`。
- 参数唯一来源：`params/`（常态参数读 `params/regulator.json#normal_state`）。
- 规则唯一来源：`风控.md`（硬闸、信号、防守档与审批）。
- 命令与接口速查：`MCP介绍.md`。
- 过程资料与计划的落盘位置以运行定义的 `system.yml` 为准。

### 1.1 每日时间轴（交易日）

| 时点 | 事项 | 谁做 |
|:--|:--|:--|
| 15:00 | 全局收盘提醒，询问是否有成交需录入 | 全局任务 |
| 15:00 后 | 报当日成交（逐笔如实），会话用 `trade-management` 登记并回执 `trade_as_of` | 用户 → 会话 |
| 18:00 | 盘后任务：风险与参数事实 → 参数版计划 → 飞书汇报 | 体系任务 |
| 22:30 | 全局复盘追问：事实核验 + 汇总各体系未结 todo | 全局任务 |
| 复盘时 | 审批待决策项（防守档 / 解除停买）并写体系复盘 | 用户 + 会话 |
| 次日 09:15 | 全局通报：读当日计划，提醒待决策项 | 全局任务 |
| 次日开盘前 | 按计划在券商软件同步参数；空仓且当周第一个交易日时重设基准价 | 用户 |
| 次日盘中 | 券商条件单自动执行，体系不产生盘中动作 | 券商软件 |

非交易日：18:00 任务与 22:30 追问只回执，09:15 通报只报非交易日。

## 二、盘后任务执行明细（交易日 18:00）

### 2.1 输入与前置

- 交易日判断：`tushare-data.get_trade_calendar`；非交易日发送一行状态后结束，不生成产物。
- 参数：`params/regulator.json`（常态参数、硬闸、防守档、信号阈值、审批字段）、`params/risk.json`（风险阈值、价格边界）。
- 账户事实：`trade-management.portfolio_snapshot` 取 YHZQ 现金与双标的持仓；不得用估算仓位或旧状态替代。账本时效以 `trade_as_of` 为准。
- 审批留痕：读取最近一次 `human_review.json` 的防守档档位（默认 `A0`＝不切换）。

### 2.2 步骤与产物

写入目录：`交易/过程资料/<YYYY-MM-DD>/红利科创ETF双网格体系/`。

| # | 步骤 | 数据来源 | 产物 |
|:--|:--|:--|:--|
| 1 | 取当日行情（双标的）与账户快照 | `tushare-data` / `trade-management` | `positions.json` |
| 2 | 采集风险事实：收盘价、涨跌幅、量比、平均振幅、连续下跌与累计跌幅、参考价与上下边界、实际持仓与体系口径总资产、各腿权重、阈值命中 | `div-etf-grid-trade.calculate(operation="risk_facts", date="{date}", positions={positions.json 内容})` | `risk_facts.json` |
| 3 | 采集板块事实：涨停行业分布等情绪输入 | `div-etf-grid-trade.calculate(operation="sector_facts", date="{date}")` | `sector_facts.json` |
| 4 | 计算参数事实：体系口径总资产、资金使用率、各腿权重、硬闸占用与停买、单腿是否触顶、实际档距、卖出侧档距与份数、信号评估（一阶冲击 / 二阶确认 / 纯阴跌 / 情绪量化与文本）、建议防守档、审批状态 | `div-etf-grid-trade.calculate(operation="regulator_facts", date="{date}", positions={positions.json 内容}[, human_review={human_review.json 内容}])` | `regulator_facts.json` |
| 5 | 空仓（双标的合计持仓为 0）且当日为当周第一个交易日时给出基准价重设事实：建议锚＝当日收盘价（逐腿）、应挂参数、当前防守档、档距上限；其余情况不重设 | 同步骤 4 | `calibration_check.json` |
| 6 | 生成下一交易日**参数版计划**（结构见 2.4） | 上列产物 + `params/regulator.json` | `交易/交易计划/<下一交易日>/红利科创ETF双网格体系_交易计划.md` |
| 7 | 渲染过程资料（可选，便于阅读） | `div-etf-grid-trade.render(artifact="{risk_facts\|sector_facts\|regulator_facts}", date="{date}", document={对应 JSON 内容})` | 同名 `.md` |
| 8 | 飞书汇报（要点见 2.5） | — | 简报 `knowledge/摘要/.abstract/<YYYY-MM-DD>_div-etf-grid-trade-daily-check.txt` |

步骤 2–4 一律通过体系 MCP 计算；脚本实现已在 v4 收尾时退役（原有能力均由 MCP 同等实现，且 MCP 的情绪涨跌停为分板口径）。调用前先用 `validate_parameters` 校验参数；MCP 调用失败时记录失败阶段和错误信息，不自行估算或改用历史产物。

### 2.3 判定口径

| 判定 | 依据 |
|:--|:--|
| 硬闸（资金使用率分档、停买、单腿上限） | `风控.md`「资金与集中度硬闸」，阈值读 `params/regulator.json#capital_guard` |
| 实际档距 | `min(常态档距 × 防守倍数 × 资金倍数, 档距上限)`，常态值读 `params/regulator.json#normal_state` |
| 信号与情绪 | `风控.md`「信号层」 |
| 建议防守档 | `风控.md`「防守档与审批」的 A0–A3 映射 |
| 价格边界 | `params/risk.json#price_boundary.by_instrument`（不用当日收盘价作自身基准） |
| 人工重设基准价 | `网格参数.md`「基准价重设」，触发口径见本文 6.1 |

本节不复制阈值与数值；一律以 `params/` 为准。

### 2.4 计划文档三段结构

1. **机械参数**：买入/卖出档距、买入/卖出份数、买腿与卖腿开关（含停买状态与原因）、当前防守档、硬闸占用、档距上限；不输出逐档价格（档位价由券商软件计算）。
2. **待决策的调整部分**：出现下列情形时写出，每条按 `todo` 格式落盘 `- [ ] T-YYYY-MM-DD-N ｜ 用户 ｜ 触发 ｜ 来源`（owner＝用户，来源＝本计划逻辑路径）：
   - 防守档调整（建议档 ≠ 当前档）；
   - **解除停买**（机械层 `resume_ready` 成立且当前处于停买）；
   - 其他需要人工裁定的参数调整建议。
   未审批前，机械参数段保持当前生效值（**不自动恢复买腿、不自动切换防守档**）；未决项次日以「承接 `T-…`」引用，直到审批或被否决；被否决也要回填决定。
3. **人工执行提示**：券商端需同步的动作（空仓时重设基准价、参数核对）。

### 2.5 汇报要点

首行一行式状态；正文列硬闸占用、信号与建议防守档、待决策项、待人工核对项；**若账本 `trade_as_of` 早于当日收盘，注明「账本可能未含当日成交」**；不超过 5 行，异常与待办各占一行。

### 2.6 异常分支

| 情形 | 处理 |
|:--|:--|
| 非交易日 | 一行状态回执后结束，不生成产物 |
| 空仓且当周第一个交易日 | 正常执行并额外产出基准价重设事实（步骤 5） |
| 账本未含当日成交（`trade_as_of` 早于当日收盘） | 正常执行，在汇报与计划中标注；硬闸读数以账本为准，不推断未登记成交 |
| 账户快照缺失或无效 | 记录链路异常，停止计划生成；不使用估算仓位 |
| 行情或 MCP 调用失败 | 记录失败阶段与错误信息，停止依赖该事实的下游步骤；不使用估算或历史产物代顶 |
| 有信号但未审批 | 计划只写建议与待决策项，参数维持当前档，不切换 |
| 已可解除停买但未确认 | 计划维持停买并出待决策项，不自动恢复买腿 |

## 三、人工审批与复盘（同日盘后）

1. 用户在**复盘时**审核待决策项（22:30 复盘追问 / 会话）；09:15 全局通报只提醒待决策项，不在此审批。
2. 防守档决定写入 `human_review.json`（字段见 `params/regulator.json#approval`）；该文件只承载防守档档位，其 `level` 字段由体系 MCP 读取，不得混入其他内容。**解除停买的确认不留痕于此**：改为回填计划中对应 todo 并在复盘记录决定。
3. 体系复盘写入 `交易/交易复盘/<YYYY-MM-DD>/红利科创ETF双网格体系_复盘.md`，由会话在审核时写，固定包含：当日事实与账本时效、待决策项的决定与依据、**券商侧参数是否已同步**、待办。22:30 全局任务只核事实与提问，不写复盘结论。
4. 审批通过后由会话按审批结果更新计划参数，**次日开盘生效**；09:15 之后审批的顺延到下一交易日。
5. 用户在券商软件按计划改参数；参数变更不需要重设基准价。

## 四、边界

- 过程资料记录事实与参数；正式计划只记录下一交易日参数、待决策项与人工执行提示。
- 真实持仓是唯一仓位事实，不使用估算仓位或旧状态替代。
- 定时任务不切换防守档、不解除停买、不修改静态规则与参数；审批记录与复盘结论由会话写入。
- **不产出状态迁移、状态快照与切换指令**（状态机自 v4 退役）；不生成清仓/减仓/止损动作。

## 五、当前规则入口

- 网格与参数：`网格参数.md`、`params/regulator.json`
- 风控与调节：`风控.md`
- 输出契约：运行定义的 `system.yml`

## 六、按需链

### 6.1 空仓重设基准价

- 触发：双标的合计持仓为 0（空仓），且当日为**当周第一个交易日**。
- 动作：18:00 任务产出 `calibration_check.json`（建议锚＝当日收盘价，逐腿；应挂参数、当前防守档、档距上限），并在计划的人工执行提示中列出。
- 执行：由用户在券商软件重设，时点自行决定；**系统不校验重设结果，也不做额外验证**。
- 有持仓时不重设（锚由券商软件随成交递推）。

### 6.2 信号与防守档

- 触发：一阶冲击 / 二阶确认 / 纯阴跌 / 情绪（判据见 `风控.md`）。
- 动作：机械层给出建议防守档，计划出待决策项，**不自动切换**。
- 执行：复盘时人工审批 → 会话写入 `human_review.json` 并更新计划参数 → 次日开盘生效 → 用户在券商软件改参数。

### 6.3 硬闸停买与解除

- 触发停买：资金使用率 ≥85%（`capital_guard.stop_buy`）或单腿权重 ≥45%（`leg_cap_breach`）→ **机械自动**；计划买腿开关置为停买，用户在券商侧停挂买腿。
- 解除条件：机械层 `resume_ready`（资金使用率 ≤80%）且无单腿触顶。
- 解除动作：**不自动恢复**；任务出「解除停买」待决策项，人工确认后由会话更新计划买腿开关，用户再在券商侧恢复买腿。

## 七、变更链

参数、规则、实现与流程变更按以下顺序执行：

1. 改运行定义的 `params/`（参数）、`mcp_server.py`（实现）或规则文档（`风控.md`、`网格参数.md`）；
2. 调用 `div-etf-grid-trade.validate_parameters` 校验参数；改实现时用同一口径在沙盒（`PI_PROJECT_DIR=/tmp/...`）复算一次，比对事实值不变；
3. 写 `更新日志/<YYYY-MM-DD>_<主题>.md`，记动因、变更、验证与遗留；
4. 同步受影响文档：规则、本 SOP、运行定义 `system.yml` 契约、`MCP介绍.md`；
5. 若改动了本 SOP 的章节结构，检查引用它的任务 prompt 是否仍指向正确章节；
6. 券商侧同步：按新参数在软件调整，并在复盘中记录「已同步」；
7. 变更后首个交易日复核实际产物。
