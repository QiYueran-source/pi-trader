# 红利科创ETF双网格体系 · 运作流程

本文只描述当前运行步骤。体系定位和文件索引见 `体系介绍.md`；公式、风险和状态迁移语义见对应专题文档。

## 运行前

1. 确认当前工作目录和目标日期。
2. 读取 `system.yml`、`params/` 和本文件。
3. 确认目标日期为交易日；非交易日不运行行情和状态脚本。
4. 检查前序状态、参数和必要输入是否存在且日期正确。
5. 过程资料统一写入：

```text
knowledge/交易/过程资料/YYYY-MM-DD/红利科创ETF双网格体系/
```

## 一、参数校准

每个交易日收盘后先检查是否需要校准：

```bash
python knowledge/交易/交易体系/红利科创ETF双网格体系/scripts/should_calibrate.py \
  --date YYYY-MM-DD
```

当日 `calibration_check.json` 的 `should_calibrate` 为 `true` 时，运行：

```bash
python knowledge/交易/交易体系/红利科创ETF双网格体系/scripts/calculate_grid.py \
  --date YYYY-MM-DD
```

输出 `grid_parameters.json`。该脚本只计算网格事实，不修改状态、资金、交易计划或账户。

## 二、事实采集

### 1. 准备真实持仓

运行调用方先从 YHZQ 查询实际持仓，生成当日 `positions.json`。持仓缺失或无法确认时，停止后续状态固化，不使用估算值或旧状态替代。

### 2. 采集风险和板块事实

```bash
python knowledge/交易/交易体系/红利科创ETF双网格体系/scripts/collect_risk_facts.py \
  --date YYYY-MM-DD \
  --positions knowledge/交易/过程资料/YYYY-MM-DD/红利科创ETF双网格体系/positions.json

python knowledge/交易/交易体系/红利科创ETF双网格体系/scripts/collect_sector_facts.py \
  --date YYYY-MM-DD
```

输出：

- `risk_facts.json`：风险阈值是否命中；
- `sector_facts.json`：板块和科技方向事实。

这些脚本只生成事实，不直接判断牛熊、不直接卖出或切换。

## 三、状态提案与校验

Agent 读取：

1. 最近有效的 `state_after.json`；
2. 当日 `risk_facts.json` 和 `sector_facts.json`；
3. 体系需要的财经分析和其他文本事实；
4. `状态机管理.md` 和 `params/state_machine.json`。

Agent 写入唯一的 `transition_proposal.json`。提案只能表达保持当前状态或迁移到一个合法目标状态，并保存证据摘要、冲突处理和置信度，不保存原始思维链。

运行状态校验：

```bash
python knowledge/交易/交易体系/红利科创ETF双网格体系/scripts/apply_state_transition.py \
  --date YYYY-MM-DD \
  --proposal knowledge/交易/过程资料/YYYY-MM-DD/红利科创ETF双网格体系/transition_proposal.json \
  --positions knowledge/交易/过程资料/YYYY-MM-DD/红利科创ETF双网格体系/positions.json
```

脚本校验前序状态、迁移合法性和提案字段，并写入：

- `state_before.json`：迁移前状态和实际持仓快照；
- `state_after.json`：校验后的体系状态。

证据关键冲突、提案无效或输入缺失时，默认保持当前状态或停止相关下游步骤，不擅自修正。

## 四、生成切换指令

只有状态迁移发生时才生成：

```bash
python knowledge/交易/交易体系/红利科创ETF双网格体系/scripts/build_switch_instruction.py \
  --date YYYY-MM-DD
```

输出 `switch_instruction.json`。它是人工执行建议，不代表已经下单或成交，不使用默认仓位或硬编码价格。

## 五、生成交易计划并人工执行

每天都应生成下一交易日计划：

```text
knowledge/交易/交易计划/<下一交易日>/红利科创ETF双网格体系_交易计划.md
```

计划至少说明：

- 当前状态和目标状态；
- 网格参数或切换指令；
- 具体动作、标的和执行条件；
- 风险和失效条件；
- 实际执行由用户在券商端完成。

人工执行后的成交价格、份额、未执行原因和条件单变化进入交易记录与交易复盘，不回写历史过程事实。

## 六、运行后

- 完成一次完整运行后，调用 `summary` 技能写入 `knowledge/摘要/.abstract/` 简报。
- 过程产物和计划应使用 `trade-system` 技能规定的路径与命名。
- 失败时保留已生成的有效事实，并记录失败阶段和错误，不生成替代结果。

## 异常处理

- 非交易日：不运行行情、风险和状态脚本。
- 缺少行情：不生成替代价格或网格参数。
- 缺少真实持仓：不固化状态迁移，不生成切换订单。
- 参数校验失败：停止运行并先修复静态参数。
- 日期或体系不一致：停止下游步骤，不读取其他体系产物。
- 旧过程资料：仅作为历史证据；当前运行不直接将旧目录结果当作新目录产物。
