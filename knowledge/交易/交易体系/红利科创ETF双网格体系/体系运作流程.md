# 红利科创ETF双网格体系运作流程

## 运行入口

体系只有**一个定时任务**：`div-etf-grid-trade-1800-daily-check`（交易日 18:00，非交易日只回执）。任务只通过 MCP 访问数据与账户：`tushare-data` 提供交易日与行情，`trade-management.portfolio_snapshot` 提供 YHZQ 仓位与现金。过程资料与计划的路径以 `system.yml` 为准。

## 盘后顺序（交易日 18:00）

1. 确认交易日；非交易日只发送一行状态，不生成产物。
2. 读取参数、MCP 行情与账户快照，生成持仓与风险事实（双标的）：`positions.json`、`risk_facts.json`、`sector_facts.json`。
3. 按 `风控.md` 计算并写入 `regulator_facts.json`：常态档距/份数、硬闸占用（资金使用率分档、停买/恢复、单腿 45%）、实际档距、信号评估、建议防守档与审批状态。
4. 空仓时另出 `calibration_check.json`（建议基准价＝当日收盘价、应挂参数）；有持仓时不重设基准价。
5. 生成下一交易日**参数版计划**，固定三段：机械参数 / 待决策的调整部分（按 `todo` 格式落条目）/ 人工执行提示。
6. 飞书汇报：硬闸占用、信号与建议防守档、待决策项、待人工核对项。
7. 持仓或关键输入无效时记录链路异常并停止后续步骤。

## 人工审批与复盘（同日盘后）

1. 用户在**复盘时**审核待决策项（22:30 复盘追问 / 会话）；09:15 全局通报只提醒待决策项，不在此审批。
2. 决定写入 `human_review.json`（字段见 `params/regulator.json#approval`），并回填计划中对应 todo 的完成状态与决定。
3. 体系复盘写入 `交易/交易复盘/{date}/红利科创ETF双网格体系_复盘.md`，由会话在审核时写；22:30 全局任务只核事实与提问，不写复盘结论。
4. 审批通过后由会话按审批结果更新计划参数，**次日开盘生效**；09:15 之后审批的顺延到下一交易日。
5. 用户在券商软件按计划改参数；参数变更不需要重设基准价。

## 边界

- 过程资料记录事实与参数；正式计划只记录下一交易日参数、待决策项与人工执行提示。
- 真实持仓是唯一仓位事实，不使用估算仓位或旧状态替代。
- 定时任务不切换防守档、不修改静态规则与参数；审批记录与复盘结论由会话写入。
- **不产出状态迁移、状态快照与切换指令**（状态机自 v4 退役）；不生成清仓/减仓/止损动作。

## 当前规则入口

- 网格与参数：`网格参数.md`、`params/regulator.json`
- 风控与调节：`风控.md`
- 输出契约：`system.yml`
