# 红利科创ETF双网格体系运作流程

> 本文件是体系流程的唯一事实源。盘后任务的执行指引见**第 2 节**；任务 prompt 只写运行契约（交易日判断、投递、简报、输出格式、边界）并指向本节。

## 一、运行入口

体系只有**一个定时任务**：`div-etf-grid-trade-1800-daily-check`（交易日 18:00；非交易日只回执一行）。任务通过 MCP 访问数据与账户：`tushare-data`（交易日、行情、情绪）、`trade-management.portfolio_snapshot`（YHZQ 仓位与现金）。

- 参数唯一来源：`params/`（常态参数读 `params/regulator.json#normal_state`）。
- 规则唯一来源：`风控.md`（硬闸、信号、防守档与审批）。
- 脚本命令与依赖口径：`常用代码速查.md`。
- 过程资料与计划的落盘位置以 `system.yml` 为准。

## 二、盘后任务执行明细（交易日 18:00）

### 2.1 输入与前置

- 交易日判断：`tushare-data.get_trade_calendar`；非交易日发送一行状态后结束，不生成产物。
- 参数：`params/regulator.json`（常态参数、硬闸、防守档、信号阈值、审批字段）、`params/risk.json`（风险阈值、价格边界）。
- 账户事实：`trade-management.portfolio_snapshot` 取 YHZQ 现金与双标的持仓；不得用估算仓位或旧状态替代。
- 审批留痕：读取最近一次 `human_review.json`（默认空＝不切换防守档）。

### 2.2 步骤与产物

写入目录：`交易/过程资料/<YYYY-MM-DD>/红利科创ETF双网格体系/`。

| # | 步骤 | 数据来源 | 产物 |
|:--|:--|:--|:--|
| 1 | 取当日行情（双标的）与账户快照 | `tushare-data` / `trade-management` | `positions.json` |
| 2 | 采集风险事实：收盘价、涨跌幅、量比、平均振幅、连续下跌与累计跌幅、参考价与上下边界、实际持仓与体系口径总资产、各腿权重、阈值命中 | `scripts/collect_risk_facts.py --date {date} --positions {positions.json}` 或 MCP 同口径复算 | `risk_facts.json` |
| 3 | 采集板块事实：涨停行业分布等情绪输入 | `scripts/collect_sector_facts.py --date {date}` 或 MCP 同口径复算 | `sector_facts.json` |
| 4 | 计算参数事实：体系口径总资产、资金使用率、各腿权重、硬闸占用与停买/恢复、单腿是否触顶、实际档距、卖出侧档距与份数、信号评估（一阶冲击 / 二阶确认 / 纯阴跌 / 情绪量化与文本）、建议防守档、审批状态 | `scripts/collect_regulator_facts.py --date {date} --positions {positions.json} [--human-review {json}]` 或 MCP 同口径复算 | `regulator_facts.json` |
| 5 | 空仓（双标的合计持仓为 0）时给出基准价重设事实：建议锚＝当日收盘价（逐腿）、应挂参数、当前防守档、档距上限；有持仓时不重设 | 同步骤 4 | `calibration_check.json` |
| 6 | 生成下一交易日**参数版计划**（结构见 2.4） | 上列产物 + `params/regulator.json` | `交易/交易计划/<下一交易日>/红利科创ETF双网格体系_交易计划.md` |
| 7 | 渲染过程资料（可选，便于阅读） | `scripts/render.py --template {risk_facts\|sector_facts\|regulator_facts} --date {date}` | 同名 `.md` |
| 8 | 飞书汇报（要点见 2.5） | — | 简报 `knowledge/摘要/.abstract/<YYYY-MM-DD>_div-etf-grid-trade-daily-check.txt` |

步骤 2–4 的脚本与 MCP 复算必须同口径；脚本不可用时按同一口径用 MCP 复算，并在汇报中注明来源。

### 2.3 判定口径

| 判定 | 依据 |
|:--|:--|
| 硬闸（资金使用率分档、停买/恢复、单腿上限） | `风控.md`「资金与集中度硬闸」，阈值读 `params/regulator.json#capital_guard` |
| 实际档距 | `min(常态档距 × 防守倍数 × 资金倍数, 档距上限)`，常态值读 `params/regulator.json#normal_state` |
| 信号与情绪 | `风控.md`「信号层」 |
| 建议防守档 | `风控.md`「防守档与审批」的 A0–A3 映射 |
| 价格边界 | `params/risk.json#price_boundary.by_instrument`（不用当日收盘价作自身基准） |
| 人工重设基准价 | `网格参数.md`「基准价重设」 |

本节不复制阈值与数值；一律以 `params/` 为准。

### 2.4 计划文档三段结构

1. **机械参数**：买入/卖出档距、买入/卖出份数、买卖开关、当前防守档、硬闸占用、档距上限；不输出逐档价格（档位价由券商软件计算）。
2. **待决策的调整部分**：仅当出现信号或建议档 ≠ 当前档时写出，每条按 `todo` 格式落盘 `- [ ] T-YYYY-MM-DD-N ｜ 用户 ｜ 触发 ｜ 来源`（owner＝用户，来源＝本计划逻辑路径）；未决项次日以「承接 `T-…`」引用，不重复新建。
3. **人工执行提示**：券商端需同步的动作（空仓时重设基准价、参数核对）。

### 2.5 汇报要点

首行一行式状态；正文列硬闸占用、信号与建议防守档、待决策项、待人工核对项；不超过 5 行，异常与待办各占一行。

### 2.6 异常分支

| 情形 | 处理 |
|:--|:--|
| 非交易日 | 一行状态回执后结束，不生成产物 |
| 空仓 | 正常执行并额外产出基准价重设事实（步骤 5） |
| 账户快照缺失或无效 | 记录链路异常，停止计划生成；不使用估算仓位 |
| 行情或脚本失败 | 按同口径用 MCP 复算；两者都不可得时记录链路异常并停止依赖步骤 |
| 有信号但未审批 | 计划只写建议与待决策项，参数维持当前档，不切换 |

## 三、人工审批与复盘（同日盘后）

1. 用户在**复盘时**审核待决策项（22:30 复盘追问 / 会话）；09:15 全局通报只提醒待决策项，不在此审批。
2. 决定写入 `human_review.json`（字段见 `params/regulator.json#approval`），并回填计划中对应 todo 的完成状态与决定。
3. 体系复盘写入 `交易/交易复盘/<YYYY-MM-DD>/红利科创ETF双网格体系_复盘.md`，由会话在审核时写；22:30 全局任务只核事实与提问，不写复盘结论。
4. 审批通过后由会话按审批结果更新计划参数，**次日开盘生效**；09:15 之后审批的顺延到下一交易日。
5. 用户在券商软件按计划改参数；参数变更不需要重设基准价。

## 四、边界

- 过程资料记录事实与参数；正式计划只记录下一交易日参数、待决策项与人工执行提示。
- 真实持仓是唯一仓位事实，不使用估算仓位或旧状态替代。
- 定时任务不切换防守档、不修改静态规则与参数；审批记录与复盘结论由会话写入。
- **不产出状态迁移、状态快照与切换指令**（状态机自 v4 退役）；不生成清仓/减仓/止损动作。

## 五、当前规则入口

- 网格与参数：`网格参数.md`、`params/regulator.json`
- 风控与调节：`风控.md`
- 输出契约：`system.yml`
