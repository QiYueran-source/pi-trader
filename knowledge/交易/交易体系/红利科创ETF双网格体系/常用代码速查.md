# 红利科创ETF双网格体系常用代码速查

## 运行入口

所有脚本显式接收 `--date`，支持 `YYYY-MM-DD` 或 `YYYYMMDD`。过程产物写入：

```text
交易/过程资料/{date}/红利科创ETF双网格体系/
```

```bash
cd /pi-trader
PYTHON=/opt/venv/bin/python
BASE=knowledge/交易/交易体系/红利科创ETF双网格体系/scripts
```

| 目的 | 命令 |
|---|---|
| 采集风险事实（双标的） | `$PYTHON $BASE/collect_risk_facts.py --date {date} --positions {positions.json}` |
| 计算调节器事实（硬闸/档距/信号/建议档） | `$PYTHON $BASE/collect_regulator_facts.py --date {date} --positions {positions.json} [--human-review {json}] [--skip-emotion]` |
| 采集板块事实 | `$PYTHON $BASE/collect_sector_facts.py --date {date}` |
| 渲染过程资料 | `$PYTHON $BASE/render.py --template {risk_facts\|sector_facts\|regulator_facts} --date {date}` |

说明：

- 脚本**不复制密钥**：Tushare token 与项目 MCP 服务共用 `.pi/mcp-servers/tushare/.env`（由 `runtime_support.tushare_client()` 读取）。
- 依赖口径：脚本依赖统一由 `/opt/venv` 提供（含渲染所需的 `jinja2 3.1.6`），必须用 `/opt/venv/bin/python` 运行；脚本内不再做用户级 `sys.path` 引导。
- `/opt/venv` 属 root 且不在挂载点上（随容器可写层）：容器重建后若渲染报 `ModuleNotFoundError: jinja2`，由 root 执行一条命令补回：`UV_CACHE_DIR=/tmp/uvcache uv pip install --python /opt/venv/bin/python jinja2`。
- 已退役（v4）：`should_calibrate.py`、`calculate_grid.py`（回撤步长）、`apply_state_transition.py`、`build_switch_instruction.py`（状态机）。
- 参数校验：`runtime_support.load_parameters()` 会按 v4 结构校验 `params/` 下 6 个参数文件。

## Tushare 接口

### 交易日历

```python
pro.trade_cal(
    exchange="SSE",
    start_date="20260810",
    end_date="20260811",
    fields="cal_date,is_open",
)
```

### ETF 日线

```python
pro.fund_daily(
    ts_code="515180.SH",
    start_date="20260601",
    end_date="20260810",
    fields="trade_date,close,high,low,vol,amount",
)
```

返回默认可能倒序，计算前必须按 `trade_date` 升序排序。

### 全市场行业事实

```python
pro.daily(trade_date="20260810", fields="ts_code,pct_chg")
pro.stock_basic(exchange="", list_status="L", fields="ts_code,name,industry")
```

## 状态提案输入

Agent 写入的 `transition_proposal.json` 至少包含：

```json
{
  "date": "YYYY-MM-DD",
  "system_id": "div_etf_grid_trade",
  "from_state": "normal",
  "to_state": "normal",
  "decision": "keep",
  "confidence": "medium",
  "evidence_summary": ["过程资料与文本研究的结论摘要"],
  "conflict_resolution": "存在冲突，保持状态",
  "decided_by": "agent"
}
```

持仓输入至少包含：

```json
{
  "positions": {
    "dividend": {"shares": 0, "market_value_amount": 0},
    "growth": {"shares": 0, "market_value_amount": 0}
  }
}
```

状态与切换脚本不直接访问券商账户；调用端必须先生成真实持仓事实。
