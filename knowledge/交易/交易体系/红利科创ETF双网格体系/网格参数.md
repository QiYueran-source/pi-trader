# 红利科创ETF双网格体系参数

## 定位

本文件说明参数职责、锚与档位价格的维护方、无持仓时重设基准价的流程和人工条件单边界。参数唯一来源是运行定义目录 `.pi/mcp-servers/trade-system/div_etf_grid_trade/params/`（下文中的 `params/` 均指该目录），正文不复制可独立生效的数值；当日计算结果不写回参数文件。

**v4 要点**：档距与份数为固定配置（读 `params/regulator.json` 的 `normal_state`），**系统不算档位价格**，档位与锚由券商软件维护。

## 参数职责

| 文件 | 内容 |
|---|---|
| `instruments.json` | 双标的身份、账户、费率和最小交易单位 |
| `regulator.json` | **常态参数（档距/份数/开关）、资金与集中度硬闸、防守档、信号阈值、审批字段** |
| `grid.json` | 资金池、确认比例、档位维护方与锚重设口径 |
| `risk.json` | 风险事实采集阈值（双标的）、价格边界 |
| `runtime.json` | 过程资料路径与日期规则 |
| ~~`state_machine.json`~~ | v4 已删除（状态机退役） |

## 术语与参数键名对照

本文只写含义，数值一律从 `params/` 读（`regulator.json` 为唯一数值来源）。

| 术语 | 参数键名 / 位置 | 含义 |
|:--|:--|:--|
| 常态档距 | `regulator.normal_state.<腿>.buy_step_ratio` / `sell_step_ratio` | 相邻档之间的价格间距（基线值） |
| 常态份数 | `regulator.normal_state.<腿>.buy_shares` / `sell_shares` | 每笔申报份数（100 的整数倍） |
| 防守档 | `regulator.defense_levels.<A0–A3>`；生效档来自 `human_review.level`（体系级）+ `human_review.per_leg`（按腿覆盖） | 档位名称本身不存参数；未写出的腿沿用体系档 |
| 防守倍数 | `regulator.defense_levels.<档>.step_multiplier` | 防守档的档距倍数，**买卖两侧同乘** |
| 防守份数倍数 | `regulator.defense_levels.<档>.shares_multiplier` | 防守档的单笔份数倍数，**买卖两侧同乘** |
| 资金分档 | `regulator.capital_guard.tiers[].u` | 按资金使用率落入的档位 |
| 资金倍数 | `regulator.capital_guard.tiers[].step_multiplier` | 该分档的倍数，**只乘买入档距** |
| 买入上限 | `regulator.capital_guard.step_cap.<腿>` | 买入档距天花板；卖出档距**不设上限** |
| 资金使用率 | 产物 `capital_guard.usage_ratio` | 持仓市值 ÷ 体系口径总资产 |
| 单腿上限 | `regulator.capital_guard.leg_max_weight` | 单腿权重天花板，触达即停该腿买入 |
| 停买 / 解除停买 | `stop_buy_u` / `resume_u` | 触线自动停买；解除需人工确认 |
| 保底仓 | `regulator.reserve_shares` | 每腿持仓下限，触达即停卖该腿，回到下限之上自动恢复 |
| 档位 / 档位价格 | 不在系统内（`execute.ladder_owner=broker_software`） | 具体价格点 / 该点价格 |
| 锚（基准价） | `execute.anchor_owner=broker_software` | 档位价格序列的基准价 |
| 腿 | `instruments.instruments.<腿>` | `dividend`（红利）、`growth`（双创） |

## 档距与份数

```text
买入档距 = min(常态买入档距 × 防守倍数 × 资金倍数, 买入上限)
卖出档距 = 常态卖出档距 × 防守倍数              ← 不吃资金倍数，不设上限
买入份数 = floor100(常态买入份数 × 防守份数倍数)
卖出份数 = floor100(常态卖出份数 × 防守份数倍数)
```

- 每个量吃哪些倍数由 `regulator.json#scaling` 声明（`defense` / `capital`），改口径先改声明再改实现。
- 档距与份数为固定配置值，可随时按情况调整；调整属静态配置变更，须先更新参数并写 `更新日志/`。
- 档距不再由回撤公式计算（`drawdown_coefficient`、`minimum_step_ratio`、`step_formula` 自 v4 退役），也不使用波动率自适应。
- 红利用「买密卖疏 + 买多卖少」表达储蓄属性；双创买卖基准对称、允许 T。
- 份数取整：申报必须是 **100 份的整数倍**，缩放后向下取整、最小 100 份；常态份数本身也必须是 100 的正整数倍（由 `validate_parameters` 拦）。
- 所有 `*_ratio` 都使用 0 到 1 的小数表示；展示层转换为百分比，计算与参数文件不使用百分数整数。

## 锚与档位价格的维护（v4）

- **档位价格由券商软件计算**，系统只出参数（档距/份数/开关/防守档），不出档位价。
- **锚（基准价）由券商软件维护**；**空仓状态下每周第一个交易日重设**（18:00 任务出建议锚＝当日收盘价，人工在券商软件重设，时点自定；系统不校验重设结果）。
- **参数变更（含防守档切换）不需要重设基准价** —— 防守档切换是无缝的。
- 一次只预挂一档，后续档位由软件递推。
- 原「人工临时覆盖 `manual_overrides`」已合并为正式配置（见 `params/regulator.json`），该块自 v4 删除。

## 确认比例（2026-10-12 起置 0）

- `grid.json#confirmation` 的买入确认反弹比例与卖出确认回落比例**均为 0**：确认价 = 触档价，价格触及档位即成交，条件单直接按档位价设置。
- 取值依据、重新启用条件与评估记录见 `笔记/实证分析/网格确认阈值冗余性验证.md`。
- 触档即成交会在单边下跌或跳空时一天内连续吃多档，人工执行前须核对资金使用率分档与停买、单腿权重上限、档距上限（见 `交易/交易体系/红利科创ETF双网格体系/风控.md`）。

## 基准价重设（v4 取代原周度校准）

```text
交易日盘后（18:00 任务）：
  ① 空仓且当日为当周第一个交易日 → 出「需重设基准价」事实（建议锚＝当日收盘价，逐腿）+ 应挂参数清单
  ② 用户在券商软件重设，时点自定；系统不校验重设结果，也不做额外校验
```

- v4 不再计算档距：档距固定读配置；回撤公式相关的 `should_calibrate.py` / `calculate_grid.py` 已随批 3 删除。
- 有持仓时不重设基准价（锚由券商软件随成交递推）。

## 人工执行边界

- 双腿常态均启用买卖；停买由资金分档与单腿上限触发（阈值见 `params/regulator.json#capital_guard`），**解除停买需人工确认**；卖腿停卖由保底仓触发（`reserve_shares`），回到下限之上自动恢复。
- 档距、份数、开关、防守档参数变更均属静态配置变更，应先更新参数并写 `更新日志/`。
- 防守档切换需人工审批（见 `交易/交易体系/红利科创ETF双网格体系/风控.md`）。
- 网格参数是配置事实，不是自动成交指令。
