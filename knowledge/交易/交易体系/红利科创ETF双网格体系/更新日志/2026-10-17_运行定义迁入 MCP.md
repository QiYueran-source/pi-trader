# 运行定义迁入体系 MCP，知识库目录只留文档 | 2026-10-17

## 一、动因

体系运行需要同时维护两套定义：知识库内的 `params/`、`templates/`、`scripts/`，和 MCP 目录内的同名副本。两处参数已经出现注释与 `schema_version` 漂移，脚本的情绪涨跌停也仍是非分板口径（10-16 得 74/26，MCP 为 65/15）。用户 2026-10-17 裁定收口为单一运行定义。

## 二、口径决定（用户 2026-10-17）

| 项 | 决定 |
|:--|:--|
| 运行定义位置 | `.pi/mcp-servers/trade-system/<system-id>/`，参数、模板、实现、契约都在其中 |
| 知识库体系目录 | 只留文档（体系介绍、运作流程、规则、`references/`、`更新日志/`） |
| 服务组织 | 一个体系一个 MCP 服务；注册键＝`system-id` 的连字符形式（`div-etf-grid-trade`），目录名＝`system-id` |
| 体系脚本 | 删除，能力由 MCP 同等实现 |
| 技能 | MCP 与定时任务各自独立为 reference |

## 三、变更

**运行定义（`.pi/mcp-servers/trade-system/div_etf_grid_trade/`）**

- 实现从上级 `trade-system/mcp_server.py` 移入体系目录并自包含：`SYSTEM_ROOT` 取本目录、`SYSTEM_ID` 取目录名、`REPO_ROOT` 回退深度改为 `parents[4]`，入口校验 `system.yml` 存在；删除 17 行 `runpy` 跳板与空 `functions/`。
- `get_manifest` 增补 `system_root`/`parameter_root`/`template_root`；`system.yml` 增补 `service`（注册名与入口）与 `templates`。
- 参数以知识库版覆盖（含 v4 注释；`risk.json` `schema_version` 1 → 3，产物 `parameter_schema_version` 回到 3）；`normal_state` 内的注释键改为按 `instruments` 取腿，校验器忽略注释键。
- 模板：`risk_facts`、`regulator_facts` 取知识库版（含「基数＝system_nav」「停买（≥85%）」「单腿上限（45%）」「条件审批行」）；`sector_facts` 取 MCP 版（Frontmatter 合规）。

**知识库**

- 删除 `params/`、`templates/`、`scripts/`、`system.yml` 与 `__pycache__/`。
- `体系介绍.md`、`体系运作流程.md`、`网格参数.md`、`风控.md`、`references/输出说明.md`、`常用代码速查.md` 同步为运行定义与 MCP 口径；`常用代码速查.md` 改为运行接口速查（工具、入参、依赖、退役清单）。
- `交易计划/2026-10-19/红利科创ETF双网格体系_交易计划.md` 参数指针改为运行定义路径。

**任务与技能**

- 18:00 任务 prompt 改为「体系 MCP `div-etf-grid-trade`」，与实时注册逐字一致并重注册；`cronjob.yml` 描述对齐注册记录。
