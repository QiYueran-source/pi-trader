# 参数更新 | 2026-10-12

> 调参路径：**用户指示**（静态规则变更，非行情驱动的周度校准）。
> 本次只改确认比例，步长、份额、窗口、系数、资金池全部不变。

## 新参数

| 标的 | 参数 | 旧值 | 新值 |
|:---|:---|---:|---:|
| 红利ETF 515180 | `buy_confirmation_rebound_ratio` | 0.2 | **0** |
| | `sell_confirmation_pullback_ratio` | 0.2 | **0** |
| 双创50ETF 159781 | `buy_confirmation_rebound_ratio` | 0.2 | **0** |
| | `sell_confirmation_pullback_ratio` | 0.2 | **0** |
| 两者 | 步长 / 份额 / 窗口 / 回撤系数 / 资金池 | — | 不变 |

生效效果：确认价 = 触档价 × (1 + 0) = 触档价，**价格触及档位即成交**。以 2026-10-09 校准为例，原先需要等待的确认价（双创 +0.50788%、红利 +0.20%）不再要求。

## 变更原因

用户 2026-10-12 指示。事前的实证分析显示该确认在日内尺度上近乎冗余：

1. **触档当日可达确认价的比例**：双创 **96.6%**（243 日中 58 个触档日）、红利 **98.0%**（51 日）。
2. **5 分钟样本（13 日）**：触档并确认后仍跌破触档价的比例（假确认）**90%**；日内 ≥买确认阈值的反向腿日均 7.6 次，而 ≥买步长的仅 0.9 次。
3. **构造性根因**：校准把步长定在约 0.87~0.89×日内中位振幅，0.2 的乘数于是把确认阈值压到日内中位振幅的约 17%，必然落在日内噪声带内——换标的无法解决（红利同为 17.7%）。
4. **代价**：确认只把每笔买入价抬高（双创 +0.508%、红利 +0.20%），并不构成有效过滤。

依据文档：`knowledge/笔记/实证分析/网格确认阈值冗余性验证.md`（含数据口径与局限）。收益影响量级：按当前成交频率（双创约 5 笔/年），取消确认的收益影响在**每年几十元**级别，本次变更的主要价值是**少一个参数、少一层人工计算、条件单可直接按档位价挂单**。

## 风险与配套约束

- **触档即成交**意味着单边下跌或跳空时会一天内连续吃多档（历史样本出现过单日连吃 5 档至收盘）。取消确认后，防线只剩：
  - 单日最大成交档数与单日最大成交金额（人工执行时核对）；
  - 总库存与仓位熔断 `risk.json: position_fuse_ratio = 0.8`；
  - 卖出腿可用份额（159781 与主观多头体系共仓，卖单可能废单）。
- 未同时调整步长／份额；若后续把网格尺度改粗（日间级），应按当时的评估重设确认比例，而不是沿用 0。

## 结构变更

- `params/grid.json`：`grids.dividend.buy_confirmation_rebound_ratio` / `sell_confirmation_pullback_ratio` 0.2 → **0**；`grids.growth` 同。
- `网格参数.md`：新增「确认比例（2026-10-12 起置 0，已停用）」一节，写明现状、重新启用条件与配套约束。
- `params/risk.json`、`params/runtime.json`、`params/instruments.json`、`params/state_machine.json` 未动。
- 脚本未改：`calculate_grid.py` 按 `步长 × 比例` 计算，比例置 0 后确认值自动为 0；`runtime_support.py` 的 `require_ratio(minimum=0.0)` 允许 0，校验通过。

## 回滚方式

把上表四个比例改回 0.2（写入 `params/grid.json`）即可恢复原行为，不需要改脚本或模板；同时撤回本条更新日志的说明或追加一条回滚记录。
