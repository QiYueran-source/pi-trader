# 红利科创ETF双网格体系 · v2 升级方案

- **更新日期：** 2026-07-24
- **更新原因：** 首期运行复盘（40天/+63.6元）总结问题后，综合讨论形成的体系升级
- **升级性质：** 架构级升级（参数策略、风控定位、状态机均为新增/重写）

---

## 一、概述

v2 在 v1（纯机械网格）的基础上，引入**三态状态机**、**动态调参**、**软边界+重校准**、**风控只警告不决策** 四大变化。目标是让网格从「死规则执行器」升级为「有上层判断的智能网格」。

### 动机

| 问题 | v1的不足 | v2的方案 |
|:---|:---|:---|
| 网格区间外哑火 | 硬上下界，过界后无操作 | 软边界 + 过界N天触发重校准 |
| 单边行情应对差 | 涨的时候卖光，跌的时候买满 | 科技牛/熊状态机干预 |
| 风控越权 | 风控自己决定暂停/熔断 | 风控只发警告，AI综合决策 |
| 调参滞后 | 每月固定调参，反应慢 | 每周调参+按需触发 |
| 单笔盈利薄 | 400份/笔，单档赚~±18元 | 1000份/笔，放大到~±50元 |

---

## 二、变更详情

### 2.1 每笔份数调整

| 项目 | v1 | v2 |
|:---|:---:|:---:|
| 每笔份数 | **400 份** | **1,000 份** |
| 每笔金额（~1.4元） | ~560 元 | ~1,400 元 |
| 网格档数 | 3档（高波动）→ 实际用8档 | **5~6档**（随步长动态调整） |
| 资金利用率 | 54% | 85%+ |

**影响：** 单档盈亏从 ±18 元放大到 ±50 元，但总资金 8,000 不变，风险可控。

### 2.2 调参策略重构

#### 频率变更

| 项目 | v1 | v2 |
|:---|:---:|:---:|
| 调参频率 | 每月固定（30个自然日） | **每周五收盘** |
| 触发方式 | 到期自动 | 定期 + 按需触发 |

#### 步长算法变更

```
v1：近22日均振幅 → 分类（低/正常/高）→ 查表得步长
v2：近一个月（22交易日）最大涨幅 × 0.5 → 卖出步长
     近一个月（22交易日）最大回撤 × 0.5 → 买入步长
     最低步长 0.5% → 防极端值
```

#### 基准价策略变更

| 项目 | v1 | v2 |
|:---|:---:|:---:|
| 基准价 | **每次调参重置**为调参日收盘价 | **基本不动**，仅在以下情况重置：过界太远、状态切换 |
| 目的 | 跟随市场 | 保持锚点稳定，减少频繁搬动 |

#### 按需触发条件

除每周五固定调参外，以下情况也触发：

| 触发条件 | 动作 |
|:---|:---|
| 收盘价连续 N 天超出当前网格区间 | 提前重校准（N值待实战确定） |
| 近5日均振幅相比调参日变化超过 X% | 重算步长 |
| 科技牛/熊结束→回到正常网格 | 以当前价附近重启网格 |

### 2.3 三态状态机（新增）

```
🟢 正常网格         🔴 科技牛              🟡 科技熊
  ────────→ 科技牛市信号 ────────→
  ────────→ 科技弱势信号 ────────→
  ←──── 科技牛/熊结束信号 ────
```

| 状态 | 买入 | 卖出 | 网格 |
|:---|:---:|:---:|:---:|
| 🟢 正常 | 网格触发 | 网格触发 | ✅ 运行 |
| 🔴 科技牛 | ❌ 停止 | ⚠️ 清仓 | ❌ 停止 |
| 🟡 科技熊 | ✅ 正常 | ❌ 停止 | ❌ 停止 |

**信号来源：**
- ① 投顾信号（最重要）：AI 读开盘前分析全文判断科技方向
- ② 板块数据（辅助）：`check_hot_sectors.py` 统计科技板块占比

**退出机制：**
- 科技牛 → 确认结束 → 回到正常，重启网格**分批建仓**
- 科技熊 → 确认结束 → 回到正常，重启网格**分批清仓**
- 不追求最低买/最高卖，确认趋势比猜顶底更可靠

### 2.4 风控定位重构

| 项目 | v1 | v2 |
|:---|:---:|:---:|
| 定位 | **自己决策**（暂停/熔断/恢复） | **只警告不决策** |
| 输出 | 直接操作 | 🟡 WARN / 🔴 ALERT |
| 后续 | 自动执行 | AI收到警告后综合判断 |

**风控警告项：**

| 检查项 | 级别 | 触发条件 |
|:---|:---:|:---|
| 持仓达 80% | 🔴 ALERT | 持仓占用 ≥ 总资金 80% |
| 价格过界 N 天 | 🟡 WARN | 收盘连续 N 天超出网格区间 |
| 累计亏损超阈值 | 🔴 ALERT | 当月累计亏损超过 N 元 |
| 波动率突变 | 🟡 WARN | 近5日均振幅变动超过 X% |
| 连续阴跌 | 🟡 WARN | 连续阴跌 N 天 + 亏损超 N% |
| 量价异常 | 🔵 INFO | 异常放量/缩量 |

### 2.5 共享板块数据工具（新增）

`scripts/check_hot_sectors.py`

- 基于 Tushare 数据统计当日热门板块
- 输出科技/非科技分类和占比
- 结果写入 `~hermes-trader/.inbox/hot_sectors_{date}.json`
- 同时供红利网格（状态机判断）和回调低吸（板块分析）使用

### 逐个文件详解

#### params/ 参数文件

**`params/grid.json`** — 🔄 彻底重写

| 改动 | v1 现状 | v2 改为 |
|:---|:---|:---|
| 资金 | `grid_fraction: 12`, `per_trade_amount: 660` | 去掉份数概念，直接 `per_shares: 1000` |
| 步长 | 三档步长表（low/normal/high）+ 波动状态分类 | 去掉。步长改为动态计算，不查表 |
| 价格区间 | `price_lower: 1.267`, `price_upper: 1.397` | 去掉硬边界 |
| 基准价 | `baseline_price: 1.327` | 去掉（基准价基本不动，不放在grid.json里） |
| 计算窗口 | `amp_calc_trading_days: 22` | 保留22天窗口但用途改为：统计月最大涨幅/回撤 |

**`params/risk.json`** — 🔄 部分重写

| 改动 | v1 现状 | v2 改为 |
|:---|:---|:---|
| 资金控制 | `max_position: 6000`, `max_hold_orders: 6`, `pause_buy/sell_on_limit_breach: true` | 去掉 `pause_*` 字段（风控不再自决策），新增 `熔断阈值.持仓熔断水位: 80%`、`熔断阈值.累计亏损熔断: N元` |
| 价格穿透防护 | 25%/30%大阈值 | 保留但降级为INFO级别警告（实际从未触发过） |
| 日频风控 | 检查项结构（consecutive_down_days等） | 结构保留，新增输出字段 `warning_level`（INFO/WARN/ALERT） |

**`params/state.json`** — 🔄 重写

| 新增字段 | 说明 |
|:---|:---|
| `state_machine.current_state` | 当前状态：`normal` / `bull` / `bear` |
| `state_machine.last_signal` | 最近一次状态切换的信号来源 |
| `state_machine.last_transition` | 最近一次状态切换的日期 |
| `last_calc_params` | 最近一次调参的计算摘要（步长、基准价等） |

**`params/base.json`** — 🔄 小改

| 改动 | 说明 |
|:---|:---|
| 去掉 `update_interval.calendar_days: 30` | v2 不再固定周期调参 |

#### scripts/ 脚本文件

**`scripts/grid_calc_params.py`** — 🔄 彻底重写

| 改动 | v1 现状 | v2 改为 |
|:---|:---|:---|
| 算法 | 近22日均振幅→判断市场状态(低/正常/高)→查表得步长 | **近22日最大涨幅×0.5→卖步长**，**近22日最大回撤×0.5→买步长**，最低0.5% |
| 价格区间 | 计算 `price_lower/upper` | 不计算，v2 无硬边界 |

| 落盘 | 写回 `grid.json` + `risk.json` + `state.json` | 只写 `state.json`，不再动 `risk.json`（risk由risk_monitor独立管理） |

**`scripts/grid_check_monthly.py`** — ❌ 废弃

原功能：检查距上次更新是否满30天。

**`scripts/risk_monitor.py`** — 🔄 部分重写

## 五、风险提示

1. **1000份/笔放大单档盈亏**：单档亏损从 -18 元放大到 -50 元，心理感受更明显，但相对 8,000 本金仍很小
2. **科技牛/熊判断依赖投顾质量**：如果投顾判断不准，状态机可能误切换
3. **0.5 系数为首次设置**：可能需要根据实战数据微调
4. **每周调参可能比每月更敏感**：需关注是否导致步长频繁波动
