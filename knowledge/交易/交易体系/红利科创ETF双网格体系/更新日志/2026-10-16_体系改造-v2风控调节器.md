# v2 风控调节器替代状态机 | 2026-10-16

## 一、变更动因

1. **用户定位**：体系是理财型低频持仓，不应存在一次性清仓 9,000 份这类硬动作；2026-10-15 的 `normal → bear` 迁移触发后经人工裁定暂缓（见 `2026-10-16_人工裁定-暂缓bear切换并临时调宽买入步长.md`）。
2. **复盘发现**：网格在单边下跌中没有缓冲 —— 档距过密、逐档吃仓，缺少仓位层面的约束。
3. **用户决定**：**去掉状态机，改用风控策略替代**。

## 二、新机制：风控调节器

| 项 | 内容 |
|:---|:---|
| 调节对象 | **仅买入**（卖出步长、卖出份额、确认比例、资金池不变） |
| 调节变量 | `d = |当前价 / 腿档位锚 − 1|`，锚 = 该腿**最后一次网格成交价**（滚动锚） |
| 分层 | `L0` d<5%（k_step 1.0 / k_size 1.0）、`L1` 5–10%（1.3 / 0.8）、`L2` 10–15%（1.6 / 0.6）、`L3` ≥15%（2.0 / 0.5） |
| 硬约束 | 单腿权重 ≤40%、双腿合计 ≤85%、现金 ≥15%（权重基数＝体系口径总资产 = 双标的市值 + 体系现金），单笔金额 ≤2,000 元 |
| 触发动作 | 硬约束触犯 → 该腿/双腿**停买**；恢复＝权重回落至阈值内（即时，不等滞回） |
| 滞回 | 升降档需连续 **3 个交易日**确认；每腿**每周 ≤1 次**档位变更 |
| 禁止动作 | 清仓、减仓、止损、反 T（ETF 不止损，极端行情只停买） |
| 档位锚 | 统一为滚动锚；校准价只用于价格边界，不再参与档位递推 |

- `params/regulator.json`（分层、硬约束、滞回、policy 的机器可读定义）

**退役（删除）**
- `状态机管理.md`
- `params/state_machine.json`
- `scripts/apply_state_transition.py`、`scripts/build_switch_instruction.py`
- `templates/state_transition.md.j2`、`templates/switch_instruction.md.j2`
- 过程产物 `transition_proposal.json`、`state_before.json`、`state_after.json`、`switch_instruction.json` 不再生成（历史日期目录保留）

**修改**
- `params/risk.json` → v2：采集范围扩至 `dividend` + `growth`；`capital_constraints` 换为三项权重约束（原「单笔比例 25% + 仓位熔断 80%」被取代）；`price_boundary` 改为双标的各自边界（红利 1.08225/1.8759、双创 0.6608/1.2272）
- `网格参数.md`：公式加入 `k_step`/`k_size` 层；人工覆盖语义改为覆盖**基准买入步长**
- `风控.md`：定位改为「事实采集」，调节规则移交 `风控调节器.md`；禁止事项加入清仓/减仓/止损/反T
- `体系介绍.md`、`体系运作流程.md`、`system.yml`、`常用代码速查.md`、`references/输出说明.md`、`scripts/render.py`：同步去状态机表述与产物清单
- 任务 `div-etf-grid-trade-1810-risk-monitor`：prompt 改为「事实 + 调节 + 计划」，明确不得生成清仓/减仓/止损/反T，不再产出状态提案与切换指令
- 任务 `div-etf-grid-trade-1800-param-check`：校准结论需同时列出校准值与人工覆盖值及优先级

## 四、与人工覆盖（`manual_overrides`）的关系

- 人工覆盖的语义变为**覆盖基准买入步长**（红利 2.00%、双创 4.00%），`k_step`/`k_size` 仍在其上叠加。
- 覆盖**保留**，待用户指示恢复校准值；回滚＝删除 `grid.json` 的 `manual_overrides` 块 + 另写更新日志。

## 五、遗留与风险

- **硬约束即时影响**：按 2026-10-15 收盘口径，双创腿市值 7,695 元 / 体系口径总资产 19,295.56 元 = **39.87%**，距单腿 40% 上限仅约 23 元 → **下一根买入档（0.8160）成交后该腿即停买**；红利腿 7.4%，空间充足。若不希望双创这么早停买，需调整 `leg_max_weight`（如 50%）。
- 状态机与 `state_machine.json` 删除后，历史日期目录中的 `state_after.json` 等仅作历史证据，不再参与运行。
- `scripts/runtime_support.py` 仍保留状态机参数校验代码（脚本层历史实现，运行任务不依赖）；后续清理或归档 `scripts/` 时一并处理。
