# 技能与接口口径收口（MCP 为准） | 2026-10-17

## 一、动因

运行定义迁入 MCP 后，技能文本仍有旧口径：把 `params/`、`scripts/`、`templates/` 当作体系目录的常规内容，并保留「脚本为主、MCP 复算兜底」的双入口表述。

## 二、口径（用户 2026-10-17）

- 技能以双网格（已 MCP 化）为准，**不写脚本过渡分支**；其余体系按迁入步骤收口。
- 体系运行定义的唯一位置是 `.pi/mcp-servers/trade-system/<system-id>/`。
- MCP 与定时任务各自独立为 reference，SKILL.md 只留资产分工、使用流程与边界。

## 三、变更

| 文件 | 内容 |
|:--|:--|
| `SKILL.md` | 三类资产分工（运行定义与 MCP／知识库文档／体系定时任务）；使用流程 9 步；边界统一为「计算、参数校验与渲染一律通过 MCP，不执行脚本、不从知识库读参数模板」；指向四个 reference |
| `reference/mcp.md`（新） | 运行定义目录结构、命名规则表（`system-id`→目录名→注册键→工具命名空间→任务目录）、工具与入参、产物与落盘、错误与降级、自检五项、新增体系四步、**存量体系迁入七步** |
| `reference/cronjob.md`（新） | 任务目录与命名、prompt 与 SOP 的分工、依赖写法（写实际服务名，不写脚本命令或双入口）、注册与三项自检、体系无关的边界表述 |
| `reference/trade-system-management.md` | 改为知识库文档 ↔ 运行定义的边界规范：目录只放文档、成熟度、运行定义变更链、任务指针 |

| `cronjob-management` `SKILL.md`、`references/cronjob-design.md` | `system-id` 来源注明运行定义目录与知识库目录两处；异常约定改为「MCP 调用或脚本失败」 |

## 四、验证

- 技能文件均为只读 Markdown，无脚本、数据库内容。
- 全文一致性：技能中不再有「脚本为主」「或按同口径用 MCP 复算」等双入口表述；`references/` 不再列为体系目录标准内容。
- 后续动作：本体系按新口径运行（MCP 唯一入口）；其余体系迁移时照 `reference/mcp.md` 的「存量体系迁入」执行。

## 五、遗留

其余三个体系（zslof、hot-sector、rotation）的参数、模板与实现尚未迁入运行定义；迁移范围含各自 `references/` 的分流（`T-2026-10-17-24`）。
