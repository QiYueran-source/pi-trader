# SOP 补全按需链、变更链与全局接口 | 2026-10-17

## 一、动因

`体系运作流程.md` 此前只覆盖盘后执行明细与审批复盘链，缺按需链、变更链与全局接口。用户 2026-10-17 裁定按新沉淀的 SOP 内容要求补全，并给出五处口径。

## 二、口径决定（用户 2026-10-17）

| 项 | 决定 |
|:--|:--|
| 成交登记 | T 日 15:00（收盘提醒）后报当日成交，**逐笔如实登记**，多笔不合并；会话用 `trade-management` 登记并回执 `trade_as_of` |
| 空仓重设基准价 | 触发＝空仓且当日为**当周第一个交易日**；任务出建议锚（当日收盘价），由用户自定重设时点，**系统不校验、不需额外脚本验证** |
| 硬闸恢复 | **不自动**：机械层只给 `resume_ready` 信号与待决策项，人工确认后由会话更新买腿开关 |
| 未审批项 | 次日以「承接」保留，直到审批或被否决；被否决也回填决定 |
| 月度参数巡检 | 暂不设 |

## 三、变更

**`体系运作流程.md`（SOP）**

- 新增 1.1 每日时间轴（15:00 提醒 → 15:00 后登记成交 → 18:00 盘后任务 → 22:30 追问 → 复盘审批 → 次日 09:15 → 次日开盘券商同步 → 次日盘中）。
- 2.2 步骤 5 的基准价重设触发口径改为「空仓且当周第一个交易日」。
- 2.4 计划三段：机械参数段增加买腿与卖腿开关（含停买状态与原因）；待决策段明确包含**解除停买**、并写明未审批前不自动恢复、承接延续与否决回填。
- 2.5 汇报要点：账本 `trade_as_of` 早于当日收盘时须标注「账本可能未含当日成交」。
- 2.6 异常分支增补两条：账本未含当日成交、已可解除停买但未确认。
- 第 3 节：`human_review.json` 只承载防守档档位（其 `level` 被脚本读取，不得混入其他内容）；解除停买的确认改为回填计划 todo 并在复盘记录；复盘固定包含「券商侧参数是否已同步」。
- 新增第六节按需链（6.1 空仓重设基准价 / 6.2 信号与防守档 / 6.3 硬闸停买与解除）、第七节变更链（7 步，含 SOP 结构变更后检查 prompt 引用）、第八节全局任务接口表。
- 第 1–5 节编号未变，因此任务 prompt 中「第 2 节」的引用仍有效，**prompt 未改动、无需重注册**。

**`风控.md`**

- 硬闸段：停买触发为机械自动（资金使用率 ≥85% 或单腿 ≥45%）；**解除停买需人工确认**，机械层只给 `resume_ready`（资金使用率 ≤80% 且无单腿触顶）与待决策项。
- 防守档段补一句解除停买同样需人工确认。

**`网格参数.md`**

- 锚与基准价重设口径改为「空仓状态下每周第一个交易日重设，人工自定执行时点，系统不校验重设结果、不做额外脚本验证」；人工执行边界补「解除停买需人工确认」。

**`params/grid.json`**

- `calibration.note` 同步新口径。
