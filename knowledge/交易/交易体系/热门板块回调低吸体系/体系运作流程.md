# 热门板块回调低吸体系 · 体系运作流程

## 定位

本文档定义热门板块回调低吸体系的**每日运行SOP**。本体系采用跨日闭环模式——每日盘后模拟执行上一交易日计划、复盘、生成下一交易日计划。

本体系为**观察体系**，所有执行均在 MNZH 模拟账户进行，不以收益为目标，以检验策略逻辑的完整性为目标。

## 闭环总览

```text
T日 18:35 生成 T+1 交易计划
        ↓
T+1日 盘后（约 15:00-18:00）
  Agent 读取选股/建仓/风控脚本输出，形成判断
        ↓
T+1日 18:25 模拟执行 T+1 交易计划
        ↓
T+1日 18:30 复盘当日执行
        ↓
T+1日 18:35 生成 T+2 交易计划
        └──────────────────────→ 循环
```

## 核心原则

### 1. 先执行上一日计划，再生成下一日计划

盘后模拟执行的对象必须是**上一交易日 18:35 生成的那份计划**，不得盘中临时改口。

### 2. 执行驱动，而非收益驱动

模拟执行以**按计划执行为准**，不以收益最大化为目标。价格偏差、条件未触发等均要如实记录，不可强行记账。

### 3. 脚本输出 + Agent 判断

体系依赖四个业务脚本产出机械事实：`select_candidates.py`、`sector_heat.py`、`entry_signal.py` 与 `risk_signal.py`。`render.py` 只将指定日期的过程资料渲染为 Markdown；Agent 负责判断热门行业、仓位分级和交易计划。

### 4. 执行复盘与体系复盘分离

- **执行复盘**：检查是否按计划执行、价格抓取是否正确、持仓与记账是否一致
- **体系复盘**：检查选股/建仓/风控规则是否需要改进、策略表现如何

## 一、每日盘后：Agent 收集决策信息（15:00-18:00）

每日收盘后，Agent 先完成标的筛选和信号分析，这些工作是后续三步的基础。

### Step 0：可选复用同日网格板块环境事实

1. 运行 `prepare_shared_sector_context.py --date {日期}`。
2. 脚本检查 `交易/过程资料/{日期}/红利ETF网格/sector_facts.json` 是否存在，且其 `date`、`system_id`、`artifact` 均有效。
3. 有效时，复制为本体系的 `shared_sector_context.json` 并记录来源；缺失时输出不可用结果，不读取其他日期，也不阻断低吸体系后续流程。

`shared_sector_context.json` 只提供全市场当日行业与科技方向背景；它不替代候选行业的连板、均线和量比专项分析。

### Step 1：候选、板块与行业筛选

1. 运行 `select_candidates.py --date {日期}` 获取全市场候选股
2. 运行 `sector_heat.py --date {日期}` 计算候选行业的专项热度事实
3. 运行 `render.py --date {日期} --template sector_heat` 渲染板块热度 Markdown
4. AI 综合共享环境事实（如有）与候选行业专项事实，判断热门行业，并将理由落盘为板块热度研判
5. 运行 `select_candidates.py --date {日期} --industry "{行业列表}" --output hottest_industry_candidate.json`

### Step 2：建仓技术信号

1. 运行 `entry_signal.py --date {日期} --input {当天过程目录}/hottest_industry_candidate.json`
2. 读取 `entry_signal.json`，得到满足放量突破的技术信号

### Step 3：持仓风险评估

1. 从 hermes-trade 查询实际持仓，并写为 `{代码: 买入价}` 的 positions 文件
2. 运行 `risk_signal.py --date {日期} --positions positions.json`
3. 读取 `risk_signal.json` 的 `risk_actions` 与 `holdings`，并检查顶层 `data_sources`（记录每只持仓的实际取数通道）；脚本同时更新 `prudent_tags.json` 和 `state.json`
4. 开盘段取数降级链（官方 → promax → `unavailable`）与参考价口径（取日线 open）见 [[交易/交易体系/热门板块回调低吸体系/风控.md|风控]]「数据源」

### Step 1.5：落过程资料 · 板块热度研判

AI 判断完热门行业并完成行业筛选后，将推理过程落盘到过程资料：

- 路径：`knowledge/交易/过程资料/{当前日期}/热门板块回调低吸体系/板块热度研判.md`
- 内容：候选板块的四维量化数据 + AI 对各板块的分析 + 为什么选/不选的理由
- 参考 `过程资料/RULES.md` 的规范编写

### Step 4：Agent 综合判断

结合脚本输出 + 市场信息 + 持仓状态，形成对下一交易日的判断结论，供生成计划使用。

**仓位分级（2026-08-04 新增）：** 综合判断时按 `建仓.md` 的「仓位分级」章节执行（三层分级表、试仓比例、升级规则均在建仓.md，此处不重复），具体执行动作：

1. **大盘三档判断**：拉创业板指（399006.SZ）当日涨跌幅，分为三档——
   - `企稳`：创业板当日 >0
   - `非极端弱`：创业板当日 -2%~0
   - `极端弱`：创业板当日 ≤-2%
2. **按分级表定仓位**：根据「开仓信号 + 板块当日双确认 + 大盘档位」在分级表中定位（正式仓/试仓/观察）。
3. 交易计划中必须标注本次动作的**仓位级别**（正式仓/试仓/观察），试仓在 note 中注明"试仓 1/4"。

**如果当日有复杂决策**（多候选对比、持仓去留有取舍、犹豫不决等），将推理过程落盘到过程资料：

- 路径：`knowledge/交易/过程资料/{当前日期}/热门板块回调低吸体系/综合研判.md`
- 内容：候选股对比分析、持仓去留的权衡、最终决策逻辑
- 当日无复杂决策（如无持仓+无信号→简单的不操作说明）可跳过这篇

## 二、T+1日 18:25：模拟执行当日交易计划

### 定位

这一步不是重新做判断，而是**根据既有计划回放执行**。执行层只负责读计划、查价格、记账。

### Step 1：读取当日计划

从 `knowledge/交易/交易计划/{T+1日期}/` 查找当日计划：

- 文件存在 → 读取计划中的执行指令
- 文件不存在 → 静默退出（无计划、无操作）

### Step 2：按计划执行

根据计划中的动作类型：

| 动作 | 操作 |
|------|------|
| **买入** | 记录买入交易（价格、数量、标的） |
| **卖出** | 记录卖出交易（价格、数量、标的） |
| **持有不动** | 不操作，记录"按计划持有" |

若计划中有明确执行价格规则，按规则抓取对应价格；若无明确规则，默认使用当日收盘价。

**回放验证常见条件检查：**

| 条件 | 判断方式 | 数据来源 |
|------|----------|----------|
| 开盘大幅高开>5% | `gap = (open - pre_close) / pre_close * 100` | `pro.daily(ts_code, start_date, end_date)` |
| 非交易日顺延 | 交易日判断已在第①步完成 | `is_trading_day.py` |

**数量取整规则（A股）：**

| 板块 | 最小单位 | 示例运算 |
|------|----------|----------|
| 沪主板 (600xxx/601xxx) | 100股/手 | `floor(budget / price / 100) * 100` |
| 深主板/中小板 (000xxx/002xxx) | 100股/手 | 同上 |
| 创业板 (300xxx) | 100股/手 | 同上 |
| 科创板 (688xxx) | 200股/手 | `floor(budget / price / 200) * 200` |
| 北交所 (920xxx.BJ) | 100股/手 | 同上 |

**条件未触发的处理：** 不执行交易，在最终输出中记录"条件未触发+具体原因"。

### Step 3：记账

通过 `hermes-trade` 技能在 MNZH 账户记录模拟交易：

```bash
cd /opt/data/skills/hermes-trade/scripts && /opt/hermes/.venv/bin/python3 trade_cli.py create \
  --account-id MNZH \
  --system-id hot_sector_pullback_system \
  --code {代码} \
  --name {名称} \
  --side {buy|sell} \
  --quantity {数量} \
  --price {成交价} \
  --occurred-at {执行时点} \
  --note "热门板块回调低吸模拟执行 {日期}"
```

### Step 4：输出执行结果

输出结果供复盘 cron 读取，至少包含：
- 是否按计划执行
- 成交价/量
- 持仓变化

### Step 4.5：更新自选股状态（有例外时）

**无交易（持有不动 / 空仓不操作）→ 原则上跳过自选股状态更新。** 但有例外：

**例外A：计划监控清单有新候选标的需要入库。** 当计划中"监控清单"表格出现尚未在 watchlist 中的标的时，即使无交易，也应将这些标的通过 `watchlist_cli.py create` 添加到自选池：

```bash
cd /opt/data/skills/hermes-trade/scripts && /opt/hermes/.venv/bin/python3 watchlist_cli.py create \
  --code {代码} --name {名称} --status watching \
  --systems '[{"id":"hot_sector_pullback_system","name":"热门板块回调低吸体系","reason":"{关注理由}"}]' \
  --reason "热门板块回调低吸监控 {日期}"
```

**例外B：计划中明确标注某标的"退出重点监控"或类似状态变更时**，即使无交易，也应更新其 `--reason` 字段以反映最新评估：

```bash
watchlist_cli.py update {代码} --reason "退出重点监控 {日期} 回调幅度已恢复"
```

**⚠️ 退出监控的单日判定敏感性（2026-08-03 实测）：** 单日涨跌作为"退出重点监控"依据过于敏感——长城电工 600192 于 7/31 因单日 -1.80% 被移出监控，8/3 即涨停 +10.06%。单日下跌可能是随机波动而非趋势转弱。若计划/复盘提到"退出监控"，执行时不要机械照做，先确认是否基于连续多日表现或技术形态（MA5/MA10 位置）而非单日涨跌；单日依据时在复盘记录为信号偏差即可，不要改执行动作。退出监控 ≠ 不可再入池。

买入成交后，自选股候选 (candidate) → 持仓 (trading)：

```bash
watchlist_cli.py update {代码} --status trading
```

- 买入的全部更新为 trading
- 候选但未买入的保持 candidate 不动
- 卖出的（完全平仓）→ 从 watchlist 删除或移除本体系 systems 条目

### Step 5：落简报

写入 `knowledge/摘要/.abstract/{日期}_hot-sector-pullback-execute.txt`

## 三、T+1日 18:30：复盘


### Step 3：执行复盘

对比计划中的动作 vs 实际执行结果：
- 是否按计划执行
- 价差是否合理
- 条件是否如实触发
- 如有偏差，记录原因

### Step 4：体系复盘

基于持仓状态、策略表现、当日市场情况，评价体系运行状态：
- 当前持仓是否合理
- 选股/建仓/风控规则表现如何
- 是否有值得注意的市场变化
- 是否有体系改进方向（记录但不修改）

## 四、T+1日 18:35：生成下一交易日计划

### Step 1：读取复盘结论

复盘 cron 的输出已通过 context_from 注入，提取关键信息：
- 当日执行结果
- 体系复盘分析
- 改进建议

### Step 2：查询持仓状态

通过 hermes-trade 查询 MNZH 账户下当前持仓和最新盈亏。

### Step 3：收集决策信息

基于当前情况自主判断需要什么信息：
- **脚本数据**：运行或读取 `select_candidates.py` / `sector_heat.py` / `entry_signal.py` / `risk_signal.py` 产物
- **市场信息**：搜索相关板块/个股的近期新闻
- **技术分析**：拉取持仓或候选股的日线数据

### Step 4：读取规则文档

- [[交易/交易体系/热门板块回调低吸体系/选股.md|选股规则]]
- [[交易/交易体系/热门板块回调低吸体系/建仓.md|建仓规则]]
- [[交易/交易体系/热门板块回调低吸体系/风控.md|风控规则]]

### Step 5：形成唯一动作结论

计划结论只能是以下之一：
1. 买入某只股票（建仓）
2. 卖出某只股票（平仓）
3. 持有不动（无操作）

**不做多方案并行输出。** 如果判断不清，默认保守。

**⚠️ 回调深度检查（必做 — 不能只看 `entry_signal.json` 信号量）：**

`entry_signal.py` 输出的信号量可能很大（100+），但其中多数是"板后继续涨"或"当日涨停"的追板信号，不符合"回调低吸"逻辑。拿到信号后，必须按候选的 `pullback_pct` 做以下分类：

| 类型 | pullback_pct | 含义 | 是否可操作 |
|:-----|:------------|:-----|:----------|
| 负回调 | < 0 | 从板高回落 → 符合"回调"逻辑 | ✅ 核心候选 |
| 正回调 | > 0 | 板后持续上行 → "追涨"非"低吸" | ❌ 不符合 |
| 零回调 | = 0 | 当日涨停（刚封板）→ 无回调 | ❌ 不符合 |

**关键判断：** 即使热门板块成立、buy_signal 信号很多，如果负回调候选数量为 0 或回调深度普遍不足（最深< -8%，距 MA10 差距 > 10%）→ **必须不操作**。回调低吸的核心是买在均线支撑附近，不是追在板高附近。

**实战案例（2026-07-16）：** 制药集群首次达到热门标准（42只候选），buy_signal 输出 116 个信号，但仅 27 只为负回调，且最深的制药板块候选（迪哲医药 -5.33%）距 MA10 仍差 19%。正确决策：继续空仓观察，标注观察清单待次日盘中验证。

**强制生成计划（每天必须落盘，无例外）：**
- entry_signal 有信号 + 无持仓 → 检查回调深度 → 深度够则买入计划，不够则不操作
- entry_signal 有信号 + 有持仓 → 生成买入+持有/调仓计划
- risk_signal 有 `reduce` 或 `liquidate` 动作 → 强制生成对应卖出计划
- 当前有持仓 → 强制生成持有/卖出计划（持仓不能无主）
- **无信号 + 无持仓** → **出不操作说明**（解释为什么不开仓：市场环境如何、候选股质量、买入条件未触发的原因）
- **有热门板块 + 有信号 + 但回调深度不足** → **出不操作说明**（说明板块已热但买点未到，标注观察清单供次日回放执行）

**关键记忆点：** **每天必须有交易计划**——无论是否有持仓、无论是否有信号。有持仓出持有/卖出计划，无持仓出不操作说明。让人看到的是"系统分析过了，决定不操作"，而不是"系统跳过了没管"。无计划 = 止损建议被丢失 = 真实亏损。（详见 `踩坑记录.md` 陷阱 II）

## 五、异常处理

### 1. 无当日计划 → 跳过

18:25 执行阶段读不到当日的交易计划文件 → 静默退出，不推送不落盘。

### 2. 无复盘结论 → 跳过

18:35 生成计划时没有复盘结论注入 → 跳过本次任务，不做操作。

### 3. 数据缺失

若 Tushare 对应数据缺失 → 如实记录，不编造价格。

### 4. 判断不清 → 默认保守

Agent 判断不清时，默认继续持有或空仓等待，不强行操作。

### 5. 18:30 复盘不能 silent（关键）

**18:30 不能 silent**——18:35 generate-plan 靠 context_from 读复盘结论，silent 会导致下游断链。即使无交易（"无交易，体系正常"）也要输出完整复盘结论（文档 + 精简版推送）。

### 6. 不复盘时的静默规则

- **复盘文档模板**：`references/review-template.md` — 5段式结构（执行复盘→资产表现→落选信号→体系评估→预判），含 frontmatter、精简版格式、特殊场景处理。**首次复盘时也引用此模板。**
- **信号复盘贯穿始终** — 无论有无交易，都检查当日过程资料中的 `entry_signal.json` 评估信号质量，对比信号股次日表现，区分“选了→涨跌”与“没选→涨跌”。
- **entry_signal.json 空信号处理** — 当 `signals` 数组为空时，落选信号复盘直接写“0个信号，无落选信号可对比”。
