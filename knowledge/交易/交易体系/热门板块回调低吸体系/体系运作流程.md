# 热门板块回调低吸体系运作流程

> 本文件是体系流程的唯一事实源。盘后任务的执行指引见**第 2 节**；任务 prompt 只写运行契约（交易日判断、投递、简报、输出格式、边界）并指向本节。
> **路径写法**：本文路径一律为逻辑路径（不带 `knowledge/`、`archive/` 前缀），并在路径后就近标注头与解析方式——落盘标注「（落 `knowledge/`）」，读取标注「（读 `knowledge/`→`archive/`）」表示先在 `knowledge/` 找、缺失时到 `archive/` 找。归档只改物理位置，逻辑路径不变；新产物只写物理根 `knowledge/`。

## 一、运行入口

体系有三个定时任务：`hot-sector-pullback-1900-replay-execute`（交易日 19:00，按当日计划回放 MNZH 模拟账户）、`hot-sector-pullback-1910-review`（交易日 19:10，复盘当日计划与执行）、`hot-sector-pullback-1925-generate-plan`（交易日 19:25，生成下一交易日计划）；非交易日只回执一行。任务通过 MCP 访问数据与账户：`tushare-data`（交易日与行情）、`trade-management`（MNZH 模拟账户的成交、持仓与现金）、体系自身的 `hot-sector-pullback-system`（四段事实、板块环境与渲染）。

- 运行定义（唯一）：`.pi/mcp-servers/trade-system/hot_sector_pullback_system/`，含 `mcp_server.py`（实现）、`system.yml`（契约）、`params/`（参数唯一来源）、`templates/`（模板唯一来源）。下文出现的 `params/`、`templates/` 均指该目录下。
- 体系 MCP：注册名 `hot-sector-pullback-system`；工具清单、入参与返回口径见 `交易/交易体系/热门板块回调低吸体系/MCP介绍.md`。
- 规则唯一来源：`交易/交易体系/热门板块回调低吸体系/选股.md`（候选与涨停口径）、`交易/交易体系/热门板块回调低吸体系/建仓.md`（建仓信号与仓位分级）、`交易/交易体系/热门板块回调低吸体系/风控.md`（三层风控、审慎标签与取数降级）。
- 过程资料、计划与复盘的落盘位置以运行定义的 `system.yml` 为准。

### 1.1 每日时间轴（交易日）

| 时点 | 事项 | 谁做 |
|:--|:--|:--|
| 15:00 | 全局收盘提醒，询问是否有成交需录入 | 全局任务 |
| 15:00 后 | 报当日成交，会话用 `trade-management` 登记 | 用户 → 会话 |
| 19:00 | 回放执行：按当日计划登记模拟成交并核验快照 | 体系任务 |
| 19:10 | 复盘：对照计划与执行，写体系复盘 | 体系任务 |
| 19:25 | 生成事实链与下一交易日计划，飞书汇报 | 体系任务 |
| 22:30 | 全局复盘追问：核验事实 + 汇总各体系未结 todo | 全局任务 |
| 次日 09:15 | 全局通报：读当日计划 | 全局任务 |
| 次日开盘 | 按计划在 MNZH 模拟账户执行 | 用户 |

非交易日：19:00／19:10／19:25 三个任务只回执一行，不生成产物。

## 二、盘后任务执行明细（交易日 19:00–19:25）

### 2.1 输入与前置

- 交易日判断：`tushare-data.get_trade_calendar`；非交易日发送一行状态后结束，不生成产物。
- 当日计划：`交易/交易计划/<当日>/热门板块回调低吸体系_交易计划.md`（读 `knowledge/`→`archive/`）；缺失时记录链路异常，不补写。
- 账户事实：`trade-management.portfolio_snapshot`（MNZH）取现金、非零持仓与 `trade_as_of`；不得用估算仓位或旧状态替代。
- 上一有效状态：`state.json`、`prudent_tags.json`（读 `knowledge/`→`archive/`，取最近一份有效快照）。
- 参数：`params/selection.json`、`params/sector_heat.json`、`params/entry.json`、`params/risk.json`、`params/runtime.json`；调用前先用 `validate_parameters` 校验。

### 2.2.1 19:00 回放执行

| # | 步骤 | 数据来源 | 产物 |
|:--|:--|:--|:--|
| 1 | 确认交易日、计划完整性及其标的、数量与价格规则 | `tushare-data.get_trade_calendar` | — |
| 2 | 按计划登记模拟成交并用快照核验结果 | `trade-management`（`trade_record`、`portfolio_snapshot`） | 执行事实 |
| 3 | 汇报结果、持仓变化与异常 | — | 简报 `摘要/.abstract/<YYYY-MM-DD>_hot-sector-pullback-execute.txt`（落 `knowledge/`） |

回放执行不重新判断、不修改计划；非交易日或当日无计划时只写最小结论。

### 2.2.2 19:10 复盘

对照当日计划、执行事实与市场事实写体系复盘；无成交时仍写维持结论。产物：`交易/交易复盘/<YYYY-MM-DD>/热门板块回调低吸体系_复盘.md`（落 `knowledge/`）与简报 `摘要/.abstract/<YYYY-MM-DD>_hot-sector-pullback-review.txt`（落 `knowledge/`）。

### 2.2.3 19:25 事实链与下一交易日计划

写入目录：`交易/过程资料/<YYYY-MM-DD>/热门板块回调低吸体系/`（落 `knowledge/`）。

| # | 步骤 | 数据来源（MCP 工具与入参） | 产物 |
|:--|:--|:--|:--|
| 1 | 全市场候选筛选 | `hot-sector-pullback-system.calculate(operation="select_candidates", date="{date}")` | `full_market_candidate.json` |
| 2 | 候选行业热度与全市场板块环境 | `hot-sector-pullback-system.calculate(operation="sector_heat", date="{date}")` | `sector_heat.json`、`sector_environment.json` |
| 3 | 渲染热度事实供阅读（可选） | `hot-sector-pullback-system.render(artifact="sector_heat", date="{date}")` | `sector_heat.md` |
| 4 | 判断热门行业并留痕 | 上列产物 + `交易/交易体系/热门板块回调低吸体系/选股.md`「行业筛选」 | `板块热度研判.md` |
| 5 | 按选定行业筛选候选 | `calculate(operation="select_candidates", date="{date}", industries=[...])` | `hottest_industry_candidate.json` |
| 6 | 建仓信号 | `calculate(operation="entry_signal", date="{date}", industries=[...])` | `entry_signal.json` |
| 7 | 持仓风控 | `calculate(operation="risk_signal", date="{date}", positions={portfolio_snapshot 结果})` | `risk_signal.json`、`state.json`、`prudent_tags.json` |
| 8 | 渲染事实供阅读（可选） | `render(artifact="{candidates\|entry_signal\|risk_signal}", date="{date}")` | 同名 `.md` |
| 9 | 生成下一交易日计划（结构见 2.4） | 上列产物 + `params/` + 规则文档 | `交易/交易计划/<下一交易日>/热门板块回调低吸体系_交易计划.md`（落 `knowledge/`） |
| 10 | 飞书汇报（要点见 2.5） | — | 简报 `摘要/.abstract/<YYYY-MM-DD>_hot-sector-pullback-generate-plan.txt`（落 `knowledge/`） |

步骤 1–8 一律通过体系 MCP 计算与渲染；调用失败时记录失败阶段与错误信息，不估算、不改用历史产物。未选定行业时步骤 5–6 省略 `industries` 入参，直接以上一步产物为准。

### 2.3 判定口径

| 判定 | 依据 |
|:--|:--|
| 候选（涨停窗口、板数、回调均线、新股排除） | `交易/交易体系/热门板块回调低吸体系/选股.md`「选股流程」 |
| 热门行业 | `交易/交易体系/热门板块回调低吸体系/选股.md`「行业筛选」+ 当日 `sector_heat.json`、`sector_environment.json` |
| 建仓信号与量能 | `交易/交易体系/热门板块回调低吸体系/建仓.md`「开仓信号」 |
| 仓位分级与板块双确认 | `交易/交易体系/热门板块回调低吸体系/建仓.md`「仓位分级」 |
| 大盘三档 | `交易/交易体系/热门板块回调低吸体系/建仓.md`；取值见 `sector_environment.json` 的 `benchmark` |
| 三层风控、审慎标签、参考价与降级链 | `交易/交易体系/热门板块回调低吸体系/风控.md` |
| 阈值与可配参数 | 运行定义 `params/`（`selection.json`／`sector_heat.json`／`entry.json`／`risk.json`） |
| 市场宽度与涨跌停统计口径 | `交易/交易体系/热门板块回调低吸体系/选股.md`「选股流程」；含 `sector_environment.json` 的新股排除与 ST 处理 |

本节不复制阈值与数值。

### 2.4 计划文档结构

计划是下一交易日的唯一动作来源，按四段写：

1. **动作**：标的、方向、入场与出场规则（信号日次一交易日开盘价成交、数量或仓位分级）、触发条件与失效条件；
2. **风控衔接**：三层风控与审慎标签的当前状态；
3. **待决策项**：需要用户裁定的事项按 `todo` 格式落盘 `- [ ] T-YYYY-MM-DD-N ｜ 用户 ｜ 触发 ｜ 来源`，未决定前维持现状；
4. **执行提示**：MNZH 模拟账户中需要登记的成交或参数。

计划只保留可执行结论，不复制过程事实；无可行动作时写「无动作」及理由。

### 2.5 汇报要点

首行一行式状态（`【任务简称】结论/动作 ｜ 关键数字`）；正文列动作、理由、风险与计划路径；不超过 5 行，异常与待办各占一行。三个任务各写自己的简报，不相互覆盖。

### 2.6 异常分支

| 情形 | 处理 |
|:--|:--|
| 非交易日 | 一行状态回执后结束，不生成产物 |
| 当日计划缺失或字段不全 | 19:00 与 19:10 写最小结论并标注；不补写计划 |
| 上游过程产物缺失（如缺当日 `full_market_candidate.json`） | 记录链路异常，停止依赖步骤；补跑由会话显式发起 |
| 分钟线限频或降级 | 按 `params/risk.json` 的 `fallback_sources` 顺序取数；全失败标 `unavailable`，照常产出状态文件且不刷新审慎标签 |
| 候选或信号为空 | 正常落盘空结果，计划写「无动作」结论，不推断、不用历史产物替代 |
| 账户快照缺失或无效 | 记录链路异常，停止风控与计划生成；不使用估算仓位 |
| MCP 调用失败或不可用 | 记录失败阶段与错误信息，如实报告；不执行仓库内的历史脚本 |

非交易日跳过是本体系的设计：四段事实、风控与计划都需要当日的行情与分钟线，19:25 生成的计划指向下一个交易日。这与旧实现「按今天是否有交易日跳过生成计划、结果漏掉次日计划」的失效不同（历史经过见 `笔记/体系搭建/热门板块回调低吸体系-踩坑记录.md` 陷阱 I）。

## 三、复盘衔接

1. 19:10 复盘对照当日计划、执行事实与市场事实，写入 `交易/交易复盘/<YYYY-MM-DD>/热门板块回调低吸体系_复盘.md`（落 `knowledge/`）。
2. 计划中的待决策项由用户在 22:30 复盘追问或会话中处理；未决定前维持计划现状，不自动执行。
3. 复盘结论不写回过程资料；规则与参数调整按第五节变更链处理。

## 四、按需链

### 4.1 行业筛选重跑

`select_candidates(industries=[...])` 与 `entry_signal(industries=[...])` 依赖当日 `sector_heat.json` 与 `板块热度研判.md` 的结论；研判改变后重跑第 2.2.3 节步骤 5–6，旧产物被同日新结果覆盖。

### 4.2 分钟线降级与复算

官方 `stk_mins` 实测 1 次/小时，而 19:00／19:10／19:25 同处一小时。`risk_signal` 按 `params/risk.json` 的 `fallback_sources`（默认 `["official","promax"]`）取数，`risk_signal.json` 的 `data_sources` 记录每只持仓的实际通道；复盘据此判断数据可信度。口径见 `交易/交易体系/热门板块回调低吸体系/风控.md`。

### 4.3 上游缺失后的补跑

任一上游产物缺失时按 2.6 停止依赖步骤；补跑需由会话显式发起，并保持同一交易日的日期口径。

## 五、变更链

规则、参数、实现与流程变更按以下顺序执行：

1. 改规则文档（`交易/交易体系/热门板块回调低吸体系/选股.md`／`交易/交易体系/热门板块回调低吸体系/建仓.md`／`交易/交易体系/热门板块回调低吸体系/风控.md`）、运行定义 `params/` 或 `mcp_server.py`；
2. 调用 `validate_parameters` 校验参数；改实现时用同一输入在沙盒（`PI_PROJECT_DIR=/tmp/...`）复算并比对事实值；
3. 写 `更新日志/<YYYY-MM-DD>_<主题>.md`，记动因、变更、验证与遗留；
4. 同步受影响文档：规则、本 SOP、运行定义 `system.yml` 契约、`交易/交易体系/热门板块回调低吸体系/MCP介绍.md`；本 SOP 章节编号变化时同步检查引用它的任务 prompt；
5. 变更后首个交易日复核实际产物。

## 六、与全局任务的接口

| 全局任务 | 与本体系的接口 |
|:--|:--|
| `global-0915-daily-plan-report` | 读当日 `交易/交易计划/<日期>/热门板块回调低吸体系_交易计划.md`（读 `knowledge/`→`archive/`） |
| `global-1500-trade-remind` | 提醒是否有成交需录入（成交登记链的触发口） |
| `global-2230-manual-review` | 核验当日成交与持仓，汇总本体系未结 todo |
| `global-2330-todo-audit` | 扫描并审计本体系文档中的未结 todo（只报告，不改写） |
| `global-2340-knowledge-archive` | 归档超过 30 天的日期型文档（含本体系过程资料、计划、复盘） |
| `global-2355-summary-aggregation` | 消费本体系简报，生成每日摘要 |
| `global-mon0030-weekly-landing-check` | 周一核查上周新增文档的规范与引用 |
| 本体系提供 | 过程资料、交易计划、交易复盘、简报、更新日志 |

本体系与其它交易体系没有输入输出关系：全市场板块环境由本体系自算，不读取其它体系的过程产物。

## 七、边界

- 体系只生成模拟交易计划，MNZH 为模拟账户，不执行真实交易。
- 过程资料记录事实，计划记录唯一动作，复盘记录计划与执行偏差；三者不互相替代。
- 不在运行任务中修改静态规则、参数或历史资料。
- 不用旧脚本、旧 CLI、旧 `output/` 或其它日期的产物替代当前结果。
