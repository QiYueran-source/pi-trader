# 热门板块回调低吸体系 · 体系运作流程

## 定位

本文档是本体系的业务行动指南，定义从事实采集到计划、执行、复盘的完整闭环。具体执行时刻由对应 cronjob 配置决定，当前安排为：19:00 回放执行、19:10 复盘、19:25 生成下一交易日计划。

本体系为观察体系，所有执行均在 MNZH 模拟账户进行。脚本负责生成可复现事实，Agent 负责解释事实、记录判断并形成唯一交易计划。

## 总体原则

1. 先回放上一份正式计划，再生成下一份计划。
2. 过程资料记录事实和判断依据；交易计划只记录可执行结论；复盘记录计划与执行偏差。
3. 没有交易也要完成必要的复盘和计划结论，不能用静默代替状态判断。
4. 缺少数据、日期不一致或输入无效时，停止依赖该输入的下游步骤并说明原因。
5. 不补造价格、持仓、成交、收益或市场数据；判断不清时保守处理。

## 阶段一：盘后事实采集与行业判断

### 输入

- 当前交易日和交易日历；
- `params/*.json`；
- Tushare 行情、股票信息和交易日历接口；
- 可选的同日 `红利科创ETF双网格体系/sector_facts.json`。

### 执行

按以下顺序执行脚本：

```bash
python scripts/prepare_shared_sector_context.py --date <YYYY-MM-DD>
python scripts/select_candidates.py --date <YYYY-MM-DD>
python scripts/sector_heat.py --date <YYYY-MM-DD>
python scripts/render.py --date <YYYY-MM-DD> --template sector_heat
```

共享板块事实仅作为全市场背景，不替代本体系的候选行业专项热度。Agent 读取 `sector_heat.json` 和 `sector_heat.md`，判断热门行业，并将数据、选择理由和排除理由写入：

```text
knowledge/交易/过程资料/<YYYY-MM-DD>/热门板块回调低吸体系/板块热度研判.md
```

### 输出

- `shared_sector_context.json`（可选）；
- `full_market_candidate.json`；
- `sector_heat.json`、`sector_heat.md`；
- `板块热度研判.md`。

### 异常处理

共享事实不存在时只记录不可用，不阻断本体系。候选或热度事实缺失、日期错误或参数无效时，不进入后续信号判断。

## 阶段二：热门行业候选与建仓信号

### 输入

- 阶段一的热门行业判断；
- `full_market_candidate.json`；
- `选股.md`、`建仓.md`；
- `params/selection.json`、`params/entry.json`。

### 执行

先按热门行业筛选候选，再计算建仓技术信号：

```bash
python scripts/select_candidates.py --date <YYYY-MM-DD> --industry "行业1,行业2" --output hottest_industry_candidate.json
python scripts/entry_signal.py --date <YYYY-MM-DD> --input "knowledge/交易/过程资料/<YYYY-MM-DD>/热门板块回调低吸体系/hottest_industry_candidate.json"
python scripts/render.py --date <YYYY-MM-DD> --template entry_signal
```

建仓信号只表示技术条件成立，不等于自动买入。必须检查 `pullback_pct`：负回调才符合低吸方向，零回调和正回调属于无回调或追涨，不直接作为低吸买点。

### 输出

- `hottest_industry_candidate.json`；
- `entry_signal.json`、`entry_signal.md`；
- 必要时将候选比较和取舍写入 `综合研判.md`。

## 阶段三：持仓风控

### 输入

- 交易管理 MCP 返回的 MNZH 实际持仓和买入价；
- `params/risk.json`；
- `风控.md`；
- 当日行情和开盘段数据。

### 执行

将实际持仓转换为脚本要求的 `{ts_code: buy_price}` 映射，执行：

```bash
python scripts/risk_signal.py --date <YYYY-MM-DD> --positions <positions.json>
python scripts/render.py --date <YYYY-MM-DD> --template risk_signal
```

检查 `risk_signal.json` 的 `risk_actions`、`holdings`、`data_sources`，并继续维护 `prudent_tags.json` 和 `state.json`。MA10 跌破、MA5 观察/减仓和开盘信号的具体规则以 `风控.md` 为准。

### 输出

- `risk_signal.json`；
- `prudent_tags.json`；
- `state.json`；
- `risk_signal.md`。

无法取得分钟数据时，按 `params/risk.json` 的降级链记录实际来源；全失败仍输出状态文件，不把不可用数据当作利空信号。

## 阶段四：生成交易计划

### 输入

- 当日正式复盘；
- 阶段一至三的过程资料；
- 交易管理 MCP 返回的当前持仓、资金和历史交易；
- `选股.md`、`建仓.md`、`风控.md`。

### 执行

按以下顺序判断：

1. 先处理 `risk_signal.json` 中的 `liquidate` 或 `reduce`；
2. 检查已有持仓是否仍有明确的持有或退出结论；
3. 检查热门行业和建仓信号是否同时成立；
4. 检查回调深度、板块双确认和创业板指环境；
5. 生成唯一动作：买入、卖出或持有不动；
6. 无合格买点时生成不操作计划，并写明原因和观察清单。

计划写入：

```text
knowledge/交易/交易计划/<下一交易日>/热门板块回调低吸体系_交易计划.md
```

计划必须包含动作、标的、数量或仓位级别、执行价格规则、核心理由、风险和失效条件。过程资料中的长篇推理不复制进计划。

## 阶段五：回放执行

由 19:00 的 replay-execute cronjob 触发。读取当日正式计划，只做计划回放，不重新判断。

### 输入

- `knowledge/交易/交易计划/<今天日期>/热门板块回调低吸体系_交易计划.md`；
- 交易管理 MCP 的 MNZH 账户状态；
- 计划要求的行情价格和交易日信息。

### 执行与输出

按计划校验动作、标的、数量、价格规则和触发条件。条件未触发时不交易，并记录具体原因；条件满足时通过交易管理 MCP 登记模拟成交，并更新必要的自选股状态。不得执行真实交易。

输出执行摘要，记录是否按计划、成交价格和数量、持仓变化及异常。完成完整工作后调用 `summary` 技能写入：

```text
knowledge/摘要/.abstract/<日期>_hot-sector-pullback-execute.txt
```

## 阶段六：交易复盘

由 19:10 的 review cronjob 触发。复盘不依赖“有成交”这一条件；无成交时也要说明计划是否正确执行。

### 输入

- 当日交易计划；
- 回放执行结果；
- 交易管理 MCP 的成交、持仓、资金和盈亏；
- 当日过程资料和真实行情。

### 执行

按 `references/review-template.md` 完成：

1. 执行复盘：计划与实际对比；
2. 资产和持仓表现；
3. 建仓信号和落选信号复盘；
4. 体系运行评估；
5. 下一交易日判断和改进建议。

复盘写入：

```text
knowledge/交易/交易复盘/<日期>/热门板块回调低吸体系_复盘.md
```

改进建议只记录，不在复盘任务中直接修改静态规则。完成完整工作后调用 `summary` 技能写入：

```text
knowledge/摘要/.abstract/<日期>_hot-sector-pullback-review.txt
```

## 阶段之间的依赖

```text
候选事实
  -> 板块热度判断
  -> 行业候选
  -> 建仓信号
  -> 持仓风控
  -> 交易计划
  -> 回放执行
  -> 交易复盘
  -> 下一交易日计划
```

任何阶段都不得使用其他日期或其他体系的产物替代当前缺失输入。历史案例、回测证据和踩坑记录只用于理解规则，不替代当日事实。

## 运行文件索引

- 规则：`选股.md`、`建仓.md`、`风控.md`
- 参数：`params/`
- 计算脚本：`scripts/`
- Markdown 模板：`templates/`
- 方法和案例：`references/`、`踩坑记录.md`
- 过程产物：`knowledge/交易/过程资料/<日期>/热门板块回调低吸体系/`
- 计划和复盘：由 `knowledge-management`、`trade-system`、`trade_management` 和 `summary` 技能共同约束
