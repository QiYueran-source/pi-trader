# 热门板块回调低吸体系

## 体系定位

本体系筛选近期涨停启动、回调企稳并出现放量突破信号的强势股，形成候选、板块热度、建仓信号和持仓风控四段式决策事实。当前为观察体系，所有执行均在 MNZH 模拟账户进行。

体系不把脚本信号直接等同于买入。脚本负责生成可复现事实，Agent 根据事实和市场环境形成唯一交易计划，执行与复盘分别记录实际结果和规则表现。

## 决策链路

```text
选股事实
  -> 板块热度判断
  -> 热门行业候选
  -> 建仓信号
  -> 持仓风控
  -> 交易计划
  -> 模拟执行
  -> 交易复盘
```

业务顺序、输入输出和异常处理见 [`体系运作流程.md`](体系运作流程.md)。执行时间由三个体系 cronjob 管理：19:00 回放执行、19:10 复盘、19:25 生成下一交易日计划。

## 运行产物

每日过程资料写入：

```text
knowledge/交易/过程资料/<YYYY-MM-DD>/热门板块回调低吸体系/
```

主要产物包括：

- `shared_sector_context.json`：可选的同日红利科创 ETF 双网格全市场背景；
- `full_market_candidate.json`：全市场候选；
- `hottest_industry_candidate.json`：热门行业候选；
- `sector_heat.json`、`entry_signal.json`、`risk_signal.json`：结构化事实；
- `state.json`、`prudent_tags.json`：持仓风险状态；
- `板块热度研判.md`、`综合研判.md`：Agent 判断过程。

交易计划和复盘分别写入：

```text
knowledge/交易/交易计划/<YYYY-MM-DD>/热门板块回调低吸体系_交易计划.md
knowledge/交易/交易复盘/<YYYY-MM-DD>/热门板块回调低吸体系_复盘.md
```

## 相关技能

- `trade-system`：体系结构、运行 SOP 和过程产物约束；
- `trade_management`：MNZH 模拟账户的成交、持仓和资金管理；
- `knowledge-management`：知识库路径、命名和 frontmatter；
- `summary`：完整工作结束后的摘要落盘；
- `cronjob_management`：体系定时任务的注册、检查和管理。

## 风险边界

- 本体系只生成模拟交易计划，不直接执行真实交易。
- 过程资料不是交易指令，交易计划才是执行依据。
- 缺少事实或数据日期不一致时，不用其他日期或其他体系结果替代。
- 策略规则和参数的调整记录在更新日志中，不在日常执行或复盘时直接修改。
