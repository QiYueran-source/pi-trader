# 热门板块回调低吸体系

## 阅读顺序

1. 先读本文，了解体系定位、规则入口和文件索引。
2. 执行体系时读取 `交易/交易体系/热门板块回调低吸体系/体系运作流程.md`，执行口径以它的第 2 节为唯一事实源。
3. 需要候选、建仓或风控规则细节时，读取对应专题文档。
4. 需要调用体系 MCP 或查看接口入参时，读取 `交易/交易体系/热门板块回调低吸体系/MCP介绍.md`。

## 体系定位

本体系筛选近期涨停启动、回调企稳并出现放量突破信号的强势股，形成候选、板块热度、建仓信号和持仓风控四段式决策事实。当前为观察体系，所有执行均在 MNZH 模拟账户进行。

体系不把信号直接等同于买入：体系 MCP 生成可复现事实，Agent 根据事实和市场环境形成唯一交易计划，执行与复盘分别记录实际结果和规则表现。

## 基本信息

- 体系类型：强势股回调低吸（观察体系）
- 关联账户：`MNZH`（模拟）
- 机器标识：`hot_sector_pullback_system`
- 运行定义：`.pi/mcp-servers/trade-system/hot_sector_pullback_system/`（实现、契约、参数、模板的唯一来源；MCP 注册名 `hot-sector-pullback-system`）
- 执行边界：不执行真实交易；条件与数量由用户在模拟账户人工执行

## 决策链路

```text
选股事实
  -> 板块热度与全市场板块环境
  -> 热门行业候选
  -> 建仓信号
  -> 持仓风控
  -> 交易计划
  -> 模拟执行
  -> 交易复盘
```

业务顺序、输入输出和异常处理见 `交易/交易体系/热门板块回调低吸体系/体系运作流程.md`。执行时间由三个体系任务管理：19:00 回放执行、19:10 复盘、19:25 生成下一交易日计划。

## 运行产物

产物契约以运行定义 `params/runtime.json` 与实现约定为准。当前运行产物写入：

```text
交易/过程资料/<YYYY-MM-DD>/热门板块回调低吸体系/    （落 `knowledge/`；归档后同一逻辑路径位于 `archive/`）
```

- `full_market_candidate.json`：全市场候选；
- `hottest_industry_candidate.json`：热门行业候选；
- `sector_heat.json`：候选行业热度；
- `sector_environment.json`：市场宽度、涨跌停家数、成交额与放量、涨停行业分布、最高连板与大盘三档；
- `entry_signal.json`：放量突破信号；
- `risk_signal.json`：三层风控动作与取数通道；
- `state.json`、`prudent_tags.json`：MA5 观察状态与审慎标签；
- `板块热度研判.md`：会话对热门行业的判断留痕。

交易计划和复盘分别写入：

```text
交易/交易计划/<YYYY-MM-DD>/热门板块回调低吸体系_交易计划.md
交易/交易复盘/<YYYY-MM-DD>/热门板块回调低吸体系_复盘.md
```

过程资料是运行事实，不代表已经成交。实际成交、持仓和账户变化由交易管理流程记录。

## 风险边界

- 本体系只生成模拟交易计划，不直接执行真实交易。
- 过程资料不是交易指令，交易计划才是执行依据。
- 缺少事实或数据日期不一致时，不用其他日期或其他体系结果替代。
- 策略规则和参数的调整记录在更新日志中，不在日常执行或复盘时直接修改。
