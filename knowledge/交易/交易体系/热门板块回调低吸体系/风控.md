# 风控规则

## 定位

风控模块管理持仓的**退出决策**。买入后持续跟踪每只持仓，在出现开盘利空信号、跌破均线或达到硬止损条件时执行退出。风控的触发逻辑分为三层，逐级从严。

## 数据源

风控判断依赖两种数据，均由体系服务在 `calculate(operation="risk_signal")` 内取数：

| 数据类型 | 来源 | 用途 |
|---------|------|------|
| **日线数据** | tushare 日线（目标日及近 70 天） | **当日开盘价（第一层参考价）**、MA5/MA10 计算、收盘价确认 |
| **分钟数据（开盘半小时）** | tushare `stk_mins`，`freq="5min"`，09:30~10:00 | 开盘半小时形态判断 |

### 开盘段取数降级链

`stk_mins` 官方限频严格（**实测 1 次/小时**，同小时重复调用必拒），而 19:00 replay-execute / 19:10 review / 19:25 generate-plan **同处一小时**。服务只取官方的 `client.stk_mins`，失败即标 `unavailable`：

| 通道 | 说明 |
|:---|:---|
| `official` | 官方 `client.stk_mins`（唯一通道） |
| 失败 | 标 `unavailable`（`params/risk.json#opening_signal` 无备源配置），**仍照常产出 `risk_signal.json` / `prudent_tags.json` / `state.json`**（不再整份丢失）；`unavailable` 不属利空信号 → 不刷新审慎标签 |

> 原 `promax` 备源（`tushare-proxy` 技能通道）已于 2026-10-18 随口径收口删除：它依赖的 `.pi/skills/source/tushare/tushare-proxy/scripts` 在仓库中不存在，实际必然失败，只会把兜底伪装成可用。

- `risk_signal.json` 顶层 `data_sources` 记录每只持仓的实际取数通道（当前只有 `official`／`unavailable`），复盘据此判定数据可信度。
- 分钟线请求按持仓串行执行；实际等待节奏以数据源限速为准。
- ⚠️ **（历史证据，备源已撤销）promax 分钟数据实测有质量瑕疵**（2026-09-27 实测 `000536.SZ`）：全天返回 **50 根**（标准 48，多出 `09:30`、`13:00`）；`14:55` 与 `15:00` 两根**逐字段重复**；首根 open 与日线 open 存在偏差（9/23 实测 **3.64 vs 3.60**）。故参考价一律取日线 open（见下），分钟数据只用于形态判定。

### 参考价口径

`params/risk.json#opening_signal.reference_price = "session_open"` 取**目标日的日线 `open`**——它是"当日开盘价"的权威定义，且日线接口不限频、与成交价口径一致；**不用分钟首根 open**（后者随数据源变化，当时 promax 通道下实测可偏 1.1%）。日线 open 缺失时回退分钟首根 open 并在日志告警。

> 分钟窗口 `09:30~10:00` 实测返回 **7 根** 5min bar（`09:30、09:35 … 10:00`，含两端）。

## 第一层：开盘信号 → ⚠️审慎标签

### 触发条件

每个交易日 19:25（generate-plan 环节，`calculate(operation="risk_signal")`），对每只持仓股票**拉开盘半小时（09:30~10:00）的 5 分钟线**，按 `笔记/交易策略/开盘战法-以开盘价为核心的多空判断框架.md` 判断信号：

| 信号 | 判断标准 | 动作 |
|:----|---------|:----|
| **弱势出货** 🔴 | 先涨后跌，跌破开盘价 | 打⚠️审慎标签 |
| **反弹无力** ⚠️ | 先跌后涨，不过开盘价 | 打⚠️审慎标签 |
| **风险规避** 🚨 | 开盘半小时急跌 > `params/risk.json#opening_signal.rapid_drop_pct` | 打⚠️审慎标签 |
| **强势延续** 🟢 | 先涨后跌，不破开盘价 | ✅ 正常 |
| **主力进场** 🟢 | 先跌后涨，站稳开盘价 | ✅ 正常 |
| **无明显信号** | 无上述特征 | ✅ 正常 |

### 标签有效期

| 规则 | 说明 |
|:----|:-----|
| **生效期** | 3天（含触发日） |
| **刷新** | 标签有效期内再次出现利空信号 → 从当天重新计3天 |
| **过期** | 连续3天无新利空信号 → 标签失效 |
| **持久化** | 当日写入 `交易/过程资料/{date}/热门板块回调低吸体系/prudent_tags.json`；回溯深度由 `params/risk.json` 的 `prudent_tag.snapshot_lookback_trading_days` 控制 |
| **状态文件** | `state.json` 独立保存 MA5 观察起始日，供下一交易日继续判断 |

### 标签数据结构

```json
{
  "date": "2026-07-06",
  "positions": {
    "600460.SH": {
      "created_date": "20260706",
      "expire_date": "20260708",
      "signal": "weak_distribution"
    }
  }
}
```

每个交易日写入完整的当前标签状态；服务只从最近一份有效快照继承仍有效的标签。

## 第二层：MA5跌破 → 减半

### 有审慎标签（加速模式）

> 审慎标签有效期内，MA5跌破 → **不等观察，当日直接减仓 `params/risk.json#exit_rules.ma5.reduce_ratio`**（`prudent_observation_days = 0`）

### 无审慎标签（正常模式）

> MA5跌破 → 观察 `params/risk.json#exit_rules.ma5.normal_observation_days` 个交易日，仍未收回 MA5 → 减仓 `#exit_rules.ma5.reduce_ratio`

---

## 第三层：MA10跌破 → 清仓

> 收盘跌破MA10 → **次日开盘直接清仓**，无缓冲、无观察期

MA10是风控的最高优先级防线，不设缓冲。

---

## 整体规则矩阵

| 层级 | 条件 | 缓冲 | 动作 |
|:----|:----|:----|:----|
| 🔴 **三级** | MA10跌破 | ❌ 无 | **清仓** |
| 🟡 **二级（加速）** | MA5跌破 + ⚠️标签有效 | ❌ 不等 | **减半** |
| 🟡 **二级（正常）** | MA5跌破 + 无标签 | ✅ 观察3日 | **减半** |
| 🟢 **一级** | 开盘利空信号 | — | 打⚠️标签（不下单） |

### 仓位下限

减仓过程中，若剩余仓位**不够一手**（即股数 < 对应标的最小交易单位）→ **直接全清**。

## 风险输出

风控结果写入 `交易/过程资料/{date}/热门板块回调低吸体系/risk_signal.json`（落 `knowledge/`）。服务同时写入 `prudent_tags.json`、`state.json` 和当日 `positions.json` 快照；输出动作固定为 `hold`、`observe`、`reduce`、`liquidate`：

```json
{
  "date": "20260928",
  "data_sources": {"000536.SZ": "official"},
  "stats": {"positions": 1, "evaluated": 1, "actions": 1, "hold": 0},
  "risk_actions": [
    {
      "code": "000536.SZ",
      "name": "华映科技",
      "buy_price": 3.6,
      "close": 3.39,
      "pnl_pct": -5.83,
      "signal_date": "20260928",
      "opening": {
        "status": "ok",
        "signal": "rapid_drop",
        "reference_price": 3.61,
        "source": "official"
      },
      "prudent_tag": {"created_date": "20260928", "expire_date": "20260930", "signal": "rapid_drop"},
      "daily": {"ma5": 3.544, "ma10": 3.476},
      "action": "liquidate",
      "reason": "below_ma10"
    }
  ],
  "holdings": []
}
```

实现另附 `artifact`、`system_id`、`generated_at`、`note` 元数据字段与生效的 `params`；`holdings` 为动作为 `hold` 的持仓。空仓时按空仓契约把 `state.json`、`prudent_tags.json` 置为空仓位结构，不继承旧快照。

## 调用方式

```json
{"system_id": "hot_sector_pullback_system", "operation": "risk_signal", "date": "2026-09-28", "positions": {"000536.SZ": 3.6}}
{"system_id": "hot_sector_pullback_system", "operation": "risk_signal", "date": "2026-09-28", "positions": {"000536.SZ": 3.6}, "dry_run": true}
```

`positions` 传空对象 `{}` 表示空仓；`dry_run=true` 只返回结果不落盘。
