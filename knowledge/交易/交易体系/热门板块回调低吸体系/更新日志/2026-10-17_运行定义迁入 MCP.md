# 运行定义迁入体系 MCP，知识库目录只留文档 | 2026-10-17

## 一、动因

体系此前同时存在两套定义：知识库内的 `params/`、`templates/`、`scripts/`（7 个脚本，1,611 行）与 `.pi/mcp.json` 的运行定义。实测知识库脚本的产物 schema 与现行过程资料对不上（如 `select_candidates.py` 输出 `stats.final_candidates`，产物为 `stats.total_candidates`／`candidate_sectors`），4 个渲染模板引用的字段也不存在，`render.py` 直接报错；真正在产的过程资料由会话按现行口径生成。此状态等于把废弃 schema 留在仓库里，并制造两套产物格式。

## 二、口径决定（用户 2026-10-17）

| 项 | 决定 |
|:--|:--|
| 运行定义位置 | `.pi/mcp-servers/trade-system/hot_sector_pullback_system/`（实现、契约、参数、模板、复盘与过程文档模板） |
| 服务组织 | 一个体系一个 MCP 服务，注册键 `hot-sector-pullback-system` |
| 操作切分 | 四个事实工具（`select_candidates`／`sector_heat`／`entry_signal`／`risk_signal`）+ `render` |
| 全市场板块环境 | 不建跨体系工具、不读双网格 `sector_facts`，由本体系 `sector_heat` 自算为 `sector_environment.json`；`shared_sector_context.json` 停用 |
| 涨停口径 | 分板精确（北交所 30%／双创 20%／主板 10%／ST 5%）+ 容差；跌停剔 ST；`T-2026-10-16-9` 以本实现为唯一口径结案 |
| 回调过滤 | 逐日重算 MA10 后逐日比较（不采用「只看最新一根」的简化口径） |
| 板块趋势 | `trend` 沿用过去配置：`short > long` 记「多头排列」 |
| 行业候选层 | 保留 `hottest_industry_candidate.json` |
