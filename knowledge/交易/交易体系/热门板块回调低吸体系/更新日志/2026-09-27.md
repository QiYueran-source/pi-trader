# 更新日志 · 2026-09-27

## 变更背景

有持仓时，19:25 generate-plan 环节的 `risk_signal.py` 会在 `fetch_opening_signal` 处直接抛 `Exception: 频率超限` 退出，导致 `risk_signal.json` / `prudent_tags.json` / `state.json` **三者全部不产出**。此前被判定为「结构性必然失败」，处置方式是手工采执行层 5 分钟记录 + 日线交叉印证，并在正文标注「未经脚本独立重算」。

本次核查改判：**数据本身取得到，缺的是脚本内的降级路径**。

- 官方 `stk_mins` 限频实测为 **1 次/小时**（同小时重复调用必拒），而 19:00 replay-execute / 19:10 review / 19:25 generate-plan **同处一小时**互相挤；
- 每次调用会吃掉该小时额度，故 19:25 必挂；
- `fetch_opening_signal` 原先在 `main()` 持仓循环内裸调，异常向上抛 → 三次 `save_json` 永不执行。

## 参数变更

`params/risk.json` 的 `opening_signal` 新增：

```json
"fallback_sources": ["official", "promax"]
```

依据交易体系 RULES「`scripts/` 不在脚本中硬编码同类业务参数」，降级顺序配置化。

## 脚本变更

### `scripts/runtime_support.py`

`load_risk_config()` 的 `require_exact_fields` 期望集同步加入 `fallback_sources`，并新增取值校验：必须为非空数组、元素仅限 `official` / `promax`、不得重复。**精确字段校验器必须同步改，否则脚本当场 fail。**

### `scripts/risk_signal.py`

1. 拆出 `fetch_official_bars()` 与 `fetch_proxy_bars()`；`fetch_opening_signal()` 按 `fallback_sources` 顺序降级，返回结果带 `source` 字段。
2. promax 分支走 `tushare-proxy` 技能（延迟导入），并**强制校验返回 `trade_time` 日期 == 目标交易日**（代理有返回陈旧历史分钟序列的前科）。
3. 调用点包 `try/except`：任何异常都降级为 `unavailable`，**保证三个 JSON 必定落盘**（宁可产出带 `unavailable` 标记的文件，也不要「文件不存在」这种歧义状态）。
4. 输出顶层新增 `data_sources: {code: source}`，记录每只持仓的实际取数通道（`official` / `promax` / `unavailable`）。
5. `unavailable` 时 `signal="unavailable"`，不在 `BEARISH_OPENING_SIGNALS` 内 → **不刷新审慎标签**，行为安全。

### 参考价口径修正（`session_open`）

`classify_opening_signal()` 原先用**分钟首根 open** 作参考价。实测该值随数据源变化（promax 与官方日线 open 可差 1.1%），当 `last_close` 贴近参考价时足以翻转第一层判定。现改为：

1. `fetch_daily_records()` 的 `fields` 增 `open`；
2. `classify_opening_signal(bars, config, reference_open)` 以**日线 open** 为参考价（权威定义、`daily` 不限频、与成交价口径一致）；
3. 分钟首根 open 与日线 open 偏差 > `max(0.01, 参考价×0.5%)` 时打日志告警；日线 open 缺失则回退分钟首根 open 并告警。

## 验证

1. **回放对账**：9/23、9/24 真实持仓日跑通（官方被拒 → promax），两日判定均 `weak_distribution`、`action=reduce / reason=below_ma5`，MA5/MA10 与审慎标签**与历史复盘完全一致**；9/23 参考价得日线 open `3.6` 并正确触发偏差告警。
2. **官方优先路径**：mock 官方成功时 `source=official`。
3. **韧性**：全部数据源失败时 `main()` 不抛异常，三个 JSON 全部产出、`data_sources=unavailable`。
