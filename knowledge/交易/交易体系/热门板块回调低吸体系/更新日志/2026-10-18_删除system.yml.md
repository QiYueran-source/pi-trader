# 删除 system.yml（体系身份改由目录名与体系介绍承载） | 2026-10-18

## 一、动因

`system.yml` 在实现里只被做存在性校验（`is_file()`），字段一个都不读，且每个字段都另有权威来源：目录名（`system-id`）、代码常量（名称、版本）、`params/instrument.json`（账户）、实现注册的工具（操作）、`params/runtime.json`（产物文件名与状态规则）、知识库 `体系介绍.md`（成熟度、账户、边界）。用户 2026-10-18 裁定删除。

## 二、变更

| 对象 | 变更 |
|:--|:--|
| 运行定义目录 | 删除 `system.yml`；启动校验改为 `params/` 目录必须存在 |
| 技能 | `trade-system` SKILL 与 `reference/{mcp,sop,single-source,trade-system-management}.md`、`agent-dev/cronjob-management` SKILL 与 `references/cronjob-design.md` 中「取自/以 `system.yml` 为准」的表述改为：`system-id` = 运行定义目录名（未迁入体系取 `体系介绍.md` Frontmatter）、体系身份与成熟度归 `体系介绍.md`、操作与工具以实现为准、产物文件名以 `params/runtime.json` 为准 |
| 知识库文档 | `体系介绍.md`（基本信息与文件索引）、`MCP介绍.md`（目录树与契约细节）、`体系运作流程.md`（运行定义行、落盘位置、变更链）中的引用同步 |

## 三、验证

- 删除后四个体系的 MCP 服务均可正常启动：工具发现、`get_manifest`（返回的体系身份与操作来自实现）、`validate_parameters`、既有计算/渲染工具全部不变。
- 全仓（技能、知识库活文档）已无 `system.yml` 活引用；历史 更新日志 与 摘要 中的记述按「历史不回改」保留。

## 四、遗留

- 热门板块 19:25 任务的 `prompt.txt` 仍写「运行契约以运行定义 `…/system.yml` 为准」，将随任务 prompt 批次一并改为「以本体系 MCP 的 `get_manifest` 与 `params/runtime.json` 为准」，待用户确认后重注册。
