## 文档结构（5段式）

### 一、执行复盘

**计划 vs 实际对比表：**

| 计划动作 | 标的 | 计划价格 | 实际价格 | 偏差 | 状态 |
|---------|------|---------|---------|------|------|
| ... | ... | ... | ... | ... | ✅/❌ |

**已闭合盈亏表（如有卖出）：**

| 标的 | 买入日期 | 买入价 | 卖出价 | 数量 | 盈亏 | 持有天数 |
|------|---------|--------|--------|------|------|---------|

**结论**：一行总结执行是否完全按计划。

### 二、资产表现复盘

**市场环境**：用 `pro.daily(trade_date=当日)` 拉全市场涨跌分布（上涨N只/下跌N只/比例%）。

**持仓逐一检查表：**

| 标的 | 成本价 | 今日收盘 | 盈亏% | MA5 | MA5之上? | 判断 |
|------|--------|---------|-------|-----|---------|------|

**归因分析**（每只持仓逐一写）：

- 标的名称（盈亏%，判断词如"极强/健康/偏弱"）
  - 买入逻辑：{当初的理由}
  - 当前状态：{近期走势简述}
  - 逻辑验证：✅/⚠️/❌ {是否成立}
  - 建议：{持有/关注/卖出建议}

**已卖出归因**（如有）：

- 标的名称（盈亏%）
  - 失败原因：{一句话}
  - 归因分类：{选股失误/大盘带崩/板块错判}

归因分类标准：
| 归因 | 特征 | 应对 |
|------|------|------|
| 选股失误 | 板块涨、个股跌，或个股跌幅远超同板块 | 反思选股规则 |
| 大盘带崩 | 同板块/同概念多只均下跌，跌幅相近 | 观察板块修复 |
| 板块错判 | 该板块不在主线，系统性回调 | 减少非主线选股 |

### 三、落选信号复盘

检查最新 `entry_signal.json`：

- 覆盖候选数、信号数
- 0 信号：直接写"无落选信号可对比"
- 有信号但未买入：对比信号股次日表现，分析落选决策质量

### 四、体系运行评估

**胜率统计表：**

| 指标 | 数值 |
|------|------|
| 总交易笔数 | N笔买入 + N笔卖出 |
| 盈利笔数 | N笔 |
| 亏损笔数 | N笔 |
| 胜率 | X% |
| 已实现盈亏 | ±N |
| 未实现盈亏 | ±N |
| 净盈亏 | ±N |

**暴露问题**：（按条列出，每条一行）

**已卖出股票验证：**

检查已平仓股票卖出后的走势，验证止损决策正确性：

```
| 股票 | 卖出价 | 最新价 | 卖出后涨跌 | 评价 |
|------|--------|--------|-----------|------|
| 示例 | X.XX | Y.YY | ↓ 持续跌/-5% | ✅ 止损正确 |
```

如全部持续下跌，止损决策质量好。如有卖后大涨，需分析原因。

**单票依赖度检查：**

```
总 P&L = +N
最大盈利持仓贡献 = +N_max
剔除后 P&L = 总P&L - N_max
→ 如果显著为负，说明体系严重依赖单票
```

**改进建议**：（按条列出，注明"仅记录，不直接修改规则"）

## 特殊场景

### 无交易时

跳过"一、执行复盘"中的计划对比表和已闭合盈亏表，改为"本日无交易计划/无成交"。
其他4段照常输出（资产表现、落选信号、体系评估、预判）。

### 信号空窗期（系统已平仓 + 连续 N 日零信号）

当所有持仓已了结（系统空仓），且 entry_signal.json 连续 N≥2 个交易日输出 0 信号时：

1. **执行复盘** → 改为"空仓，无计划生成"。由 19:00 replay-execute cron 输出的执行摘要
2. **资产表现复盘** → 汇总已完结批次的完整盈亏表（全部已实现盈亏，无持仓无未实现）。做卖出后验证（post-sell check），确认止损决策质量。加单票依赖度分析。
3. **落选信号复盘** → 直接写"entry_signal.json 输出 0 个信号（共 N 只候选均未触发条件），无落选信号可对比"。不需要尝试分析信号表现或推测原因。
4. **组合复盘** → 强调空仓状态、现金余额、买入能力。标注"等待信号"。
5. **体系复盘 → 改进建议** 中增加：

   ```text
   - 空窗期评估：连续{N}日零信号。应持续观察，满5~10个交易日仍无信号时
     考虑放宽筛选参数（如成交量倍数从1.2降至1.1、回调幅度扩大）。
   - 当前操作策略：空仓等待是体系正常行为，信号空窗期不代表体系失效。
     耐心等待市场结构恢复。
   ```

**关键**：即使空仓+零信号，复盘结论也要通过最终消息输出，供 下一阶段 generate-plan 任务 读取。
18:35 无复盘结论会跳过整个体系的计划生成——所以复盘必须明确说"信号空窗期，空仓等待"。

### 执行输出为 [SILENT] 时的处理

当 19:00 replay-execute 任务 输出 [SILENT]（无计划、无交易）时：

1. **不要依赖 context_from 的执行摘要** — [SILENT] 意味着 0 信息
2. **直接从以下来源获取状态**：
   - `交易管理 MCP` 返回的当前持仓和历史交易
   - 交易管理 MCP 返回现金余额
   - `交易/过程资料/{今天日期}/热门板块回调低吸体系/entry_signal.json` → 建仓信号
   - `交易/过程资料/{今天日期}/热门板块回调低吸体系/risk_signal.json` → 风险信号
3. **执行摘要写"无计划生成，空仓/持仓不动"**
4. **继续正常输出完整复盘**（按空仓或持有状态选择对应段落）

### 无持仓时（冷启动）

跳过"二、资产表现复盘"，重点放在"三、落选信号复盘"（buy_signal 信号质量分析）。
体系评估聚焦改进建议。

### 有计划文件不存在，但 1825 context_from 注入

当 19:00 replay-execute 任务 通过 context_from 将执行结果注入为上下文时（即使计划文件不存在），复盘仍可正常进行：

1. **frontmatter 中跳过 `derived_from` 链接**（计划文件不存在）
2. **执行摘要从 1825 输出中提取**（持有不动/买入/卖出等信息）
3. **信号数据从 `交易/过程资料/{今天日期}/热门板块回调低吸体系/entry_signal.json` 直接读取**
4. **资产数据从 ``trade-management` 技能和交易管理 MCP` + tushare 真实行情获取**
5. **精简版照常输出**，确保 下一阶段 generate-plan 任务 有数据可读

关键差异：复盘不依赖"有计划文件才运行"，而是依赖"有 context_from 输入或体系有持仓/信号"。

### 主要指数表现（复盘用）

复盘时同时拉取大盘指数环境，判断系统性风险 vs 个股风险：

```python
indices = {'000001.SH':'上证指数','399001.SZ':'深证成指','399006.SZ':'创业板指','000688.SH':'科创50'}
for code, name in indices.items():
    df = pro.index_daily(ts_code=code, start_date='YYYYMMDD', end_date='YYYYMMDD')
    if len(df) > 0:
        r = df.iloc[0]
        print(f'{name}: close={r.close:.2f} chg={r.pct_chg:.2f}%')
```

注意 `pro.index_daily()` 返回与 `pro.daily()` 相同的字段：`open, high, low, close, pre_close, change, pct_chg`，数据按 trade_date 降序排列。
