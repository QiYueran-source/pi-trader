# 过程资料规则

## 定位

过程资料存放按日期产生的运行事实与决策分析材料。它记录“当日计算了什么、分析了什么”，为交易计划和交易复盘提供可追溯依据，但不替代最终交易指令或复盘结论。

## 目录组织

新产生的体系过程资料按日期与体系名称组织：

```text
交易/过程资料/
└── YYYY-MM-DD/
    └── <体系名称>/
        ├── <计算结果>.json
        ├── <状态产物>.json
        ├── <渲染结果>.md
        └── <分析材料>.md
```

- 日期必须使用 `YYYY-MM-DD`。
- 体系名称目录用于隔离同日不同体系的产物。
- 体系无关的资料可直接放在日期目录下，但文件名必须说明内容来源。
- 既有历史目录保持原样；本规则约束新产生的过程资料。

## 应放入的内容

| 类型 | 示例 |
|---|---|
| 机械计算结果 | 候选池、板块热度、建仓信号、风险结论 JSON |
| 分析材料 | 板块研判、多标的比较、综合决策依据 Markdown |
| 展示产物 | 从结构化结果渲染的 Markdown 报告 |
| 状态产物 | 标签、观察期、状态机位置等 JSON |

状态产物与普通过程资料一样按日期写入。它的特点是可能被下一次同体系运行读取，因此需要保留日期、避免覆盖历史文件，并且只能向前查找最近有效状态，不能读取未来日期。

## 不应放入的内容

| 内容 | 应放位置 |
|---|---|
| 静态规则、参数、脚本、模板、更新日志 | `交易/交易体系/<体系名称>/` |
| 面向下一交易日的最终买卖指令 | `交易/交易计划/<日期>/` |
| 对计划与执行的复核、归因和改进结论 | `交易/交易复盘/<日期>/` |
| 无日期、无来源、无复用价值的临时文件 | 不持久化 |

## 产物要求

- 结构化过程结果应包含运行日期；重要结果应能定位到所属体系和参数版本或参数快照。
- AI 分析 Markdown 应说明其引用的关键 JSON、事实或数据来源。
- 缺失当日分析结果时，不得将其他日期的分析结果伪装为当日结果。
- 过程资料默认保留历史；修正或重跑应产生新的日期产物或明确的补充说明，不覆盖历史事实。

## 写作规则

Markdown 过程资料遵循顶层 [[RULES.md\|知识库规则]]。有体系归属的 Markdown 应在 frontmatter 标记对应 `system-id`，便于计划、复盘和知识图谱引用。
