# 22:30 复盘清单推送（交互式复盘的发问端）

到点给用户发一条**复盘清单**：告诉他今晚复盘哪三块、每块要回答什么，并把当日客观事实自动填好。用户回三句即完成输入。

- 本任务**只发清单 + 摆事实**：不写复盘文档、不评价操作好坏、不给买卖建议
- 归档（落盘复盘 + 生成次日行动计划）由用户在对话里回答之后的会话完成，**不在本任务内**

## 执行步骤

### 1. 判断交易日

```bash
/opt/hermes/.venv/bin/python3 /hermes-trader/cronjob/utils/is_trading_day.py
```

输出：`<TRADING_DAY|NON_TRADING_DAY>|<今天日期>|<下一个交易日>`

- **NON_TRADING_DAY** → 落简报后回复 `[SILENT]`，不打扰
- **TRADING_DAY** → 继续

### 2. 拉当日交易事实（不写死账户，由当日成交决定）

```bash
cd /opt/data/skills/knowledge/hermes-trade/scripts && /opt/hermes/.venv/bin/python3 trade_cli.py list | grep "{今天日期}"
```

- `list` 不带 `--account-id` 会列出**全部账户**，按 `occurred_at` **升序**（今天的记录在末尾）→ 用 `grep {今天日期}` 过滤，**不要用 `head` 截断**（会把最新的当天成交截掉）
- 出现的账户即「当日有成交的账户」；封存体系（如 `div_etf_grid_trade_old`）的历史记录由日期自动过滤掉
- 对照当日计划目录 `knowledge/交易/交易计划/{今天日期}/`，逐笔初判 **计划内 / 计划外**
- 当日无成交就写「今日无成交」，不要省略这一段

### 3. 摘录当日盘面事实（只摘录，不重算、不复述全文）

- 市场概况：`knowledge/事实/{今天日期}/市场收评.md`（无则用 `市场午评.md`）
- 板块与涨停：`knowledge/交易/过程资料/{今天日期}/` 下已有的脚本产物（如 `sector_heat.md` / `sector_heat.json`）
- 持仓数量与成本：对当日成交涉及的标的执行
  `trade_cli.py pnl --account-id {账户} --code {代码} --system-id {体系}`（不传 `--price` 即可，输出剩余数量与成本）

### 4. 推送复盘清单（最终回复即推送内容）

按下面结构发，**保持简短，三块固定，不要自行增删小节**：

```text
【今日复盘清单 · {今天日期}（周X）】

一、看市场（水温）
   指数：{上证/深成指/创业板指 涨跌幅}
   量能：{全天成交额、较上一交易日增减；涨跌家数}
   板块：{涨停最集中方向} ｜ 领跌：{方向}
   
二、看自己（交割单）
   今日成交：
   - {逐笔：方向 标的 数量 @价格（时间） 计划内/计划外}
   持仓：{当日成交涉及标的的剩余数量与成本}
   → 请回两句：
     ① 这些操作是「模式内试错」，还是「偏离规则」？
     ② 当时是因为看到信号下单，还是不甘心 / 怕踏空？

三、写计划（定明天）
   → 请回一句：如果明天继续跌，你的防守底线（止损位）在哪？

（回这三段就行。我会：① 落盘《整体复盘》 ② 生成次日《行动计划》）
```

### 5. 落简报

写入 `knowledge/摘要/.abstract/{今天日期}_global-2230-manual-review.txt`，内容：交易日判断、当日成交事实、是否已推送清单。

## 重要规则

1. **只发清单不写结论**：不评价操作好坏、不给操作建议、不生成任何复盘或计划文档。
2. **事实必须来自脚本或已落盘文档**：不凭记忆、不推断、不编造数字。
3. **三块结构固定**：看市场 / 看自己 / 写计划，顺序与提问措辞不要改（这是与用户约定的固定清单）。
4. **非交易日静默**：回复 `[SILENT]`，只落简报。
5. 本任务不产生 `.md` 落盘，因此无需 KG/Git 操作；若后续扩展出落盘动作，必须遵守 `PROGRAM.md` 的 Git 边界（只 `git add knowledge cronjob`、只推私有远程 `personal`、禁止任何 origin 操作）。
