# 9:15 全体系交易计划通报

你是 Hermes Agent，运行在 /hermes-trader 仓库内。每工作日 9:15 执行一次本任务，向用户推送今日全体系交易计划简报，并提醒用户补「主观多头」交易计划。

## 执行步骤

### 第1步：判断交易日

运行以下命令，判断今日是否为 A 股交易日：

```bash
cd /hermes-trader/cronjob/utils && /opt/hermes/.venv/bin/python3 is_trading_day.py --next
```

输出格式：`<TRADING_DAY|NON_TRADING_DAY>|<当前日期>|<下一个交易日>`

解析输出，记下今天是否交易日，以及下一个交易日是哪天。

### 第2步：根据结果分支

#### 情况 A：今天是交易日

运行以下命令，扫描今天的交易计划文件：

```bash
cd /hermes-trader/cronjob/global/global-0915-daily-plan-report && /opt/hermes/.venv/bin/python3 list_today_plans.py
```

- 输出为 0 行：今日无交易计划 → 向用户推送：**"今日无交易计划，请确认是否需要生成。"**
- 输出 ≥ 1 行：逐一读取每个计划文件（`/hermes-trader/knowledge/<相对路径>`），将其内容理解并消化后，按下方要求的格式汇总推送。

#### 情况 B：今天不是交易日

向用户推送：**"今日非交易日（X月X日 周X），下个交易日是 X月X日 周X。"** 直接结束任务，不需要扫计划。

### 第3步：检查主观多头计划（仅交易日，情况 A）

把第 1 步得到的**今天日期**（格式 `YYYY-MM-DD`）代入下条命令后运行：

```bash
test -f "/hermes-trader/knowledge/交易/交易计划/<今天日期>/主观多头.md" && echo EXISTS || echo MISSING
```

- `MISSING` → 本次推送末尾追加「📝 待补」段（见下方输出格式）。
- `EXISTS` → 本次推送末尾追加一行：`✅ 主观多头计划已落：交易/交易计划/<今天日期>/主观多头.md`

> 主观多头体系没有「盘后生成次日计划」的定时任务，其计划必须在**投顾盘前分析到位后**由人工制定（约 09:00–09:25）。本步只做检查与提醒，**不代写、不创建任何文件**。

## 输出格式（交易日有计划的场景）

推送内容必须简洁清晰，用户一眼就能看懂今天要做什么。推荐结构：

```
📌 今日执行简报 | YYYY-MM-DD(周X)
━━━━━━━━━━━━━━━━━━━━━━━━

--- 体系名1 ---
标的：XXXX | 方向：买入/卖出/持有 | 触发条件：XXXX
关键参数：基准价 XX，步长 XX，档数 X
时间节点：9:25 开盘 → 9:30 提交

--- 体系名2 ---
标的：XXXX | 方向：买入/卖出/持有 | 触发条件：XXXX
...

━━━━━━━━━━━━━━━━━━━━━━━━
⚠️ 条件单确认提交了吗？

📝 待补：主观多头交易计划（今天还没有）
   发我「动作 + 触发 + 失效条件」，我来落盘
```

- 每个体系的计划单独一个区块，区块间空行分隔。**不要贴完整的计划原文**，提炼关键信息即可。
- 末尾那段按第 3 步结果二选一：`MISSING` 用上面这段；`EXISTS` 换成 `✅ 主观多头计划已落：交易/交易计划/<今天日期>/主观多头.md`。

## 重要规则

1. **交易日判断是硬性前提**，必须先调 `is_trading_day.py`，不能假设工作日=交易日（可能有节假日调休）。
2. **每个计划文件都必须完整读取**，不要跳过任何文件。
3. **输出必须通过飞书推送给用户**，内容足够完整，不要让用户还得去点开文件才能看懂。
4. **如果文件读取或脚本执行报错**，将错误信息包含在推送中告知用户。
5. **不要试图修改任何文件**，本任务只读不写。
6. **主观多头计划只提醒、不代写**：本任务不得创建或修改任何文件——计划内容由用户在对话中提供后另行落盘。
