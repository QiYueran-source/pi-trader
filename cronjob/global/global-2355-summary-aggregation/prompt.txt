# 23:55 每日摘要聚合

每天 23:55 聚合当天工作简报，生成正式摘要并汇报结果。

1. 读取 `摘要/.abstract/`（读 `knowledge/`）下的当天简报：文件名以 `{运行日}_` 开头（兼容历史命名 `{运行日去连字符}_`，如 `20261008_…`）。运行日取 **Asia/Shanghai 时区**的当天；任务跨零点完成时仍按触发日处理。没有简报则发送一行状态（`【2355 摘要聚合】无当日简报 ｜ 跳过`）后结束。
2. 按 `summary` 与 `knowledge-management` 技能规范整理，生成 `摘要/摘要_{运行日}.md`（落 `knowledge/`）。Frontmatter 必须为 `title`、`summary`、`date`、`tags`（至少含 `摘要`、`日报`，可按当天主题追加），**不写** `uuid`、`updated`、`links`；`summary` 用 1–2 句概括当天，不得留空。正文按主题归并（当天工作项、关键结论、产生或修改的文件、失败与待办），不简单拼接原文；历史文档里的规则引用保持原样，不得引用已移除的 `RULES.md`。
3. 摘要写入并复核可读后，删除本次已处理的简报文件；摘要即当天唯一留存记录，简报不留档（`.abstract/` 被 gitignore、不参与归档）。若摘要写入失败，保留简报并说明；若删除失败，说明剩余文件。
4. 不调用知识图谱 CLI 或任何旧同步工具；不执行 Git 分支切换、提交或推送命令。
5. 向用户报告摘要生成状态、文件路径及 1–5 条摘要要点。

不得使用旧 Hermes 路径、旧 Python 环境、旧辅助脚本或旧远程仓库配置。任何步骤失败时，说明阶段和原因，不清理未成功处理的简报。

## 投递与输出

- **投递**：读 `cronjob/delivery.json` 的 `feishuChatId`，用 `send_to_feishu` **显式传该 chat_id** 发送结果（运行时会话空闲时没有活跃聊天状态，不显式传会失败）。文件缺失或发送失败时，把内容留在回复中并说明原因。
- **输出格式**：首行一行式状态，格式 `【任务简称】结论/动作 ｜ 关键数字`；正文只列必要要点（不超过 5 行），异常与待办各占一行。
- **无动作也回执**：非交易日、无候选、无过期文件等情形同样发送一行状态，便于确认任务确实执行。
