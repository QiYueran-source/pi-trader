# 红利科创ETF双网格 · 盘后风控检查与次日参数计划

交易日 18:00 生成当日风险事实与参数事实，并形成下一交易日的参数版计划；需要防守动作时只出建议与待决策项，不切换。

## 权威来源
- `system.yml`、`体系运作流程.md`、`风控.md`、`网格参数.md`、`params/regulator.json`。
- 交易日与行情仅使用 `tushare-data` MCP；YHZQ 持仓与现金仅使用 `trade-management.portfolio_snapshot`。

## 执行
1. 确认交易日；非交易日发送一行状态（`【1800 双网格】非交易日 ｜ 跳过`）后结束。
2. 生成当日过程资料 `交易/过程资料/{date}/红利科创ETF双网格体系/`：`positions.json`、`risk_facts.json`（双标的）、`sector_facts.json`、`regulator_facts.json`。其中 `regulator_facts.json` 含体系口径总资产、资金使用率、各腿权重、硬闸占用（≥50% ×1.3、≥70% ×1.6、≥85% 停买、回落 ≥80% 恢复、单腿 45% 触顶）、实际档距 = `min(常态档距 × 防守倍数 × 资金倍数, 档距上限)`（红利 6% / 双创 10%）、信号评估（一阶冲击 / 二阶确认 / 纯阴跌 / 情绪量化与文本）、建议防守档，以及审批状态（读 `human_review.json`，默认空＝不切换）。
3. 空仓（双标的合计持仓为 0）时另出 `calibration_check.json`：`is_flat`、`anchor_reset_required`、`suggested_anchor`（口径＝当日收盘价，逐腿给出）、`expected_parameters`（以 `params/regulator.json#normal_state` 为基准的应挂参数）、`defense_level`、`step_cap`；有持仓时不重设基准价。
4. 生成下一交易日参数版计划 `交易/交易计划/{下一交易日}/红利科创ETF双网格体系_交易计划.md`，固定三段：
   - **机械参数**：买入/卖出档距、买入/卖出份数、买卖开关、当前防守档、硬闸占用、档距上限；不输出逐档价格（档位价由券商软件计算）。
   - **待决策的调整部分**：仅当出现信号或建议档 ≠ 当前档时写出，每条按 `todo` 格式落盘 `- [ ] T-YYYY-MM-DD-N ｜ 用户 ｜ 触发 ｜ 来源`（owner＝用户，来源＝本计划逻辑路径）；同日未决项次日以「承接 `T-…`」引用，不重复新建。
   - **人工执行提示**：券商端需同步的动作（如空仓时重设基准价、参数核对）。
5. 飞书汇报：一行状态 + 硬闸占用 + 信号/建议防守档 + 待决策项 + 待人工核对项。

- **脚本可用**：需要确定性复算时，可调用体系脚本（`/opt/venv/bin/python knowledge/交易/交易体系/红利科创ETF双网格体系/scripts/<脚本名>.py`），命令与依赖口径见 `常用代码速查.md`；脚本输出与 MCP 复算必须同口径。

## 硬边界
- 不得切换防守档、不得修改静态规则与参数（含 `params/regulator.json`）；审批由会话在复盘时完成并写入 `human_review.json`，计划参数由会话按审批结果更新。
- 不得生成清仓、减仓、止损或反 T 限制；极端行情只停买。
- 不得产出状态迁移、状态快照或切换指令（状态机已退役）。
- 不写复盘结论；体系复盘由会话在用户审核时写入 `交易/交易复盘/{date}/红利科创ETF双网格体系_复盘.md`。
- 不得用估算仓位或旧状态替代真实持仓；输入无效时记录链路异常并停止计划生成。

写入简报 `knowledge/摘要/.abstract/{今天日期}_div-etf-grid-trade-daily-check.txt`，最终仅报告参数、硬闸占用、信号与建议档、计划路径和人工待办。

## 投递与输出

- **投递**：读 `cronjob/delivery.json` 的 `feishuChatId`，用 `send_to_feishu` **显式传该 chat_id** 发送结果（运行时会话空闲时没有活跃聊天状态，不显式传会失败）。文件缺失或发送失败时，把内容留在回复中并说明原因。
- **输出格式**：首行一行式状态，格式 `【任务简称】结论/动作 ｜ 关键数字`；正文只列必要要点（不超过 5 行），异常与待办各占一行。
- **无动作也回执**：非交易日、无候选、无过期文件等情形同样发送一行状态，便于确认任务确实执行。
