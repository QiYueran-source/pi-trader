# 热门板块回调低吸 · 生成下一交易日计划

交易日 19:25 生成四段事实并输出下一交易日唯一模拟计划。

## 执行指引

按 `体系运作流程.md` **第 2.2.3 节「19:25 事实链与下一交易日计划」** 执行：步骤与产物、MCP 入参、异常分支均在该节；判定口径见 **第 2.3 节**，计划结构见 **第 2.4 节**，汇报要点见 **第 2.5 节**，共同输入与前置见 **第 2.1 节**。

## 运行契约

- 交易日判断用体系 MCP `hot-sector-pullback-system` 的 `is_trading_day`（本服务自带，不依赖其它 MCP）；非交易日发送一行状态（`【1925 回调低吸计划】非交易日 ｜ 跳过`）后结束。
- 四段事实与渲染只用体系 MCP `hot-sector-pullback-system`：`validate_parameters` → `calculate`（`select_candidates`／`sector_heat`／`entry_signal`／`risk_signal`）→ `render`；不执行历史脚本。
- 持仓与现金只用 `trade-management.portfolio_snapshot`（MNZH）；行情与交易日只用 `tushare-data`。
- 运行契约以体系 MCP `hot-sector-pullback-system` 的 `get_manifest` 返回与运行定义 `params/runtime.json` 为准；过程资料写入 `交易/过程资料/{今天日期}/热门板块回调低吸体系/`，计划写入 `交易/交易计划/{下一交易日}/热门板块回调低吸体系_交易计划.md`（落 `knowledge/`）。
- 简报写入 `摘要/.abstract/{今天日期}_hot-sector-pullback-generate-plan.txt`（落 `knowledge/`）。

## 边界

只生成模拟计划：不改运行定义 `params/`、不改规则文档、不登记成交、不改写上一日产物；上游缺失、日期不一致或 MCP 报错时写链路异常并停止下游步骤，不估算、不用历史产物替代。

## 投递与输出

- **投递**：读 `cronjob/delivery.json` 的 `feishuChatId`，用 `send_to_feishu` **显式传该 chat_id** 发送结果（运行时会话空闲时没有活跃聊天状态，不显式传会失败）。文件缺失或发送失败时，把内容留在回复中并说明原因。
- **输出格式**：首行一行式状态，格式 `【任务简称】结论/动作 ｜ 关键数字`；正文只列必要要点（不超过 5 行），异常与待办各占一行。
- **无动作也回执**：非交易日、无候选、无过期文件等情形同样发送一行状态，便于确认任务确实执行。
